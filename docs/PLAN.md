# 개발 일정 (14시간)

기획 상세는 [PRD](PRD.md)를 기준으로 합니다.

## 목표

시연 한 줄: 할머니가 "병원 가고 싶어"라고 말하면, 같은 이름 병원 중 가까운 곳을 확인하고, 가까우면 걸어가는 길을, 멀면 카카오 택시를 부르는 것을 가족 아바타가 도와준다. (가상 위치로 시연)

## 우선순위

| 순위 | 기능 |
| --- | --- |
| P0 | 말하는 아바타(입 움직임), 가족 목소리 파일 재생 |
| P0 | 음성 요청 인식, 선택 버튼, "응/아니/알겠어/다시/잠깐" 응답 |
| P0 | 같은 이름 장소 확인, 미리 정한 경로 길 안내 |
| P0 | 택시 부르기 (타는 곳 확인, 카카오 택시 연결, 기다리기 안내) |
| P1 | 카메라 방향 화살표, 지도 보기 목업 |
| P1 | 가족 설정 화면 (녹음, 자주 가는 곳, 사진 → 아바타 변환) |
| P1 | AI 말뜻 이해 |
| P2 이하 | 실제 GPS·지도 API, 자유 대화 AI, 실시간 목소리 복제, 아바타 꾸미기 |

P1이 안 되면 미리 만든 아바타와 미리 설정한 값으로 시연합니다.

## 시간표

| 시간 | 목표 |
| --- | --- |
| 0-1h | 역할 분담, AI 서비스 결정, 시연 목적지 2~3곳과 안내 문장 확정 |
| 1-2h | 안내 문장 음성 파일 제작 (일레븐랩스, 동의받은 팀원 목소리), 샘플 아바타 준비 |
| 2-7h | **P0 구현**: 아바타 화면·입 움직임 / 음성 인식·응답 / 장소 확인·길 안내 / 택시 연결 |
| 7-9h | P0 통합, 처음부터 끝까지 시연 흐름 한 번 완성 |
| 9-11h | P1 구현 (카메라 화살표, 가족 설정, 아바타 변환) |
| 11-13h | 버그 수정, 음성 인식 실패 시 버튼 대체안 점검, 폰 실기 테스트 |
| 13-14h | 발표 자료, 최종 `develop` → `main` 병합, 시연 리허설 |

## 시작 전에 정해야 할 것

- [ ] 앱 이름 (곁에 / 콕콕 / 든든)
- [ ] AI 서비스 (Gemini 또는 OpenAI)
- [ ] 시연 목적지 2~3곳 (같은 이름 2곳인 장소 포함)과 경로 문장 담당
- [ ] 카카오 택시 앱 링크 준비, 폰에서 열리는지 확인
- [ ] 안내 문장 목록 확정, 목소리 복제할 팀원 동의
- [ ] 카메라 방향 보기 시연 장면 준비

## 발표에서 꼭 밝힐 것

- 시연의 가족 목소리는 **미리 만든 문장 파일**이고, 실제 서비스는 목소리를 학습해 실시간 생성하는 구조로 만든다는 점
- 위치는 **가상 위치**이고, 이후 실제 GPS와 지도 API로 확장한다는 점
- 화면에 "AI 도우미" 표시를 두고, 첫 인사에서 가족 모습으로 만든 AI임을 알린다는 점
