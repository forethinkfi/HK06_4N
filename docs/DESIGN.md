## 1. 디자인 원칙

페르소나는 79세 김정성 씨다. 길은 잘 알지만 앱 조작이 어렵다. "노인 전용" 느낌이 나지 않으면서 취약한 부분을 일부 고려한다.

1. **한 화면에 한 가지**: 위쪽 카드에 질문 하나, 아래쪽에 답 하나를 둔다. (One thing per page)
2. **말과 버튼을 함께**: 음성 대화가 기본 입력이지만, 답 버튼(⭕/❌, 선택지)은 처음부터 화면에 보인다. 다시 듣기·글자 입력은 "다시 듣기 · 글자로 답하기"를 누르면 열린다. **[피그마]**
3. **영상통화 같은 화면**: 가족 아바타를 화면 가운데 가장 크게 보여 주고, 지도 화면에서는 오른쪽 위에 작게 띄운다. **[피그마]**
4. **색에 기대지 않기**: 의미는 모양과 글자로 전한다. ⭕/❌는 색보다 모양으로 구분된다.
5. **어린아이 대하듯 하지 않기**: 과한 칭찬, 지나치게 귀여운 표현은 피한다.

- 일반 글자는 배경과의 대비가 **4.5:1 이상**, 큰 글자는 **3:1 이상**이어야 한다.
- 현재 조합의 대비(WCAG 계산값)

| 조합 | 대비 | 판정 |
|---|---|---|
| 흰 글자 / `color-listening`(흰 바탕 위 실제 색 `#626471`) | 5.9:1 | 통과 |
| 흰 글자 / `color-heard` | 5.9:1 | 통과 |
| `#111` / `color-taxi-status` | 14.7:1 | 통과 |
| `#222` / 흰 바탕 | 15.9:1 | 통과 |
| `#444` / 흰 바탕 | 9.7:1 | 통과 |
| ⭕ `#3C21A8` / 흰 바탕 | 10.6:1 | 통과 |
| ❌ `#E24048` / 흰 바탕 | 4.1:1 | 통과 (아이콘 기준 3:1) |
| `color-accent` 테두리 / 흰 바탕 | 2.8:1 | 장식용. 카드는 그림자로도 구분되므로 이 테두리에 정보를 담지 않는다 |

- 이미지·지도 위에 글자를 겹칠 때는 불투명한 배경(흰색 또는 `#222` 알약)을 깐다.
- 화면을 그레이스케일로 바꿔도 모든 정보가 읽히는지 확인한다.
- ⭕ 아이콘은 남보라색이다. 시니어 UX Tips의 "중요 아이콘에 파란 계열 피하기"와 다르지만, 모양으로 의미가 전달되고 대비가 10.6:1이라 피그마 결정을 따른다.

## 4. 버튼과 터치 영역

### 4-1. 카카오 로그인 버튼 **[카카오 규정]**

- 구성: 말풍선 모양 **심볼** + 안내 **레이블** + 이를 감싸는 **컨테이너**
- 색: 컨테이너 `#FEE500`, 심볼 `#000000`, 레이블 `rgba(0,0,0,0.85)`
- 컨테이너 radius: **12px**
- 레이블: 완성형 "카카오 로그인", 축약형 "로그인"
- 심볼의 형태·비율·색을 바꾸지 않고, 심볼 없이 버튼을 만들지 않는다.
- 곁에 앱에 로그인 화면이 생기면 위 규정을 그대로 따른다. (현재 로그인 화면 없음) 아래 곁에 버튼 규칙은 로그인 버튼에 적용하지 않는다.

### 4-2. 곁에 버튼 **[피그마]**

| 종류 | 크기 | 모양 | 용도 |
|---|---|---|---|
| 답변 버튼 ⭕/❌ | 171×112 (지도 위 175×112), 아이콘 72×72 | radius 32, 흰 배경, 테두리 2px `color-border-button`, 그림자 | 예/아니요 |
| 큰 선택 버튼 | 가로 꽉 참, 높이 76 (두 줄이면 104) | radius 32, 흰 배경, 28px Bold | 병원 고르기, 눌러서 말하기, 택시 취소 |
| 작은 선택 버튼 | 가로 꽉 참, 높이 52 | radius 32, 22px Bold | 지도 위 버튼, ⭕/❌ 아래 보조 버튼 |
| 지도 도구 버튼 | 높이 40 | radius 32, 16px Bold | 실제 경로 보기, 주소로 찾기 |

- 모든 버튼은 흰 배경 + 테두리 + 그림자로 통일한다. 노란색 주요 버튼은 쓰지 않는다.
- 버튼 사이 간격: 세로 **9px**, ⭕/❌ 사이 **12px**. (이전 가이드의 16px보다 좁지만 버튼 자체가 52~112px로 커서 잘못 누를 위험이 적다)
- 터치 영역은 최소 **44×44px**, 곁에 버튼은 **52px 이상**이다.
- 위쪽 메뉴의 뒤로(‹)·메뉴(☰) 아이콘 버튼은 44×44px이고, 화면 낭독기를 위해 "이전"/"설정" 이름을 붙인다.
- 같은 화면에 ⭕/❌가 있으면 다른 버튼은 작은 선택 버튼으로 둔다.

## 5. 레이아웃 **[피그마]**

- 기준 화면: **390 × 844**, 좌우 여백 **18px** (지도 화면 14px)
- 배경은 `color-surface-sub`, 화면 모서리 radius 30

### 5-1. 화면 구조

```
┌ 위쪽 메뉴 ─ ‹ 뒤로 ············ ☰ 메뉴 ┐   44×44 아이콘
│ ───────── 구분선 352×2 ─────────── │   color-accent-soft
│        질문 (28px Bold, 가운데)      │   높이 109 이상
│      [ AI 도우미가 듣고 있어요 ]      │   color-listening 알약
└──────── radius 30 · glow 그림자 ────────┘
   가운데: 가족 아바타 / 차량 팝업 / 지도(전체 배경)
   아래: 상태 카드 · 확인 표 · 차량 카드
   맨 아래: 답변 버튼 (⭕/❌ 또는 선택 버튼)
```

- 피그마의 위쪽 여백 40px은 휴대폰 상태 표시줄 자리다. 웹에서는 브라우저가 그 자리를 차지하므로 10px로 줄인다.
- 지도 화면: 네이버 지도가 화면 전체를 채우고, 질문 카드와 버튼이 그 위에 올라간다. 아바타는 오른쪽 위 78×82로 작게 둔다.
- 선택지가 3개 이상인 화면(병원 고르기, 고치기)은 아바타 없이 버튼을 아래쪽에 모은다.

## 6. 인터랙션과 피드백 **[팀 제안]**

- 사용자가 한 행동에는 즉시 반응한다. (듣는 중 표시, 말하는 아바타)
- 단계가 끝날 때마다 분명하게 알린다. (예: "택시를 불렀어요", "잘 오셨어요!")
- 대기 시간은 넉넉히 준다. 응답이 없으면 재촉하지 말고 "천천히 하세요"로 기다린다.
- 못 알아들었을 때는 다시 듣기와 큰 선택 버튼을 함께 제시한다.
- 택시를 부르는 중인 화면에서 뒤로(‹)를 누르면 바로 나가지 않고 "택시를 취소할까요?"를 먼저 묻는다.
- 시연 화면에는 "시연 화면이에요. 실제 택시는 호출되지 않아요."를 표시한다.

## 7. 문구 톤 **[팀 제안]**

- 손주가 실제로 할 법한 말투. 기계적인 표현을 쓰지 않는다. (자세한 대본은 [VOICE_SCRIPT.md](./VOICE_SCRIPT.md))
- 한 문장에 하나의 행동만 안내한다.
- 노인 전용이라는 느낌이 나는 표현("어르신용" 등)을 화면에 쓰지 않는다.
- 화면 제목은 짧게 쓸 수 있지만, 음성 안내 문장은 바꾸지 않는다. (예: 최종 확인 화면 제목 "이대로 부를까요?", 음성은 출발·도착·요금을 모두 읽음)

## 8. 체크리스트

- [ ] 색·글자 크기·radius를 토큰(`--color-*`, `--shadow-*`)으로 썼는가 (직접 쓴 색 값이 없는가)
- [ ] 16px 미만 글자가 없는가 (그림 속 글자 제외)
- [ ] 글자 대비가 4.5:1(큰 글자 3:1) 이상인가
- [ ] 그레이스케일로 봐도 읽히는가
- [ ] 한 화면에 질문과 행동이 하나인가
- [ ] 버튼 높이 52px 이상, radius 32, 흰 배경·테두리·그림자 규칙을 지켰는가
- [ ] 지도·이미지 위 글자에 불투명한 배경이 있는가
- [ ] "AI 도우미" 표시가 보이는가
- [ ] 아이콘만 있는 버튼에 화면 낭독기 이름이 있는가
- [ ] 카카오 로그인 버튼을 쓴다면 색(`#FEE500` / `#000000` / 검정 85%)과 radius 12px, 심볼 규칙을 지켰는가
