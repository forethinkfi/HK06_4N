## 2. 페르소나 — 김정성

> "가는 길은 잘 아는데, 요즘은 택시 한 번 부르는 것도 어렵더라고."

79세 남성 · 서울 은평구 · 승용차 및 승합차 운전원 · 배우자와 거주 · 핵심 성향: 성실함, 독립적인 생활, 규칙적인 일상, 가족에 대한 애정

| 구분 | 특징 |
|---|---|
| 디지털 활용 능력 | 익숙한 스마트폰 퍼즐 게임은 이용 가능 |
| 이동 능력 | 오랜 운전 경력으로 서울 지리에 익숙 |
| 잠재적 어려움 | 낯선 택시 앱의 메뉴, 위치 설정, 호출 방법 |
| 친숙한 도움 방식 | 손주에게 스마트폰 사용법을 배우는 방식 |
| 심리적 욕구 | 타인의 도움 없이 스스로 일상을 유지하고 싶음 |
| 서비스 이용 동기 | 복잡한 앱 조작 없이 말로 이동 도움을 받고 싶음 |

김정성 씨는 길을 모르는 사람이 아니다. **이동 경험은 풍부하지만, 이동 서비스를 이용하기 위한 디지털 조작에 어려움을 겪는 사람**으로 설정한다.

> 디지털 조작의 어려움과 심리적 욕구는 실제 인터뷰 결과가 아닌 페르소나 기반 가설이다.

## 3. 사용자 시나리오

| 항목 | 내용 |
|---|---|
| 시간 | 평일 오전 10시 |
| 장소 | 은평구 불광동 자택 (○○아파트 101동, 가상 예시) |
| 상황 | 정기 검진을 위해 병원에 방문해야 함 |
| 배경 | 오늘은 직접 운전하지 않고 택시로 대학병원에 가기로 함. 집 안에서 택시를 부른 뒤 나감 |
| 문제 | 택시 앱 이용이 복잡하고 길에서 택시를 잡기 어려움 |
| 서비스 인지 | 손주가 이전에 곁에 앱을 설치해 줌 |
| 사용자 목표 | 손주에게 전화하지 않고 택시로 병원에 도착하기 |
| 기대 결과 | 혼자서도 원하는 곳으로 이동할 수 있다는 자신감 |

**사전 상황:** 며칠 전 손주가 할아버지 스마트폰에 곁에를 설치하고, 가족 화면에서 아래 설정과 동의를 마쳤다. 아래 TO-BE 유저저니는 **이 등록이 끝났다는 가정**에서 시작한다.

### 가족 화면: 사전 등록과 동의

| 순서 | 항목 | 동의하는 사람 |
|---|---|---|
| 1 | 아바타에 쓸 사진·목소리 사용 | 사진·목소리의 주인(손주) |
| 2 | 위치 정보 사용 | 어르신 본인 |
| 3 | 결제 카드 등록 (선택) | 어르신과 카드 명의자 |
| 4 | 우리 집 주소 등록 (아파트 동까지) | 어르신 본인 |
| 5 | 병원 등록: 대학병원, 동네 내과 (이름·종류·주소) | — |

- 어르신의 동의는 가족이 대신 누르지 않고, 설명을 들은 어르신이 직접 확인한다.
- 동의하지 않은 기능은 켜지 않는다. 카드를 등록하지 않으면 내릴 때 직접 결제로 안내한다.

> 병원 방문, 방문 시간, 가족의 사전 설정은 유저저니를 구체화하기 위해 추가한 가상 상황이다.

## 4. AS-IS 유저저니 (곁에가 없을 때)

| 단계 | 사용자 행동 | 사용자 생각 | 감정 | 페인포인트 |
|---|---|---|---|---|
| ① 외출 준비 | 병원 갈 준비를 함 | 오늘은 택시를 타고 가야겠다. | 기대 | - |
| ② 택시 탐색 | 집 앞에서 택시를 잡으려 함 | 빈 택시가 왜 이렇게 없지? | 답답함 | 길거리 택시 이용 어려움 |
| ③ 앱 실행 | 기존 택시 앱을 실행함 | 어디를 눌러야 하지? | 혼란 | 낯선 인터페이스 |
| ④ 장소 설정 | 출발지와 병원을 검색함 | 이 병원이 내가 가려는 곳인가? | 불안 | 위치 설정, 동명 장소 |
| ⑤ 호출 실패 | 호출 과정에서 막혀 포기함 | 잘못 누르면 어떡하지? | 좌절 | 복잡한 호출 과정 |
| ⑥ 도움 요청 | 손주에게 전화함 | 바쁠 텐데 또 전화해야겠네. | 미안함 | 가족에게 의존 |
| ⑦ 이동 | 가족의 도움으로 택시 이용 | 다음에도 부탁해야겠군. | 안도 | 독립 이용 자신감 부족 |

감정 곡선: 기대 → 답답 → 혼란 → 불안 → **좌절(최저)** → 미안함 → 안도 (사용자 인터뷰 이전의 가설 기반)

## 5. TO-BE 유저저니 (곁에 사용 시)

**이번 상황:** 집 안에서 대학병원으로 가는 택시를 부른다. 타는 곳은 **○○아파트 101동 앞**이다. (시나리오용 가상 설정)

| 단계 | 사용자 행동 | 터치포인트 | 사용자 생각 | 감정 | 개선 기회 |
|---|---|---|---|---|---|
| ① 외출 준비 | 집 안에서 병원 갈 준비를 함 | 집 안 | 택시를 어떻게 부르지? | 약간의 걱정 | 나가기 전에 부를 수 있게 하기 |
| ② 곁에 떠올리기 | 손주가 설치해 준 곁에를 떠올림 | 스마트폰 홈 | 손주처럼 알려준다고 했지. | 기대 | 쉬운 앱 진입 |
| ③ 앱 실행 | 곁에를 실행함 | 영상통화형 화면 | 손주가 알려주는 것 같네. | 친숙함 | 가족 기반 인터페이스 |
| ④ 목적지 선택 | 등록된 대학병원·동네 내과 중 고르고 확인함. 다른 병원이면 이름을 말해 확인함 | 음성, 병원 버튼, [다른 병원] | 오늘 갈 병원이 맞아. | 안정감 | 등록하지 않은 병원도 갈 수 있게 하기 |
| ⑤ 타는 곳 확인 | 집 안에서 지도와 사진을 보고 101동 앞이 맞는지 확인함. 원하면 바꿈 | 지도, 타는 곳 사진 | 우리 동 앞이면 되겠네. | 안심 | 동 이름과 사진을 함께 보여주기 |
| ⑥ 결제·준비·요금 확인 | 결제 방법을 고르고 나갈 준비를 확인한 뒤, 요금을 듣고 보며 ⭕ 네 / ❌ 아니요로 답함 | 확인 화면, 음성 | 준비하고 요금도 확인한 뒤 부르면 되겠네. | **긴장 → 안심** | 서두르지 않게 하고, 부르기 전에 거절 가능 |
| ⑦ 배차 확인 | 차 사진·차종·차 번호를 확인함 | 차량 팝업 | 이 차가 오는구나. | 신뢰감 | 아래에 두고 언제든 다시 크게 보기 |
| ⑧ 나가기·대기 | 택시 위치를 확인하고 챙겨서 101동 앞으로 나가 기다림 | 지도, 말풍선, 도착 예정 시간 | 어디쯤 왔는지 보고 나가면 되겠네. | 안심 | 서두르지 않게 안내 |
| ⑨ 택시 탑승 | 택시가 보이는지, 차 번호가 맞는지 차례로 확인하고 탑승 | 큰 차 번호 | 내가 부른 차가 맞아. | 확신 | 잘못 타는 것 방지 |
| ⑩ 내릴 준비 | 도착 전 안내를 듣고 소지품을 챙김 | 음성, 말풍선 | 이제 내릴 준비를 해야지. | 안정감 | 미리 알려주기 |
| ⑪ 목적지 도착 | 병원에 도착해 칭찬과 격려를 들음 | 도착 화면 | 나도 혼자서 할 수 있구나. | **성취감** | 다음 이용 자신감 |

**TO-BE 감정 곡선:** 걱정 → 기대 → 친숙 → 안정 → 안심 → **긴장(요금 확인)** → 신뢰 → 안심 → 확신 → 안정 → **성취(최고)** (사용자 인터뷰 이전의 가설)

### 전후 비교

| 상황 | AS-IS (곁에가 없을 때) | TO-BE (곁에 사용 시) | 감정 변화 (가설) |
|---|---|---|---|
| 택시 이용 시작 | 밖에 나가 택시를 기다리지만 안 잡힘 | 집 안에서 택시를 부른 뒤 나감 | 답답 → 안심 |
| 앱 조작 | 어디를 눌러야 할지 모름 | 말 또는 큰 버튼으로 답함 | 혼란 → 안정 |
| 목적지 | 같은 이름의 장소가 불안함 | 등록한 대학병원·동네 내과에서 선택 | 불안 → 안정 |
| 타는 곳 | 위치 설정이 어려움 | 등록한 동 앞을 지도·사진으로 확인 | 불안 → 안심 |
| 요금·호출 | 잘못 누를까 봐 포기 | 결제 방법, 나갈 준비, 요금을 확인한 뒤 호출 | 좌절 → 긴장 → 안심 |
| 가족 도움 | 손주에게 전화하며 미안해함 | 전화하지 않고 진행 | 미안함 → 신뢰 |
| 이동 후 | 다음에도 부탁해야겠다고 생각 | 내릴 준비 안내와 칭찬을 받음 | 안도 → 성취 |

## 6. 스토리보드 상세 시나리오 (12장면)

> 장소 이름, 요금, 시간, 차량 정보는 모두 시연용 예시다.

| # | 장면 | 내용 | 대사 | 감정 |
|---|---|---|---|---|
| 1 | 병원에 가는 날 | 집 안에서 외출을 준비하며 택시를 타기로 한다. | 김정성: "오늘은 택시 타고 병원에 다녀와야겠어." | 기대, 걱정 |
| 2 | 곁에 떠올리기 | 손주가 설치해 준 곁에를 연다. | 김정성: "손주가 말만 하면 된다고 했지." | 기대 |
| 3 | 손주와 영상통화하듯 | AI 손주가 나타난다. 첫 이용 때 AI임을 알린다. | AI: "저는 손주의 모습과 목소리로 만든 AI 도우미예요. 할아버지, 오늘 어디 가세요?" / 김: "병원 가게 택시 잡아줘." | 친숙함 |
| 4 | 병원 선택 | 등록한 두 병원과 [다른 병원]을 큰 버튼으로 보여준다. | AI: "대학병원과 동네 내과 중 어디로 가세요?" / 김: "대학병원." / AI: "행복대학병원 맞아요?" (⭕❌) / 김: "네." | 안정감 |
| 5 | 타는 곳 확인 | 집 안에서 지도에 타는 곳을 표시하고 사진을 보여준다. | AI: "타는 곳은 ○○아파트 101동 앞으로 하면 될까요?" (⭕❌) / 김: "네." | 안심 |
| 6 | 결제와 나갈 준비 | 등록한 카드를 쓸지 묻고, 나갈 준비를 확인한다. | AI: "등록한 카드로 결제할까요?" (⭕❌) / 김: "네." / AI: "나갈 준비 되셨어요?" (⭕❌) / 김: "네." | 신중함 |
| 7 | 요금 확인과 호출 | 출발지·도착지·요금·결제 방법을 보여주고 말로도 읽는다. | AI: "예상 요금은 약 6,000원이에요." / "이대로 부를까요?" (⭕❌) / 김: "네." | 긴장 → 안심 |
| 8 | 배차 확인 | 차 사진·차종·차 번호를 팝업으로 보여준다. | AI: "택시가 배정됐어요. 차 사진과 번호, 확인하셨어요?" (⭕❌) / 김: "네." / AI: "3분 뒤에 도착해요." | 신뢰감 |
| 9 | 챙겨서 나가기 | 팝업을 닫으면 차 사진과 번호는 아래로 내려가고 지도가 커진다. 아래 카드를 누르면 다시 크게 보인다. 챙겨서 101동 앞으로 나간다. | AI: "이제 천천히 챙겨서 나가세요." / (가까워지면) "택시가 곧 도착해요." | 안심 |
| 10 | 택시 확인과 탑승 | 택시가 보이는지 먼저, 차 번호가 맞는지 다음에 묻는다. | AI: "택시가 보이세요?" (⭕❌) / 김: "네." / AI: "차 번호가 맞나요?" (⭕❌) / 김: "네." / AI: "이제 타셔도 돼요." | 확신 |
| 11 | 내릴 준비 | 병원에 가까워지면 알려준다. | AI: "곧 병원에 도착해요. 소지품을 챙기세요." / "차가 완전히 멈추면 내리세요." | 안정감 |
| 12 | 병원 도착 | 도착을 알리고 칭찬과 격려를 한다. | AI: "병원에 도착했어요. 혼자서 잘 오셨어요!" / "다음에도 곁에서 도와드릴게요." / 김: "다음에도 혼자 갈 수 있겠어." | 성취감 |

- 6장면에서 준비가 안 됐으면 부르지 않고 "천천히 준비하세요. 준비되면 '준비됐어'라고 말씀해 주세요."라고 알리며 기다린다.
- (⭕❌)는 네·아니요로 답하는 질문이다.
- 4장면에서 "아니요"라고 하면 "혹시 다른 병원 가시는 걸까요?" (⭕❌)라고 묻고, 병원 이름과 지역을 확인한다.
- 직접 결제를 고른 경우, 11장면에서 "요금은 내리실 때 직접 결제해 주세요."를 덧붙인다.

## 7. 서비스 전체 유저 플로우

```
곁에 앱 실행 → 음성으로 목적지 요청 → 병원 선택(대학병원/동네 내과/다른 병원)·확인 → 이동 방법 확인
  ├─ [택시 부르기] (메인)
  │     타는 곳 확인(○○아파트 101동 앞, 지도+사진) ↔ 다른 곳에서 부르기
  │     → 결제 방법 선택 → 나갈 준비 확인(아니면 기다림) → 요금 포함 최종 확인
  │         ├─ ❌ 아니요 → 고칠 항목 선택 또는 부르지 않기
  │         └─ ⭕ 네 → 모의 호출
  │     → 차량 팝업(닫으면 아래 카드, 누르면 다시 크게) → 택시 위치 지도·도착 예정 시간
  │     → 챙겨서 나가기 → 101동 앞 대기 → "곧 도착해요"
  │     → 택시가 보이는지 확인 → 차 번호 확인 → 탑승
  │     → 내릴 준비 안내 → 병원 도착·칭찬
  └─ [도보 길찾기] (서브)
        단계별 음성 안내 → 필요 시 지도 → 카메라 방향 안내(선택) → 도착·칭찬
```

### 7-1. 택시 호출 상세 흐름

한 번에 하나만 묻는다. 네·아니요로 답할 수 있는 질문은 (⭕❌)로 표시하고, 화면에는 [⭕ 네] [❌ 아니요] 큰 버튼을 글자와 함께 보여준다. "응", "맞아", "그래"는 네로, "아니", "아니야"는 아니요로 알아듣는다. 병원 이름이나 장소를 묻는 질문, 여러 항목 중 고르는 질문은 그대로 둔다. 모든 질문은 말과 큰 글씨로 함께 전하고, 큰 버튼으로도 답할 수 있다.

| 단계 | 곁에(AI 손주) | 어르신 | 화면 | 다음 단계 / 다른 답 |
|---|---|---|---|---|
| 1. 병원 선택·확인 | "대학병원과 동네 내과 중 어디로 가세요?" → (⭕❌) "행복대학병원 맞아요?" | "대학병원" → ⭕ 네 / ❌ 아니요 | 종류+이름 버튼 2개, [다른 병원] | ⭕ → 2 / ❌ 또는 다른 병원 → 1-1 |
| 1-1. 다른 병원 확인 | (⭕❌) "혹시 다른 병원 가시는 걸까요?" | ⭕ 네 / ❌ 아니요 | [⭕ 네] [❌ 아니요] | ⭕ → 1-2 / ❌ → 등록 병원을 다시 보여줌 |
| 1-2. 병원 이름 | "어느 병원에 가세요?" → (⭕❌) "○○동 ○○병원 맞아요?" | 병원 이름 → ⭕ 네 / ❌ 아니요 | 병원 이름·지역 | ⭕ → 2 / ❌ → 이름을 다시 묻거나 가까운 다른 곳을 확인 |
| 1-3. 이동 방법 | "택시 잡아줘"라고 했으면 묻지 않음. "어떻게 가?"인데 멀면 (⭕❌) "걸어가기엔 조금 먼데 택시 타고 가실래요?" | ⭕ 네 / ❌ 아니요 | [⭕ 네] [❌ 아니요] | ⭕ → 2 / ❌ → (⭕❌) "걸어가는 길을 알려드릴까요?" ⭕면 도보, ❌면 종료. 가까우면 도보 안내 |
| 2. 타는 곳 안내 | (⭕❌) "타는 곳은 ○○아파트 101동 앞으로 하면 될까요?" | ⭕ 네 / ❌ 아니요 | 지도(우리 집·타는 곳), 타는 곳 사진, [⭕ 네] [❌ 아니요] | ⭕ → 3 / ❌ → 2-1 |
| 2-1. 다른 곳 | "그럼 어디에서 부를까요?" | 장소를 말함 | 등록 장소 버튼, 지도 | 새 장소를 지도·사진으로 보여주고 "여기로 부를까요?"로 다시 확인. 길 건너편이면 "길 건너" 큰 표시 |
| 3. 결제 방법 | (⭕❌) "등록한 카드로 결제할까요?" | ⭕ 네 / ❌ 아니요 | 카드 / 직접 결제 | ⭕ → 카드로 정하고 3-1 / ❌ → "내리실 때 직접 결제해 주세요." 안내 후 3-1. 등록한 카드가 없으면 직접 결제를 안내하고 3-1 |
| 3-1. 나갈 준비 | (⭕❌) "나갈 준비 되셨어요?" | ⭕ 네 / ❌ 아니요 | [⭕ 네] [❌ 아니요] | ⭕ → 4 / ❌ → 부르지 않고 "천천히 준비하세요. 준비되면 '준비됐어'라고 말씀해 주세요." 안내 후 [준비됐어요] 버튼으로 대기. "준비됐어"라고 하면 4 |
| 4. 최종 확인 | 출발지·도착지·예상 요금·결제 방법을 읽고 (⭕❌) "이대로 부를까요?" | ⭕ 네 / ❌ 아니요 | 네 가지 항목을 큰 글씨로 | ⭕ → 5 / ❌ → 4-1 |
| 4-1. 수정·중단 | "어디가 다른가요?" | "타는 곳" / "가는 곳" / "결제" / "안 부를래" | 큰 버튼 네 개 | 해당 단계로 돌아간 뒤 4를 다시 확인. 안 부를래 → 호출하지 않고 종료. 요금이 부담되면 이 버튼으로 중단 |
| 5. 호출 | "택시를 부르고 있어요." | 기다림 | 호출 중, 취소 버튼 | 배차 완료 → 6 |
| 6. 배차 확인 | (⭕❌) "차 사진과 번호, 확인하셨어요?" | ⭕ 네 / ❌ 아니요 (닫기는 ⭕와 같음) | 차 사진·차종·번호 팝업 | ⭕ → 팝업이 아래 카드로 내려가고 7 / ❌ → 팝업을 유지하고 차종·번호를 읽어준 뒤 다시 확인 |
| 7. 나가기·대기 | "3분 뒤에 도착해요. 천천히 챙겨서 나가세요." | 101동 앞으로 이동 | 큰 지도, 택시 위치, "약 3분", 아래 차량 카드(누르면 크게) | 가까워지면 "택시가 곧 도착해요." → 8 |
| 8. 택시 확인 | (⭕❌) "택시가 보이세요?" | ⭕ 네 / ❌ 아니요 | 큰 차 번호, 지도 | ⭕ → 9 / ❌ → "타는 곳에서 조금 더 기다려 주세요." 후 지도 표시, 다시 확인 |
| 9. 번호 확인 | (⭕❌) "차 번호가 맞나요?" | ⭕ 네 / ❌ 아니요 | 큰 차 번호 | ⭕ → "이제 타셔도 돼요." / ❌ → "이 차는 타지 마세요." 후 8 |
| 10. 이동 중 | 이동 화면을 유지 (예시안은 정해 둔 시간 후 탑승한 것으로 전환) | 이동 | 목적지까지 지도 | 도착 직전 → 11 |
| 11. 내릴 준비 | "곧 병원에 도착해요. 소지품을 챙기세요. 차가 멈추면 내리세요." | 준비 | 말풍선, (직접 결제면) 결제 안내 | 도착 → 12 |
| 12. 도착 | "병원에 도착했어요. 혼자서 잘 오셨어요! 다음에도 곁에서 도와드릴게요." | 하차 | 큰 아바타, [안내 마치기] | 안내를 마치면 첫 화면 |

**예외 처리**
- 집 안에서는 위치가 부정확할 수 있어, 가족이 등록한 우리 집 주소를 기준으로 타는 곳을 보여준다.
- 타는 곳을 길 건너편으로 바꾼 경우에만 "횡단보도로 건너세요. 초록불에 주위를 살피세요."라고 안내한다.
- 나가는 데 시간이 걸릴 수 있으므로 서두르라고 재촉하지 않는다.
- 택시 연결에 실패하면 (⭕❌) "카카오택시 연결이 안 되네요. 한 번 더 해볼까요?"라고 묻는다. ⭕면 다시 시도하고, ❌면 부르지 않고 마친다.
- 호출 중이나 대기 중 "취소해"라고 하면 (⭕❌) "택시를 취소할까요?"라고 한 번 더 확인한다. ⭕면 취소하고 "택시를 취소했어요."라고 알리며, ❌면 그대로 진행한다.
- 음성 인식이 안 되면 "말이 안 통하나요?" 창의 큰 버튼으로 이어 간다.
- 침묵은 동의로 보지 않는다. 답이 없으면 호출하지 않고 다시 묻는다.

**구현 범위: 예시안**

실제 서비스 연동 없이 화면 흐름을 보여주는 예시안으로 만든다.

| 항목 | 예시안에서 보여주는 방식 |
|---|---|
| 타는 곳 | 등록한 집 주소를 가정한 예시 지도와 사진 |
| 지도 (필수 화면) | 예시 지도 위에서 택시가 정해 둔 경로로 이동 |
| 호출·결제 | 모의 호출, 예시 요금, 실제 결제 없음 |
| 차량 정보 | 예시 차 사진·차종·차 번호 |
| 시간·도착 | 정해 둔 시간에 맞춰 화면 전환 |

## 9. 최종 UX 문제 정의

**Problem Statement**
이동 경험이 풍부한 어르신도 복잡한 택시 호출 및 지도 앱의 조작 방식 때문에 원하는 장소로 독립적으로 이동하는 데 어려움을 겪는다.

**HMW (How Might We)**
어떻게 하면 어르신이 복잡한 앱 사용법을 배우지 않고도 가족과 대화하는 것처럼 편안하게 택시를 이용하고 목적지까지 이동할 수 있을까?

**Solution**
실제 가족의 모습과 목소리를 활용한 영상통화형 AI가 사용자의 음성 요청을 듣고, 목적지 확인부터 택시 호출, 도보 길찾기까지 한 단계씩 안내한다.

**Core Value**
> 혼자서도 갈 수 있도록, 언제나 곁에.

디지털 기술 때문에 제한되었던 어르신의 **이동 자유를 되찾아 주는 경험**을 핵심으로 한다.
