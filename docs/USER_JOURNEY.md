# 곁에(GYEOT-E) — 유저저니 및 시나리오

> 최신 PRD 기준으로 정리한 페르소나, 유저저니, 스토리보드 시나리오 문서입니다.
> 손주 음성 대본은 [VOICE_SCRIPT.md](./VOICE_SCRIPT.md)를 참고하세요.
> 택시 호출 부분(출발 위치 스캔, 배차 확인)은 팀 논의로 새로 정리한 시나리오이며, PRD와 앱 초안에는 아직 반영 전입니다.

## 1. PRD 핵심 요약

| 구분 | 내용 |
|---|---|
| 서비스명 | 곁에 |
| 서비스 유형 | 고령층 맞춤형 AI 이동 지원 서비스 |
| 메인 기능 | 카카오 택시 호출 (곁에가 직접 호출) |
| 서브 기능 | 도보 길찾기 |
| 인터페이스 | 실제 가족 모습에 가까운 영상통화형 AI |
| 주요 조작 방식 | 음성 대화 |
| 목적지 설정 | 음성 검색 및 자주 가는 장소 우선 확인 |
| 지도 | 필요할 때만 표시 |
| 카메라 | 택시를 부를 출발 위치 확인(폰을 들고 한 바퀴 돌기), 길을 모를 때 방향 화살표 안내 |
| 핵심 가치 | 가족이 곁에서 하나씩 알려주는 안심감 |

**핵심 변화:** 여러 버튼을 선택하는 방식이 아니라, 앱을 켜면 손주와 영상통화하듯 바로 대화가 시작된다. 지도는 보조 수단이다.

**중요:** 곁에가 **카카오 택시를 직접 호출**한다. 먼저 어르신이 폰을 들고 한 바퀴 돌아 **정확한 출발 위치를 확인**하고, 호출 전에 출발지·도착지·예상 요금을 큰 글씨로 보여준 뒤 어르신이 "맞아"라고 하면 부른다. 택시가 배정되면 **해당 차량(사진·번호판·차종)을 보여주고 확인하도록 안내**하며, 도착 예정 시간은 화면이 아니라 AI 음성으로만 알려준다. 어르신은 택시 앱을 조작하지 않으며 곁에는 결제를 처리하지 않는다. 시연의 호출은 모의 호출이다. 자세한 흐름은 [7-1. 택시 호출 상세 흐름](#7-1-택시-호출-상세-흐름)을 참고한다.

## 2. 페르소나 — 김정성

> "가는 길은 잘 아는데, 요즘은 택시 한 번 부르는 것도 어렵더라고."

79세 남성 · 서울 은평구 · 승용차 및 승합차 운전원 · 배우자와 거주 · 핵심 성향: 성실함, 독립적인 생활, 규칙적인 일상, 가족에 대한 애정

| 구분 | 특징 |
|---|---|
| 디지털 활용 능력 | 익숙한 스마트폰 퍼즐 게임은 이용 가능 |
| 이동 능력 | 오랜 운전 경력으로 서울 지리에 익숙 |
| 잠재적 어려움 | 낯선 택시 앱의 메뉴, 위치 설정, 호출 방법 |
| 친숙한 도움 방식 | 손주에게 스마트폰 사용법을 배우는 방식 |
| 심리적 욕구 | 타인의 도움 없이 스스로 일상을 유지하고 싶음 |
| 서비스 이용 동기 | 복잡한 앱 조작 없이 말로 이동 도움을 받고 싶음 |

김정성 씨는 길을 모르는 사람이 아니다. **이동 경험은 풍부하지만, 이동 서비스를 이용하기 위한 디지털 조작에 어려움을 겪는 사람**으로 설정한다.

> 디지털 조작의 어려움과 심리적 욕구는 실제 인터뷰 결과가 아닌 페르소나 기반 가설이다.

## 3. 사용자 시나리오

| 항목 | 내용 |
|---|---|
| 시간 | 평일 오전 10시 |
| 장소 | 은평구 불광동 자택 |
| 상황 | 정기 검진을 위해 병원에 방문해야 함 |
| 배경 | 오늘은 직접 운전하지 않고 택시로 이동하기로 함 |
| 문제 | 택시 앱 이용이 복잡하고 길에서 택시를 잡기 어려움 |
| 서비스 인지 | 손주가 이전에 곁에 앱을 설치해 줌 |
| 사용자 목표 | 손주에게 전화하지 않고 택시로 병원에 도착하기 |
| 기대 결과 | 혼자서도 원하는 곳으로 이동할 수 있다는 자신감 |

**사전 상황:** 며칠 전 손주가 할아버지 스마트폰에 곁에 앱을 설치했다. 손주는 자신의 모습과 목소리를 기반으로 AI 도우미를 설정하고, 자주 가는 병원도 미리 등록해 두었다.

> 병원 방문, 방문 시간, 가족의 사전 설정은 유저저니를 구체화하기 위해 추가한 가상 상황이다.

## 4. AS-IS 유저저니 (곁에가 없을 때)

| 단계 | 사용자 행동 | 사용자 생각 | 감정 | 페인포인트 |
|---|---|---|---|---|
| ① 외출 준비 | 병원 갈 준비를 함 | 오늘은 택시를 타고 가야겠다. | 기대 | - |
| ② 택시 탐색 | 집 앞에서 택시를 잡으려 함 | 빈 택시가 왜 이렇게 없지? | 답답함 | 길거리 택시 이용 어려움 |
| ③ 앱 실행 | 기존 택시 앱을 실행함 | 어디를 눌러야 하지? | 혼란 | 낯선 인터페이스 |
| ④ 장소 설정 | 출발지와 병원을 검색함 | 이 병원이 내가 가려는 곳인가? | 불안 | 위치 설정, 동명 장소 |
| ⑤ 호출 실패 | 호출 과정에서 막혀 포기함 | 잘못 누르면 어떡하지? | 좌절 | 복잡한 호출 과정 |
| ⑥ 도움 요청 | 손주에게 전화함 | 바쁠 텐데 또 전화해야겠네. | 미안함 | 가족에게 의존 |
| ⑦ 이동 | 가족의 도움으로 택시 이용 | 다음에도 부탁해야겠군. | 안도 | 독립 이용 자신감 부족 |

감정 곡선: 기대 → 답답 → 혼란 → 불안 → **좌절(최저)** → 미안함 → 안도 (사용자 인터뷰 이전의 가설 기반)

## 5. TO-BE 유저저니 (곁에 사용 시)

| 단계 | 사용자 행동 | 터치포인트 | 사용자 생각 | 감정 | 개선 기회 |
|---|---|---|---|---|---|
| ① 외출 준비 | 병원 방문을 준비함 | 스마트폰 홈 | 택시를 어떻게 부르지? | 걱정 | 쉬운 앱 진입 |
| ② 앱 실행 | 곁에 앱을 실행함 | 영상통화형 화면 | 손주가 알려주는 것 같네. | 친숙함 | 가족 기반 인터페이스 |
| ③ 목적지 요청 | 병원에 가고 싶다고 말함 | 음성 대화 | 말만 하면 되는구나. | 안도감 | 음성 중심 조작 |
| ④ 장소 확인 | 병원 이름과 지역을 확인함 | 음성 및 큰 글씨 | 내가 가려는 곳이 맞아. | 안정감 | 목적지 오인 방지 |
| ⑤ 이동 방법 결정 | 택시 이용에 동의함 | AI 음성 안내 | 택시로 가면 되겠네. | 신뢰감 | 상황에 맞는 이동 수단 제안 |
| ⑥ 출발 위치 확인 | 안내에 따라 안전한 곳에서 폰을 들고 천천히 한 바퀴 돎. 곁에가 찾은 위치가 맞는지 "응"이라고 확인함 | 카메라 화면(한 바퀴 진행 표시), 주소·지도 큰 글씨 | 이렇게만 돌면 내 위치를 아네. | **신기함 (낯선 동작)** | 한 문장 안내와 진행 격려, 위치 오인 방지 |
| ⑦ 택시 호출 | 곁에가 출발지·도착지·예상 요금을 보여주면 맞는지 확인하고 "맞아"라고 말함. 곁에가 카카오 택시를 직접 부름 | 곁에 화면 (큰 글씨 확인) | 말만 했는데 택시를 불러주네. | **긴장 (요금·호출 확인)** | 호출 전 확인과 호출 중 안내 |
| ⑧ 배차 확인 | 택시가 배정됐다는 안내를 듣고, 오기로 한 차량(사진·번호판·차종)을 확인하고 "알겠어"라고 말함. 도착 예정 시간은 AI 음성으로 들음 | 차량 정보 카드, AI 음성 | 이 차가 오는구나. | 신뢰감 | 한 문장씩 안내, 차량 사전 확인 |
| ⑨ 택시 탑승 | 도착 알림을 듣고 번호판을 확인한 뒤 탑승 | 차량 정보, 승차 위치 | 이제 병원에 갈 수 있겠군. | 안심 | 승차 위치와 번호판 안내 |
| ⑩ 목적지 도착 | 병원에 도착함 | 도착 안내 | 나도 혼자서 할 수 있구나. | 성취감 | 독립적인 이동 경험 |

호출 전 요금을 확인하는 ⑦ 구간에서 불안감이 다시 높아질 가능성이 있다. 앱 전환이 없으므로 곁에 화면 안에서 확인과 호출이 끝난다. 폰을 들고 한 바퀴 도는 ⑥은 낯선 동작이라 "안전한 곳에서"라는 첫 안내와 진행 중 격려("잘하고 계세요")로 부담을 줄인다.

## 6. 스토리보드 상세 시나리오 (10장면)

| 9 | 택시 도착과 탑승 | 택시가 도착하면 도착을 알리고 번호판과 목적지를 확인하게 한다. 승차 위치를 모르면 길찾기 기능을 쓴다. 시연은 "3분 뒤에 도착한대요" 후 약 3초 뒤 도착한 것으로 진행한다. | AI 손주: "택시가 도착했대요. 도착했을까요?" / 김정성: "응." / AI 손주: "번호판과 목적지를 확인하세요." / (필요 시) "할아버지, 잠깐 멈추고 방향을 확인해 주세요." | 안심 |
| 10 | 혼자서 병원에 도착 | 가족에게 부탁하지 않고 이동했다는 성취감을 느낀다. | AI 손주: "할아버지, 잘 오셨어요!" / 김정성: "다음에도 혼자 갈 수 있겠어." | 만족감, 자신감, 성취감 |

## 7. 서비스 전체 유저 플로우

택시 호출이 중심이고, 거리와 사용자 의사에 따라 도보 길찾기로 이어진다.

```
곁에 앱 실행
  ↓
영상통화형 AI 손주 등장
  ↓
음성으로 목적지 요청
  ↓
목적지 이름 및 지역 확인
  ↓
이동 방법 확인 및 제안
  ├─ [택시 부르기] (메인)
  │     출발 위치 확인(폰을 들고 한 바퀴) → 위치 맞는지 확인
  │     → 출발지·도착지·요금 확인 → 곁에가 카카오 택시 호출
  │     → 배차 확인(차량 사진·번호판, 한 문장씩 안내) → 도착 확인 → 택시 탑승
  └─ [도보 길찾기] (서브)
        단계별 음성 안내 → 필요 시 지도 보기 → 카메라 방향 안내(선택)
  ↓
목적지 도착 및 칭찬
```

### 7-1. 택시 호출 상세 흐름

택시 부르기(메인)의 단계별 상세 흐름이다. 한 문장에 한 동작만 말하고, 화면에서는 한 번에 한 가지만 바뀐다.

| 단계 | 어르신 | 곁에(AI 손주) | 화면 | 다음으로 넘어가는 조건 |
|---|---|---|---|---|
| 1. 요청 | "택시 잡아줘" | "어디로 가실까요?" | 듣는 중 | 음성 인식 |
| 2. 목적지 확인 | "병원" | 같은 이름 병원이 여럿이면 가까운 곳부터 "○○동 병원이에요?" | 이름·지역 큰 글씨 | "응" (확인 없이는 넘어가지 않음) |
| 3. 위치 스캔 | 안전한 곳에서 폰을 들고 천천히 한 바퀴 돎 | "안전한 곳에서 핸드폰을 들고 천천히 한 바퀴 돌아 주세요." (진행 중 "잘하고 계세요. 조금만 더 돌아 주세요.") | 카메라 화면과 한 바퀴 진행 표시 | 한 바퀴 완료 |
| 4. 위치 확인 | "응" / "아니" | 주변 간판·건물로 위치를 찾아 "불광역 2번 출구 앞이에요?" | 주소·지도 큰 글씨 | "응" |
| 5. 호출 전 확인 | "맞아" | 출발지·도착지·예상 요금을 보여주며 확인을 받음 | 큰 글씨 확인 화면 | "맞아" |
| 6. 택시 호출 | 기다림 | 곁에가 확인된 위치로 카카오 택시를 부름 (시연은 모의 호출) | "택시를 부르고 있어요" | 배차 완료 |
| 7-1. 배차 알림 | — | "택시가 배정됐어요." | "배정 완료"로 바뀜 | 말이 끝나면 자동 |
| 7-2. 차량 확인 | "알겠어" | "이 차량이 오기로 했으니 확인해 주세요." | 택시 사진·번호판·차종 카드 | "알겠어" (큰 버튼도 있음) |
| 7-3. 도착 예정 | — | "○분 뒤에 도착한대요." (시연: "3분 뒤에 도착한대요.") | 차량 카드 유지, **도착 시간 글씨 없음** | 말이 끝나면 자동 ("다시"라고 하면 한 번 더 말함) |
| 8. 기다리기 | — | "여기서 기다리세요." | 차량 카드 유지 | 도착 알림 |
| 9. 도착 확인 | "응" | "택시가 도착했대요. 도착했을까요?" → "번호판과 목적지를 확인하세요." | 번호판 크게 | "알겠어" |
| 10. 마침 | 탑승 | "필요하면 또 불러주세요." | 처음 화면 | — |

**예외 처리**
- 한 바퀴 영상이 흐리거나 위치를 못 찾으면 "다시 한 번 돌아 주세요"라고 안내하고, 그래도 안 되면 가족이 등록한 장소(집 앞, 병원 앞 등)를 선택 버튼으로 고르게 한다.
- 위치가 틀렸다고 "아니"라고 하면 다시 한 바퀴 돌도록 안내한다.
- 음성 인식이 안 될 때는 모든 단계에서 "말이 안 통하나요?" 창의 큰 버튼으로 이어 갈 수 있다.

**시연과 실제 서비스**

| 항목 | 시연 | 실제 서비스 |
|---|---|---|
| 위치 확인 | 미리 정한 장면(예: 집 앞)에서 한 바퀴 도는 동작을 하면 정해 둔 위치로 인식(가상 위치) | GPS와 한 바퀴 영상에서 고른 몇 장을 함께 써서 위치 보정 |
| 택시 호출 | 모의 호출, 예시 요금 | 카카오모빌리티 제휴·API 연동 |
| 차량 사진·번호판 | 예시 이미지와 예시 번호판 | 실제 배차 정보(사진 제공 여부는 확인 필요) |
| 도착 예정 시간 | 미리 녹음한 "3분 뒤에 도착한대요" | 실제 도착 시간을 넣은 음성 생성 |

**안전과 개인정보**
- 돌아다니며 폰을 드는 동작이라 첫 문장에서 "안전한 곳에서"를 먼저 말한다. 도로 근처나 계단에서는 하지 않도록 안내한다.
- 한 바퀴 영상에는 사람 얼굴이나 다른 차 번호판이 들어갈 수 있다. 시작 전에 동의를 받고, 영상 전체가 아니라 위치 인식에 쓸 몇 장만 보내며, 인식이 끝나면 저장하지 않는다.

## 8. 주요 터치포인트 UI

카카오 로그인 가이드의 옐로우/블랙 색상을 참고하고 고령층 사용성을 고려한 곁에 전용 UI 콘셉트이다.

| # | 화면 | 구성 | 비고 |
|---|---|---|---|
| 01 | 앱 실행 | 손주 얼굴 + "할아버지, 오늘 어디 가세요?" + 큰 마이크 버튼("듣고 있어요") + 지도 보기 | 별도 메뉴 선택 없이 바로 대화 시작 |
| 02 | 목적지 확인 | "평소 가시는 병원 맞아요?" + 목적지 카드(불광동 병원) + [맞아] / [아니야] | 음성 응답 또는 큰 버튼 |
| 03 | 이동 수단 결정 | "택시를 부를까요?" + [택시 부르기](노란 버튼) + [걸어서 가기] | 동의 후 위치 스캔 화면으로 이동 |
| 04 | 위치 스캔 | 카메라 화면 + "안전한 곳에서 핸드폰을 들고 천천히 한 바퀴 돌아 주세요." + 한 바퀴 진행 표시(원형 링) | 폰을 들고 한 바퀴 돌며 출발 위치를 확인. 셔터를 누르지 않음 |
| 05 | 위치 확인 | "불광역 2번 출구 앞이에요?" + 주소·지도 + [맞아] / [아니야] | 음성 응답 또는 큰 버튼. 맞으면 요금 확인 화면으로 이동 |
| 06 | 배차 확인 | "택시가 배정됐어요." → "이 차량이 오기로 했으니 확인해 주세요." + 택시 사진·번호판·차종 카드 | 한 문장씩 표시. 도착 예정 시간은 화면에 쓰지 않고 AI 음성으로만 안내 |
| 07 | 지도 보기 | 현재 위치~병원 경로 + "안내로 돌아가기" | 필요한 순간에만 확인 |
| 08 | 카메라 방향 안내 | 카메라 화면 위 화살표 + "앞으로 쭉 가세요. 멈춰서 방향을 확인하세요." + 닫기 | 길이 헷갈릴 때 보조적으로 사용 |
| 09 | 도착 완료 | 손주 얼굴 + "할아버지, 잘 오셨어요!" + [안내 마치기] | 친숙한 칭찬으로 성취감 제공 |

> 실제 카카오 공식 UI가 아닌 곁에 자체 와이어프레임 제안이다.
> 위치 스캔(04)은 택시 흐름의 단계이고, 카메라 방향 안내(08)는 PRD상 선택적 MVP 기능이다. 실제 GPS 연동은 이후 범위이다.
> 택시 호출 단계(요금 확인 화면 등)는 위 7-1의 상세 흐름을 따른다.

## 9. 최종 UX 문제 정의

**Problem Statement**
이동 경험이 풍부한 어르신도 복잡한 택시 호출 및 지도 앱의 조작 방식 때문에 원하는 장소로 독립적으로 이동하는 데 어려움을 겪는다.

**HMW (How Might We)**
어떻게 하면 어르신이 복잡한 앱 사용법을 배우지 않고도 가족과 대화하는 것처럼 편안하게 택시를 이용하고 목적지까지 이동할 수 있을까?

**Solution**
실제 가족의 모습과 목소리를 활용한 영상통화형 AI가 사용자의 음성 요청을 듣고, 목적지 확인부터 택시 호출, 도보 길찾기까지 한 단계씩 안내한다.

**Core Value**
> 혼자서도 갈 수 있도록, 언제나 곁에.

디지털 기술 때문에 제한되었던 어르신의 **이동 자유를 되찾아 주는 경험**을 핵심으로 한다.
