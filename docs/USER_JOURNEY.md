# 곁에(GYEOT-E) — 유저저니 및 시나리오

> 최신 PRD 기준으로 정리한 페르소나, 유저저니, 스토리보드 시나리오 문서입니다.
> 손주 음성 대본은 [VOICE_SCRIPT.md](./VOICE_SCRIPT.md)를 참고하세요.

## 1. PRD 핵심 요약

| 구분 | 내용 |
|---|---|
| 서비스명 | 곁에 |
| 서비스 유형 | 고령층 맞춤형 AI 이동 지원 서비스 |
| 메인 기능 | 카카오 택시 호출 (곁에가 직접 호출) |
| 서브 기능 | 도보 길찾기 |
| 인터페이스 | 실제 가족 모습에 가까운 영상통화형 AI |
| 주요 조작 방식 | 음성 대화 |
| 목적지 설정 | 음성 검색 및 자주 가는 장소 우선 확인 |
| 지도 | 필요할 때만 표시 |
| 카메라 | 길을 모를 때 방향을 화살표로 안내 |
| 핵심 가치 | 가족이 곁에서 하나씩 알려주는 안심감 |

**핵심 변화:** 여러 버튼을 선택하는 방식이 아니라, 앱을 켜면 손주와 영상통화하듯 바로 대화가 시작된다. 지도는 보조 수단이다.

**중요:** 곁에가 **카카오 택시를 직접 호출**한다. 호출 전에 출발지·도착지·예상 요금을 큰 글씨로 보여주고, 어르신이 "맞아"라고 하면 부른다. 어르신은 택시 앱을 조작하지 않으며 곁에는 결제를 처리하지 않는다. 시연의 호출은 모의 호출이다.

## 2. 페르소나 — 김정성

> "가는 길은 잘 아는데, 요즘은 택시 한 번 부르는 것도 어렵더라고."

79세 남성 · 서울 은평구 · 승용차 및 승합차 운전원 · 배우자와 거주 · 핵심 성향: 성실함, 독립적인 생활, 규칙적인 일상, 가족에 대한 애정

| 구분 | 특징 |
|---|---|
| 디지털 활용 능력 | 익숙한 스마트폰 퍼즐 게임은 이용 가능 |
| 이동 능력 | 오랜 운전 경력으로 서울 지리에 익숙 |
| 잠재적 어려움 | 낯선 택시 앱의 메뉴, 위치 설정, 호출 방법 |
| 친숙한 도움 방식 | 손주에게 스마트폰 사용법을 배우는 방식 |
| 심리적 욕구 | 타인의 도움 없이 스스로 일상을 유지하고 싶음 |
| 서비스 이용 동기 | 복잡한 앱 조작 없이 말로 이동 도움을 받고 싶음 |

김정성 씨는 길을 모르는 사람이 아니다. **이동 경험은 풍부하지만, 이동 서비스를 이용하기 위한 디지털 조작에 어려움을 겪는 사람**으로 설정한다.

> 디지털 조작의 어려움과 심리적 욕구는 실제 인터뷰 결과가 아닌 페르소나 기반 가설이다.

## 3. 사용자 시나리오

| 항목 | 내용 |
|---|---|
| 시간 | 평일 오전 10시 |
| 장소 | 은평구 불광동 자택 |
| 상황 | 정기 검진을 위해 병원에 방문해야 함 |
| 배경 | 오늘은 직접 운전하지 않고 택시로 이동하기로 함 |
| 문제 | 택시 앱 이용이 복잡하고 길에서 택시를 잡기 어려움 |
| 서비스 인지 | 손주가 이전에 곁에 앱을 설치해 줌 |
| 사용자 목표 | 손주에게 전화하지 않고 택시로 병원에 도착하기 |
| 기대 결과 | 혼자서도 원하는 곳으로 이동할 수 있다는 자신감 |

**사전 상황:** 며칠 전 손주가 할아버지 스마트폰에 곁에 앱을 설치했다. 손주는 자신의 모습과 목소리를 기반으로 AI 도우미를 설정하고, 자주 가는 병원도 미리 등록해 두었다.

> 병원 방문, 방문 시간, 가족의 사전 설정은 유저저니를 구체화하기 위해 추가한 가상 상황이다.

## 4. AS-IS 유저저니 (곁에가 없을 때)

| 단계 | 사용자 행동 | 사용자 생각 | 감정 | 페인포인트 |
|---|---|---|---|---|
| ① 외출 준비 | 병원 갈 준비를 함 | 오늘은 택시를 타고 가야겠다. | 기대 | - |
| ② 택시 탐색 | 집 앞에서 택시를 잡으려 함 | 빈 택시가 왜 이렇게 없지? | 답답함 | 길거리 택시 이용 어려움 |
| ③ 앱 실행 | 기존 택시 앱을 실행함 | 어디를 눌러야 하지? | 혼란 | 낯선 인터페이스 |
| ④ 장소 설정 | 출발지와 병원을 검색함 | 이 병원이 내가 가려는 곳인가? | 불안 | 위치 설정, 동명 장소 |
| ⑤ 호출 실패 | 호출 과정에서 막혀 포기함 | 잘못 누르면 어떡하지? | 좌절 | 복잡한 호출 과정 |
| ⑥ 도움 요청 | 손주에게 전화함 | 바쁠 텐데 또 전화해야겠네. | 미안함 | 가족에게 의존 |
| ⑦ 이동 | 가족의 도움으로 택시 이용 | 다음에도 부탁해야겠군. | 안도 | 독립 이용 자신감 부족 |

감정 곡선: 기대 → 답답 → 혼란 → 불안 → **좌절(최저)** → 미안함 → 안도 (사용자 인터뷰 이전의 가설 기반)

## 5. TO-BE 유저저니 (곁에 사용 시)

| 단계 | 사용자 행동 | 터치포인트 | 사용자 생각 | 감정 | 개선 기회 |
|---|---|---|---|---|---|
| ① 외출 준비 | 병원 방문을 준비함 | 스마트폰 홈 | 택시를 어떻게 부르지? | 걱정 | 쉬운 앱 진입 |
| ② 앱 실행 | 곁에 앱을 실행함 | 영상통화형 화면 | 손주가 알려주는 것 같네. | 친숙함 | 가족 기반 인터페이스 |
| ③ 목적지 요청 | 병원에 가고 싶다고 말함 | 음성 대화 | 말만 하면 되는구나. | 안도감 | 음성 중심 조작 |
| ④ 장소 확인 | 병원 이름과 지역을 확인함 | 음성 및 큰 글씨 | 내가 가려는 곳이 맞아. | 안정감 | 목적지 오인 방지 |
| ⑤ 이동 방법 결정 | 택시 이용에 동의함 | AI 음성 안내 | 택시로 가면 되겠네. | 신뢰감 | 상황에 맞는 이동 수단 제안 |
| ⑥ 택시 호출 | 곁에가 출발지·도착지·예상 요금을 보여주면 맞는지 확인하고 "맞아"라고 말함. 곁에가 카카오 택시를 직접 부름 | 곁에 화면 (큰 글씨 확인) | 말만 했는데 택시를 불러주네. | **긴장 (요금·호출 확인)** | 호출 전 확인과 호출 중 안내 |
| ⑦ 택시 탑승 | 배정된 택시를 확인하고 탑승 | 차량 정보, 승차 위치 | 이제 병원에 갈 수 있겠군. | 안심 | 승차 위치 안내 |
| ⑧ 목적지 도착 | 병원에 도착함 | 도착 안내 | 나도 혼자서 할 수 있구나. | 성취감 | 독립적인 이동 경험 |

호출 전 요금을 확인하는 ⑥ 구간에서 불안감이 다시 높아질 가능성이 있다. 앱 전환이 없으므로 곁에 화면 안에서 확인과 호출이 끝난다.

## 6. 스토리보드 상세 시나리오 (8장면)

| # | 장면 | 내용 | 대사 | 감정 |
|---|---|---|---|---|
| 1 | 병원에 가는 날 | 외출 준비. 오늘은 운전 대신 택시를 이용하려 한다. | 김정성: "오늘은 택시 타고 병원에 다녀와야겠어." | 기대감, 약간의 걱정 |
| 2 | 잡히지 않는 택시 | 집 앞에서 택시를 기다리지만 잡히지 않아 손주가 설치해 준 앱을 떠올린다. | 김정성: "요즘은 택시도 전부 앱으로 부르나 보네." | 답답함, 막막함 |
| 3 | 손주와 영상통화하듯 | 앱을 실행하면 손주를 닮은 AI 도우미가 나타난다. 첫 이용 시 가족 모습으로 만든 AI임을 안내한다. | AI 손주: "할아버지, 오늘 어디 가세요?" / 김정성: "나 병원 갈 건데 어떻게 가?" | 친숙함, 안도감 |
| 4 | 목적지 확인 | 미리 등록된 병원을 우선 확인하고 이름과 지역을 큰 글씨로 보여준다. | AI 손주: "할아버지, 평소에 가시는 불광동 병원 맞아요?" / 김정성: "응, 거기 맞아." | 안정감 |
| 5 | 택시 이용 제안 | 거리와 상황을 바탕으로 택시 이용을 제안한다. | AI 손주: "걸어가기에는 조금 멀어요. 택시 부를까요?" / 김정성: "그래, 택시 불러줘." / AI 손주: "지금 계신 곳에서 부를까요?" / 김정성: "응." | 신뢰감 |
| 6 | 카카오 택시 호출 | 곁에가 출발지·도착지·예상 요금을 큰 글씨로 보여주고, 어르신이 "맞아"라고 하면 곁에가 카카오 택시를 직접 부른다. | AI 손주: "네! 카카오택시로 불러드릴게요. 출발하는 곳, 도착하는 곳, 요금을 확인해 주세요." / 김정성: "맞아." / AI 손주: "택시를 부르고 있어요. 잠깐만 기다리세요." | 긴장, 신중함 |
| 7 | 택시 찾아 탑승 | 호출 성공 후 승차 장소로 이동한다. 승차 위치를 모르면 길찾기 기능을 쓴다. | AI 손주: "할아버지, 잠깐 멈추고 방향을 확인해 주세요." (필요 시 카메라 방향 안내 또는 지도 보기) | 안심 |
| 8 | 혼자서 병원에 도착 | 가족에게 부탁하지 않고 이동했다는 성취감을 느낀다. | AI 손주: "할아버지, 잘 오셨어요!" / 김정성: "다음에도 혼자 갈 수 있겠어." | 만족감, 자신감, 성취감 |

## 7. 서비스 전체 유저 플로우

택시 호출이 중심이고, 거리와 사용자 의사에 따라 도보 길찾기로 이어진다.

```
곁에 앱 실행
  ↓
영상통화형 AI 손주 등장
  ↓
음성으로 목적지 요청
  ↓
목적지 이름 및 지역 확인
  ↓
이동 방법 확인 및 제안
  ├─ [택시 부르기] (메인)
  │     현재 위치 확인 → 출발지·도착지·요금 확인 → 곁에가 카카오 택시 호출 → 택시 탑승
  └─ [도보 길찾기] (서브)
        단계별 음성 안내 → 필요 시 지도 보기 → 카메라 방향 안내(선택)
  ↓
목적지 도착 및 칭찬
```

## 8. 주요 터치포인트 UI

카카오 로그인 가이드의 옐로우/블랙 색상을 참고하고 고령층 사용성을 고려한 곁에 전용 UI 콘셉트이다.

| # | 화면 | 구성 | 비고 |
|---|---|---|---|
| 01 | 앱 실행 | 손주 얼굴 + "할아버지, 오늘 어디 가세요?" + 큰 마이크 버튼("듣고 있어요") + 지도 보기 | 별도 메뉴 선택 없이 바로 대화 시작 |
| 02 | 목적지 확인 | "평소 가시는 병원 맞아요?" + 목적지 카드(불광동 병원) + [맞아] / [아니야] | 음성 응답 또는 큰 버튼 |
| 03 | 이동 수단 결정 | "택시를 부를까요?" + [택시 부르기](노란 버튼) + [걸어서 가기] | 동의 후 요금 확인 화면으로 이동 |
| 04 | 지도 보기 | 현재 위치~병원 경로 + "안내로 돌아가기" | 필요한 순간에만 확인 |
| 05 | 카메라 방향 안내 | 카메라 화면 위 화살표 + "앞으로 쭉 가세요. 멈춰서 방향을 확인하세요." + 닫기 | 길이 헷갈릴 때 보조적으로 사용 |
| 06 | 도착 완료 | 손주 얼굴 + "할아버지, 잘 오셨어요!" + [안내 마치기] | 친숙한 칭찬으로 성취감 제공 |

> 실제 카카오 공식 UI가 아닌 곁에 자체 와이어프레임 제안이다.
> 카메라 방향 안내는 PRD상 선택적 MVP 기능이며, 실제 GPS 연동은 이후 범위이다.

## 9. 최종 UX 문제 정의

**Problem Statement**
이동 경험이 풍부한 어르신도 복잡한 택시 호출 및 지도 앱의 조작 방식 때문에 원하는 장소로 독립적으로 이동하는 데 어려움을 겪는다.

**HMW (How Might We)**
어떻게 하면 어르신이 복잡한 앱 사용법을 배우지 않고도 가족과 대화하는 것처럼 편안하게 택시를 이용하고 목적지까지 이동할 수 있을까?

**Solution**
실제 가족의 모습과 목소리를 활용한 영상통화형 AI가 사용자의 음성 요청을 듣고, 목적지 확인부터 택시 호출, 도보 길찾기까지 한 단계씩 안내한다.

**Core Value**
> 혼자서도 갈 수 있도록, 언제나 곁에.

디지털 기술 때문에 제한되었던 어르신의 **이동 자유를 되찾아 주는 경험**을 핵심으로 한다.
