# 곁에 PRD 초안

2026-11-25

곁에는 어르신이 앱을 켜고 "나 여기 갈 건데 어떻게 가?"라고 말하면, 영상통화처럼 보이는 가족 아바타가 가족의 목소리로(시연은 녹음한 음성) 길을 짧은 문장으로 한 단계씩 알려주는 AI 도우미입니다. **택시 부르기가 메인**이고, 길찾기도 함께 들어갑니다. 택시는 카카오 택시로 연결하고, 가까우면 걸어가는 길을 안내합니다. 길을 모를 때는 카메라를 들어 비추면 가야 할 방향을 큰 화살표로 알려주고, 지도 보기 버튼은 시간이 되면 넣습니다. 전철, 버스, 시외버스 예약 같은 다른 이동·예약도 같은 방식으로 돕도록 확장할 계획입니다. MVP는 가상 위치(실제 위치가 아닌 정해 둔 위치)로 시연합니다.

## 배경과 문제

어르신이 혼자 이동하려면, 길을 알려주는 사람이 거의 항상 필요합니다.

- 지도앱, 택시앱, 버스·기차 예약앱처럼 이동에 앱이 필요한 일이 늘었습니다.
- 어르신은 길은 알아도 택시 앱의 메뉴, 위치 설정, 호출 방법이 낯설어 막히고, 같은 이름의 다른 장소로 잘못 가기도 합니다. 길을 잃을까 봐 외출 자체를 망설이기도 합니다.
- 가족은 전화로 "거기서 왼쪽으로 가"를 반복해야 하고, 직접 데려다줄 수 없는 경우가 많습니다.
- 기존 앱은 글자와 화면 중심이라 어르신께 낯섭니다. 어르신이 따르는 건 "아는 사람의 목소리"입니다.
- 요즘 택시는 앱으로 호출하거나 미리 예약하는 방식이 중심이라, 길에서 손을 들어도 빈 택시가 잘 보이지 않고 잡기 어렵습니다. 앱을 못 쓰면 택시를 타기 어려워졌습니다.

핵심 통찰은 어르신께 필요한 것이 기능 설명이 아니라 **믿는 사람이 옆에서 하나하나 말해 준다는 안심감**이라는 점입니다.

**아바타를 쓰는 이유:** 어르신은 새로운 앱에 거부감이 커서, 처음부터 낯선 화면을 쓰게 하면 시작조차 어렵습니다. 아는 가족의 얼굴과 목소리가 말해 주면 새 앱이라는 느낌이 줄어들어, 영상통화하듯 편하게 시작할 수 있습니다.

## 목표와 성공 지표

MVP(핵심 기능 하나만 실제로 동작하게 만든 최소 제품)의 목표는 "어르신이 앱을 켜고 말하는 것만으로 택시를 부르고, 가까우면 길을 따라간다"는 가설을 검증하는 것입니다.

**시연 한 줄:** 평일 오전 10시, 불광동 자택의 김정성 할아버지가 앱을 켜고 "병원 가고 싶어"라고 말하면, 같은 이름 병원 중 가까운 곳을 확인하고, 가까우면 짧은 안내로 걸어가는 길을, 멀면 택시를 부르는 것을 돕습니다. 택시는 타는 곳을 확인하고 출발지·도착지·예상 요금을 확인받은 뒤 곁에가 카카오 택시를 부르고(시연은 모의 호출), "여기서 기다리세요"까지 안내합니다.

**택시에서 곁에가 돕는 부분:** 곁에는 어르신이 앱 사용법을 몰라도 말 한마디로 택시를 부를 수 있게 하고, 어디서 부를지, 어디서 기다릴지, 도착했는지를 아바타가 하나씩 확인해 줍니다.

| 지표 | 측정 방법 | 목표 |
| --- | --- | --- |
| 택시 호출 성공률 | 테스트 참가자 중 도움 없이 올바른 목적지와 타는 곳을 확인하고 택시 호출까지 마친 비율 | 정해야 함 |
| 호출까지 걸린 시간 | 곁에를 연 때부터 택시 호출 완료까지 초 단위 측정 | 정해야 함 |
| 막히는 횟수 | "다시 알려줘" 요청 횟수와 장소를 잘못 알아들은 횟수 | 정해야 함 |
| 안심감 | 사용 후 "혼자 해냈다는 느낌이 들었는지" 5점 척도 질문 | 정해야 함 |

팀플 단계에서는 어르신 3~5분을 대상으로 짧은 사용성 테스트(실제 사용자에게 써보게 하고 관찰하는 테스트)를 하고 위 표의 목표수치를 팀이 정합니다.

## 핵심 시나리오

**상황:** 평일 오전 10시, 은평구 불광동 자택. 김정성 할아버지는 정기 검진을 받으러 병원에 가야 하고, 오늘은 운전하지 않고 택시로 가기로 했습니다. 집 앞에서 빈 택시가 잘 보이지 않아 며칠 전 손주가 설치해 준 곁에를 엽니다. 손주가 자신의 모습과 목소리로 AI 도우미를 만들고 자주 가는 병원을 미리 등록해 두었습니다. 목표는 손주에게 전화하지 않고 혼자 택시로 병원에 가는 것입니다. 이 상황은 시나리오를 구체화하려고 더한 가상 설정이며, 김정성 씨는 합성 데이터(nvidia/Nemotron-Personas-Korea, CC BY 4.0) 기반 페르소나입니다. 자세한 유저저니는 GitHub docs/USER\_JOURNEY.md에 있습니다.

김정성 할아버지가 앱을 켜고 병원 가는 길을 묻고, 택시를 부르거나 걸어서 가는 흐름입니다. 택시 부르기가 메인이고 길찾기는 목적지 확인, 택시 타는 곳까지 가는 길, 가까운 거리의 도보 안내에 쓰입니다. 안내 문장은 모두 한 문장에 한 동작만 담은 짧은 말입니다. (사용자 흐름은 사용자가 목표를 이루기까지 거치는 단계를 순서대로 적은 것입니다.)

1. 할아버지가 곁에를 열면 영상통화처럼 보이는 가족 아바타가 화면에 나오고, 앱이 바로 듣는 상태가 됩니다. 화면에는 "AI 도우미" 표시, 인사말, 듣고 있다는 표시, 큰 말하기 버튼이 있습니다. 첫 인사에서 "가족 모습으로 만든 AI 도우미예요"라고 한 번 알려줍니다. 화면을 안 봐도 소리만으로 따라갈 수 있습니다.
2. 할아버지가 바로 "나 병원 갈 건데 택시 잡아줘" 또는 "나 병원 갈 건데 어떻게 가?"라고 말합니다. (음성 인식으로 말을 글자로 바꾸고, AI가 "아픈데 병원 가야지" 같은 말도 목적지 요청으로 이해합니다.)
3. 같은 이름의 장소가 여러 곳이면 현재 위치에서 가장 가까운 곳부터 지역을 넣어 확인합니다. 예: "불광동에 있는 병원 맞아요?" 가족이 등록한 자주 가는 곳이 있으면 그곳을 먼저 말합니다. 이름과 지역은 화면에 큰 글자로도 보여줍니다. 할아버지가 "응"이라고 하면 넘어가고, "아니"라고 하면 다음으로 가까운 곳을 묻습니다. 확인 없이는 절대 다음으로 넘어가지 않습니다.
4. 할아버지가 "택시 잡아줘"라고 하면 바로 택시를 부릅니다(5번으로). 그냥 "어떻게 가?"라고 했는데 멀면 "뭐 타고 갈래요? 걸어갈래요?"라고 묻습니다. "택시"라고 하면 5번으로, "걸어서"라고 하면 걸어가는 길을 안내합니다. (아래 "걸어갈 때")
5. "지금 계신 곳에서 부를까요?"라고 택시 타는 곳을 확인합니다. "아니"라고 하면 "그럼 어디로 부를까요?"라고 묻고, 할아버지가 말한 곳으로 타는 곳을 바꿉니다. 택시가 서기 어려운 곳이면 가까운 큰길까지 짧은 문장으로 길을 안내합니다. 예: "나가서 오른쪽으로 가세요." "횡단보도를 건너세요."
6. 할아버지가 "응"이라고 하면 "네! 카카오택시로 불러드릴게요."라고 말한 뒤, 출발지·도착지·예상 요금을 큰 글씨로 보여주며 "출발하는 곳, 도착하는 곳, 요금을 확인해 주세요."라고 말합니다. 할아버지가 "맞아"라고 하면 곁에가 카카오 택시를 직접 부르고 "택시를 부르고 있어요. 잠깐만 기다리세요."라고 알려줍니다. 할아버지는 택시 앱을 조작하지 않습니다. 요금은 확인만 하고, 곁에는 결제를 처리하지 않습니다. 시연의 호출은 모의 호출이고 요금은 예시 금액입니다. 택시가 잘 안 잡히면 "택시가 안 잡혀요. 다른 길로 갈까요, 계속 부를까요?"라고 묻습니다. "다른 길"이라고 하면 다른 경로를 안내하고, "계속"이라고 하면 기다리며 다시 부릅니다.
7. 호출이 끝나면 "여기서 기다리세요."라고 말하고, 카카오 택시에서 도착 알림이 오면 "택시가 도착했대요. 도착했을까요?"라고 묻고(시연에서는 "택시가 3분 뒤에 도착한대요."라고 말한 뒤 약 3초 뒤 도착한 것으로 진행), "응"이라고 하면 "번호판과 목적지를 확인하세요."라고 짧게 알려줍니다.
8. 도착하면 미리 녹음해 둔 "잘 오셨어요!"라는 칭찬이 나옵니다.

**"아니"라고 할 때와 취소:** 아래는 시연 전에 팀이 확인할 **[제안]**입니다.

| 상황 | 곁에의 처리 [제안] |
| --- | --- |
| 출발지·도착지·요금 확인에서 "아니야" | 부르지 않고 "어디가 다른가요? 타는 곳, 가는 곳, 요금 중에 말씀해 주세요."라고 물음. 타는 곳이면 타는 곳을 다시 묻고, 가는 곳이면 목적지 확인으로 돌아감. 요금이면 "그럼 택시는 부르지 않을게요."라고 말하고 마침. 고친 뒤에는 확인 화면을 다시 보여줌 |
| 부르는 중이나 기다리는 중에 "취소해" | "택시를 취소할까요?"라고 한 번 더 확인함. "응"이면 취소하고 "택시를 취소했어요."라고 알림. "아니"면 그대로 진행함. 화면에는 큰 취소 버튼을 함께 둠. 실제 서비스의 취소 수수료는 확인이 필요함 |
| 걸어가기 제안에서 "아니" | "그럼 택시를 부를까요?"라고 물음. "응"이면 타는 곳 확인으로 가고, "아니"면 마침 |
| 택시 연결 실패에서 "아니" | "알겠어요. 택시는 부르지 않을게요."라고 말하고 마침 |

마칠 때는 "필요하면 또 불러주세요."라고 말하고 첫 화면으로 돌아갑니다.

**걸어갈 때:** 가까운 거리나 택시 타는 곳까지는 짧은 문장으로 한 단계씩 길을 알려줍니다. 예: "약국에서 왼쪽으로 가세요." 한 단계가 끝나 할아버지가 "알겠어"라고 하면 다음 단계를 말합니다. 위치상 길을 잘 가고 있으면 중간에도 "잘 가고 계세요."라고 짧게 칭찬합니다. 길을 모르겠으면 "여기서 어디로 가?"라고 말하거나 버튼을 누르고 카메라로 앞을 비춥니다. 영상 위에 가야 할 방향이 큰 화살표로 뜨고 "이쪽으로 가세요."라고 말합니다. 걸으면서 들지 않도록 "멈춰서 비춰 주세요."라고 먼저 안내합니다. 시연은 가상 위치가 정해진 경로를 따라 움직입니다. "지도 보기" 버튼(목업 지도에 현재 위치, 목적지, 경로 표시)은 시간이 되면 넣습니다.

**어르신만의 말:** 어르신이 사투리를 쓰거나 장소를 다르게 부를 수 있어, 가족이 등록한 표현(예: "그려"는 "응", "역전 병원"은 ○○병원)을 등록한 뜻으로 알아듣습니다. 장소는 부르는 이름으로 알아들어도 "○○병원이에요?"라고 반드시 다시 확인합니다. 음성 인식이 매번 다르게 받아 적으면 못 알아들을 수 있어 선택 버튼은 그대로 둡니다.

음성 인식에 실패하면 "다시 알려줘" 버튼과 장소 선택 버튼(병원, 시장, 터미널 등)이 있는 별도 화면이 나옵니다. 시연은 목적지를 미리 정한 2~3곳으로 하고, 그중 한 곳은 같은 이름이 두 곳 있는 장소로 만들어 확인 장면을 보여줍니다.

**가족 시나리오:** 가족이 곁에를 준비하는 흐름입니다. 시연에서는 팀이 가족 설정을 미리 해 두고, 목소리 녹음과 입 위치 맞추기는 시연에서 제외합니다(이후 단계).

1. 가족이 곁에 앱의 가족 설정 화면을 엽니다.
2. 본인 사진을 올립니다. (사진 주인의 동의가 전제입니다.)
3. 생성형 이미지 AI가 사진을 실제 모습에 가까운 아바타로 바꿔주고, 마음에 들 때까지 다시 만들 수 있습니다.
4. 아바타의 입 위치를 손가락으로 한 번 맞춥니다. (이후 단계, 시연 제외)
5. 안내 문장을 하나씩 읽으며 녹음합니다(이후 단계, 시연 제외). 녹음하지 않은 문장은 미리 만든 기본 음성 파일(시연은 녹음한 음성)이 대신 재생됩니다.
6. 할아버지가 자주 가는 곳(병원, 시장, 경로당, 터미널 등)을 이름과 주소로 등록합니다.
7. 어르신이 평소에 쓰는 말을 등록합니다. 뜻("응", "아니", "알겠어", "다시", "잠깐")을 고르고 어르신의 표현을 입력합니다. 자주 가는 곳에는 어르신이 부르는 이름을 함께 적습니다. 시간이 되면 어르신이 그 말을 직접 말해보고, 음성 인식이 받아 적은 글자도 함께 저장합니다. 통화 녹음이나 영상처럼 이미 있는 파일이 있으면 올려 어르신 표현 후보를 받을 수 있습니다(이후 단계).
8. 미리 듣기로 아바타가 말하는 모습과 목소리를 확인합니다.
9. 설정이 끝나면 어르신께 폰을 건네거나 곁에를 설치해 드립니다. (MVP는 설정이 한 폰에만 저장되므로 같은 폰으로 시연합니다.)

## 기능 범위

범위 표시는 세 가지입니다. **MVP(필수)**는 시연에 꼭 필요한 것, **MVP(시간 되면)**는 하루 일정에서 시간이 남을 때 넣는 것, **이후**는 이번 시연 범위 밖입니다.

### 어르신이 쓰는 기능

| 기능 | 범위 | 설명 |
| --- | --- | --- |
| 말하는 아바타 화면 | MVP(필수) | 앱을 열면 영상통화처럼 보이는 가족 아바타, "AI 도우미" 표시, 인사말, 듣기 표시, 큰 말하기 버튼이 보이고 바로 듣는 상태로 시작. 화면을 봐도 되고 안 봐도 되며, 설명은 모두 아바타가 말로 함 |
| AI 도우미 표시와 안내 | MVP(필수) | 화면에 "AI 도우미" 표시를 두고, 첫 인사에서 가족 모습으로 만든 AI임을 한 번 말로 알림 |
| 바로 말해서 시작 | MVP(필수) | 브라우저 기본 음성 인식(Web Speech API)으로 "나 여기 갈 건데 어떻게 가?"처럼 바로 말함. 브라우저가 막을 때를 위해 큰 말하기 버튼을 둠 |
| 같은 이름 장소 확인 | MVP(필수) | 같은 이름의 장소가 여러 곳이면 현재 위치에서 가장 가까운 곳부터 지역과 함께 "맞아요?"라고 꼭 확인. 가족이 등록한 자주 가는 곳을 먼저 말함. 확인 전에는 안내하지 않음 |
| 짧은 문장으로 한 단계씩 길 안내 | MVP(필수) | 한 문장에 한 동작만 담아 방향, 횡단보도, 눈에 띄는 건물이나 간판까지 한 단계씩 안내. 할아버지가 "알겠어"라고 하면 다음 단계. 시연은 미리 정한 경로의 문장을 미리 만든 음성 파일(녹음한 음성)로 재생 |
| 지도 보기 버튼 | MVP(시간 되면) | 필요할 때만 누르는 버튼. 목업 지도에 현재 위치, 목적지, 경로를 보여주고 닫으면 아바타 화면으로 돌아감 |
| 카카오 택시 호출 | MVP(필수) | "택시 잡아줘"라고 하거나 "뭐 타고 갈래요?"에 "택시"라고 하면 택시 부르기를 시작함. "지금 계신 곳에서 부를까요?"로 타는 곳을 확인하고("아니"라고 하면 "그럼 어디로 부를까요?"), 택시가 서기 어려운 곳이면 큰길까지 길을 안내함. 호출 전에 출발지·도착지·예상 요금을 큰 글씨로 보여주고, "맞아"라고 하면 곁에가 직접 부름. 요금은 확인만 하고 결제는 처리하지 않음. 이후 "여기서 기다리세요"라고 안내하고, 도착 알림을 받으면 "도착했을까요?"라고 확인함. 택시가 안 잡히면 "다른 길로 갈까요, 계속 부를까요?"라고 묻고, 연결이 안 되면 "카카오택시 연결이 안 되네요. 한 번 더 해볼까요?"라고 물음. 시연은 호출·요금·도착 알림을 모두 모의로 보여줌(도착은 "3분 뒤에 도착한대요" 후 약 3초 뒤) |
| 음성으로 주고받기 | MVP(필수) | 알아듣는 답은 "응/아니", "알겠어", "다시", "잠깐"처럼 미리 정한 짧은 말로 한정. 도우미가 말하는 동안에는 듣지 않고 끝난 뒤에 들음. 눌러서 답하는 버튼도 함께 둠 |
| 등록한 말 알아듣기 | MVP(시간 되면) | 가족이 등록한 표현과 장소를 부르는 이름을 받아 적은 글자와 비교해 등록한 뜻으로 처리. 장소는 "맞아요?"로 반드시 다시 확인 |
| 가족 목소리 안내 | 이후 | 인사, 확인, 길 안내, 칭찬, 격려 문장을 음성 파일로 재생. 가족 녹음이 있으면 가족 목소리, 없으면 기본 음성. 시연에는 넣지 않고 발표용 영상으로만 보여줌(시연은 녹음한 음성 파일) |
| 단계별 안내 목소리 | MVP(필수) | 시연용 짧은 안내 문장을 직접 녹음해서 미리 만들어 두고, 상황에 맞는 파일을 재생 |
| 아바타 입 움직임 | 이후 | 목소리가 재생되는 동안 소리 크기에 맞춰 입 모양이 바뀌고 눈 깜빡임과 작은 움직임을 더해 영상통화처럼 보이게 함. 시연에는 넣지 않고 발표용 영상으로만 보여줌 |
| 실패 시 선택 버튼 | MVP(필수) | 음성 인식에 실패하면 나오는 별도 화면에서 눌러서 고를 수 있는 장소 선택 버튼 ("다시 알려줘" 포함) |
| 카메라로 방향 보기 | MVP(시간 되면) | 길을 모를 때 폰 카메라로 비추면 영상 위에 가야 할 방향을 큰 화살표로 겹쳐 보여주고 "이쪽으로 가세요."라고 말함. 시연은 미리 정한 장면. 걸으면서 들지 않도록 멈춰서 비추게 안내 |
| AI 말뜻 이해 | MVP(시간 되면) | 텍스트 AI가 "아픈데 병원 가야지" 같은 다양한 말을 목적지 요청으로 이해. 안 될 때는 정해진 단어로 알아들음 |
| 실제 GPS와 지도 API 연동 | 이후 | 폰의 실제 위치와 나침반 방향을 따라 걸음마다 안내하고 카메라 화살표 방향도 실제로 계산. 시연은 가상 위치로 대체 |
| 실제 카카오 택시 호출 연동 | 이후 | 곁에가 실제로 호출하고 예상 요금과 도착 알림을 받아 오는 연동. 카카오모빌리티와의 제휴와 사용할 수 있는 API를 먼저 확인해야 함. 시연은 모의 호출 |
| 자유롭게 대화하는 AI 도우미 | 이후 | 실제 서비스의 최종 형태. 어르신이 하는 말을 이해하고 상황에 맞게 대답하고 되묻는 대화형 AI. 발표에서 반드시 명시함 |
| 실시간 복제 목소리 생성(AI가 만든 새 문장까지 가족 목소리로) | 이후 | 실제 서비스의 최종 형태이며 발표에서 반드시 명시함. 보이스피싱 위험을 설계한 뒤 도입 |
| 혼자 해보기 모드 | 이후 | 안내를 따라 하다 보면 어르신이 직접 할 수 있게 하는 모드 |
| 확장 서비스 | 이후 | 전철, 버스, 시외버스 예약 등. 맨 뒤 "나중에 추가할 기능" 표에 모아 적음 |

### 가족이 쓰는 기능

| 기능 | 범위 | 설명 |
| --- | --- | --- |
| 가족 전용 설정 화면 | MVP(필수) | 어르신께 드리기 전에 가족이 준비하는 화면. 아바타 등록, 자주 가는 곳 등록, 어르신 말 등록만 함(목소리 녹음은 이후). 시간이 없으면 팀이 미리 설정한 값으로 시연 |
| 사진 올리기와 동의 확인 | MVP(시간 되면) | 사진 주인의 동의를 먼저 확인한 뒤 사진을 올림. 변환이 끝나면 원본 사진은 저장하지 않고 아바타 이미지만 폰에 보관 |
| 사진을 아바타로 변환 | MVP(시간 되면) | 올린 사진을 생성형 이미지 AI가 실제 모습에 가까운 아바타로 바꾸고, 마음에 들 때까지 다시 만들 수 있음. 안 되면 미리 만든 아바타로 시연 |
| 아바타 디자인 방향 | MVP(시간 되면) | 영상통화 같은 느낌을 위해 실제 모습에 가까운 사실적인 스타일. 올린 사진을 기반으로 가족임을 알아볼 수 있을 만큼. 실제 얼굴을 쓰므로 본인 동의가 필수이며 앱 안에서만 사용 |
| 입 위치 맞추기 | 이후 | 입 움직임이 자연스럽도록 아바타의 입 위치를 처음에 한 번 맞춤 |
| 안내 문장 직접 녹음 | 이후 | 시연에는 넣지 않음. 가족이 문장을 직접 녹음하면 그 녹음이 기본 음성 파일보다 먼저 재생됨. 기본값은 미리 만든 음성 파일(시연은 녹음한 음성) |
| 자주 가는 곳 등록 | MVP(시간 되면) | 할아버지가 자주 가는 곳(병원, 시장, 경로당 등)의 이름과 주소를 등록. 같은 이름의 장소를 확인할 때 먼저 물어봄 |
| 어르신 말 등록(가족 입력) | MVP(시간 되면) | 뜻("응", "아니", "알겠어", "다시", "잠깐")을 고르고 어르신의 표현을 입력. 장소는 자주 가는 곳의 "부르는 이름" 칸에 적음. 한 표현은 한 가지 뜻에만 등록하고, 언제든 삭제 가능 |
| 어르신이 말해보며 등록 | MVP(시간 되면) | 가족 입력 다음에 만듦. 어르신 본인이 표현을 몇 번 말하면 음성 인식이 받아 적은 글자를 함께 저장. 어르신 동의가 필요하며 녹음 파일은 저장하지 않음 |
| 녹음으로 사투리·발음 학습 | 이후 | 어르신의 녹음(새로 녹음하거나 통화 녹음 같은 이미 있는 녹음본, 영상 속 소리)으로 음성 인식 모델(소리를 글자로 바꾸는 AI)을 맞춰 훈련하는 기능. 동의, 보관, 삭제 방식을 설계한 뒤 검토. 영상은 소리만 쓰고 영상 자체는 저장하지 않는 방향 |
| 기존 녹음본·영상에서 어르신 말 가져오기 | 이후 | 통화 녹음처럼 이미 있는 녹음본이나 영상을 올리면 어르신 목소리 부분을 글자로 받아 적어 표현 후보를 보여주고, 가족이 골라 어르신 말로 등록함. 영상은 소리만 쓰고 올린 파일은 후보를 뽑은 뒤 저장하지 않음. 어르신과 통화 상대의 동의와 법적 확인이 필요함. 이 파일은 녹음으로 사투리·발음 학습에도 쓸 수 있도록 검토 |
| 미리 듣기 | MVP(시간 되면) | 설정이 끝나면 아바타가 말하는 모습과 목소리를 확인 |
| 말하는 모습 영상 올리기 | 이후 | 가족이 말하는 5~10초 영상을 올리면 아바타가 대기 중일 때 반복 재생. 사진 한 장으로 말하는 영상을 자동으로 만드는 립싱크 AI도 이후에 검토 |
| 아바타 꾸미기(편집) | 이후 | 사진 기반 아바타를 머리 모양, 색, 소품 등으로 고쳐 꾸미는 기능. 우선순위에 넣지 않음 |
| 어르신 사용 확인 알림 | 이후 | 어르신이 곁에를 사용했는지 가족이 확인할 수 있게 하는 알림이나 사용 기록 |

**사용자 기능이 아니라 팀이 준비하는 것:** 안내 문장을 녹음해 음성 파일 만들기, 문장 목록 확정, AI 키 입력칸(본인 폰에만 저장)을 만듭니다. 안내 문장은 짧게 쓰고, 공통 문장(인사, AI 안내, 확인, 다시, 잠깐, 알겠어, 칭찬, 격려)에 택시 문장과 시연 목적지 2~3곳의 경로 문장을 더해 약 25개 안팎을 목표로 합니다. 택시 문장은 아래와 같습니다. 이름이 들어가는 말은 시연 목적지로 한정합니다.

- "택시 부를까요?"
- "지금 계신 곳에서 부를까요?"
- "큰길까지 같이 가요."
- "네! 카카오택시로 불러드릴게요."
- "출발하는 곳, 도착하는 곳, 요금을 확인해 주세요."
- "택시를 부르고 있어요. 잠깐만 기다리세요."
- "할아버지, 카카오택시 연결이 안 되네요. 한 번 더 해볼까요?" (연결이 안 될 때)
- "여기서 기다리세요."
- "택시가 오면 번호판을 보세요."
- "목적지를 기사님께 말씀하세요."
- "뭐 타고 갈래요? 걸어갈래요?"

- "택시가 안 잡혀요. 다른 길로 갈까요, 계속 부를까요?"
- "다른 길로 안내할게요."
- "계속 부르세요. 조금 더 기다려 봐요."
- "그럼 어디로 부를까요?"
- "택시가 도착했대요. 도착했을까요?"
- [제안] "어디가 다른가요? 타는 곳, 가는 곳, 요금 중에 말씀해 주세요."
- [제안] "그럼 택시는 부르지 않을게요."
- [제안] "택시를 취소할까요?"
- [제안] "택시를 취소했어요."
- [제안] "그럼 택시를 부를까요?"
- [제안] "알겠어요. 택시는 부르지 않을게요."
- [제안] "필요하면 또 불러주세요."
- "택시가 3분 뒤에 도착한대요."

## MVP 우선순위

하루 안에 만들어야 하므로 "시연 한 줄"에 필요한 것만 P0로 둡니다. (P0은 꼭 되어야 하는 것, P1은 시간이 되면 넣는 것, P2는 시연 범위 밖이지만 시간이 남으면 해보는 것, P3은 우선순위에 넣지 않고 이후로 미루는 것입니다.)

| 우선순위 | 기능 | 이유 |
| --- | --- | --- |
| P0 | 아바타 화면(AI 도우미 표시 포함), 녹음한 안내 음성 파일 재생 | "가족이 옆에 있다"는 느낌을 입 움직임 없이도 시연에서 보여줌. 입이 움직이는 모습은 발표용 영상으로 보여줌 |
| P0 | 바로 듣기, 음성 요청 인식, 음성으로 주고받기, 실패 시 선택 버튼 | 대화의 시작과 인식 오류 대비. 음성 인식이 불안정하면 선택 버튼만 눌러 진행하는 방식으로 시연함 |
| P0 | 같은 이름 장소 확인, 택시 타는 곳까지 짧은 문장 길 안내(미리 정한 경로) | 시연 한 줄의 핵심 |
| P0 | 택시 부르기(타는 곳 확인, 출발지·도착지·요금 확인, 카카오 택시 모의 호출, 기다리기 안내) | 메인 시나리오. 시연의 중심 |
| P1 | 카메라로 방향 보기(큰 화살표 겹치기), 지도 보기 목업 | 길을 모를 때 바로 도움이 됨. 안 되면 음성 설명만으로 시연 |
| P1 | 자주 가는 곳 등록 | 가족 쪽 경험을 보여줌. 안 되면 미리 설정한 값으로 시연 |
| P1 | 사진을 실제 모습에 가까운 아바타로 변환 | 가족이 직접 아바타를 만드는 경험. 안 되면 미리 만든 아바타 사용 |
| P1 | AI 말뜻 이해 | 시연에서 AI의 역할을 보여줌. 실패하면 정해진 단어로 대체 |
| P1 | 어르신 말 등록(가족 입력)과 등록한 말 알아듣기. 시간이 더 남으면 어르신이 말해보며 등록 | 사투리나 다르게 부르는 이름에 대비. 안 되면 선택 버튼으로 시연 |
| P2 | 실제 GPS·나침반·지도 API 연동 | 걸으며 시연하기 어렵고 API 키가 필요해 시연 범위 밖 |
| P2 | 자유롭게 대화하는 AI 도우미 | 응답 지연, 요금, 엉뚱한 대답 위험 때문에 이후 단계로 둠 |
| P2 | 실시간 복제 목소리 생성 | 키 보안, 대기 시간, 요금 문제 때문에 이후 단계로 둠 |
| P2 | 녹음(기존 통화 녹음·영상 포함)으로 사투리·발음 학습 | 데이터와 시간이 필요해 시연 범위 밖 |
| P3 | 아바타 꾸미기(편집), 말하는 영상 올리기 | 우선순위 아님. 이후 단계로 미룸 |

**발표에서 반드시 명시할 것 (1):** 시연은 가상 위치로 진행하고(지도 보기를 넣으면 목업 지도 사용), 실제 서비스에서는 폰의 GPS, 나침반, 지도 API와 연동하며 카메라 화살표도 실제 위치로 계산한다는 점을 밝힙니다. 시연의 카메라 화살표는 미리 정한 장면이고, 시연의 택시 호출은 실제 호출이 아닌 모의 호출이고, 화면의 요금은 예시 금액이며, 도착 알림도 실제 알림이 아니라 시간으로 대체한 장면이라는 점도 밝힙니다. 전철, 버스, 시외버스 예약 등도 같은 방식으로 돕는 것이 목표라는 점을 함께 제시합니다.

**발표에서 반드시 명시할 것 (2):** 시연의 대화는 "응/아니", "알겠어", "다시", "잠깐" 같은 미리 정한 짧은 말에 반응하는 방식(AI 말뜻 이해가 되면 다양한 말도 이해)이지만, 실제 서비스의 도우미는 어르신의 말을 이해하고 상황에 맞게 대답하는 대화형 AI라는 점을 밝힙니다.

**발표에서 반드시 명시할 것 (3):** 시연에 쓰는 목소리는 녹음해서 미리 만들어 둔 짧은 문장이지만, 실제 서비스는 목소리를 학습해 어떤 장소와 경로든 실시간으로 생성하는 구조로 만든다는 점을 발표자료에 분명히 적습니다. 동시에 시연은 미리 만든 문장임을 함께 밝힙니다.

**발표용 영상으로만 보여줄 것:** 가족 목소리로 안내하는 모습과 입이 움직이는 아바타는 시연에 넣지 않고 발표용 영상으로만 보여줍니다. 시연은 아바타 화면과 녹음한 음성 파일로 진행합니다. 영상 제작은 일정에 넣고 담당은 팀이 정합니다.

**발표 표현 주의:** 이번 기능은 AI가 사투리를 학습하는 것이 아니라 "가족이 어르신만의 말을 알려주면 곁에가 그 말로 알아듣는다"로 설명합니다. 녹음 학습은 이후 단계라고 밝힙니다.

**설계 원칙:** 도우미는 처음에 AI임을 알립니다. 어르신이 실제 가족과 통화 중이라고 오해하지 않도록 화면에 "AI 도우미" 표시를 항상 둡니다.

## 필요한 기술과 API

MVP에서 키가 필요한 것은 AI 서비스 하나(아바타 이미지 변환, 말뜻 이해)이고, 나머지는 브라우저 기본 기능이나 미리 만든 파일입니다. (API는 앱이 다른 서비스의 기능을 빌려 쓰는 통로, 키는 그 통로를 여는 비밀 열쇠입니다.)

| 기능 | 사용 기술 | 키 필요 | 비고 |
| --- | --- | --- | --- |
| 말하는 아바타 화면과 지도 보기 | HTML, CSS, JavaScript(아바타 화면, 지도 이미지 위에 현재 위치·목적지·경로 점을 그림) | 불필요 | 안내 단계는 앱 안에서 관리, 위치는 가상 |
| 카카오 택시 호출 | 시연은 앱 안의 모의 호출(정해 둔 화면과 시간). 실제 서비스는 카카오모빌리티 제휴·API 연동 | 시연은 불필요, 실제는 확인 필요 | 외부 앱이 바로 쓸 수 있는 공개 택시 호출 API는 찾지 못함. 예상 요금과 결제를 어떻게 연동할지도 확인해야 함 |
| 카메라로 방향 보기 | getUserMedia(브라우저가 카메라를 켜는 기능, https 주소에서만 동작), 영상 위에 화살표 겹치기 | 불필요 | 시연은 미리 정한 장면과 고정된 화살표. 이후 DeviceOrientation(폰 방향 센서), GPS, 지도 API로 계산 |
| 사진을 아바타로 변환 | 이미지 생성 AI API (Gemini 또는 OpenAI) | 필요 | Claude API는 이미지를 만들지 못해 제외. 가족 동의 필요 |
| 말뜻 이해(의도 분류) | 텍스트 AI API (아바타 변환과 같은 서비스) | 필요 | 짧은 문장만 보내 요금 부담이 작음. 실패하면 정해진 단어로 대체 |
| 아바타 입 움직임 | Web Audio (브라우저가 소리 크기를 분석하는 기능) | 불필요 | 입 모양을 소리 크기에 맞춤. 시연에서는 제외하고 발표용 영상에서만 보여줌 |
| 음성 요청 인식 | Web Speech API | 불필요 | 안드로이드 크롬에서 가장 안정적. 앱을 열면 바로 듣기 시작하되, 브라우저가 막을 때를 대비해 큰 말하기 버튼을 둠 |
| 어르신 말 사전 | JavaScript(받아 적은 글자를 등록한 표현과 비교), 브라우저 저장 공간에 글자만 저장 | 불필요 | 음성 인식 모델을 훈련하지는 않음. 설정은 이 폰에만 저장 |
| 가족 문장 녹음(이후, 시연 제외) | MediaRecorder (마이크 소리를 파일로 저장하는 기능) | 불필요 | 녹음이 기본 음성 파일보다 먼저 재생됨 |
| 안내 목소리 파일 | 미리 녹음한 음성 파일 | 앱에는 불필요 | 제작할 때만 사용. 시연은 녹음한 음성, 실제 서비스는 가족 목소리 복제 |
| 키·녹음·아바타·자주 가는 곳 저장 | localStorage, IndexedDB (브라우저 안의 작은 저장 공간) | 불필요 | 본인 폰에만 저장, 폰을 바꾸면 다시 설정 |
| 웹 주소 만들기 | GitHub Pages (GitHub에 올리면 웹 주소로 바꿔주는 무료 기능) | 불필요 | 폰에서 열고 마이크 권한을 쓰려면 https 필요 |
| 실제 위치·지도 연동(이후) | Geolocation API(브라우저가 현재 위치를 알려주는 기능), 지도·길찾기 API(예: 카카오 또는 네이버 지도) | 필요 | MVP에서는 쓰지 않음. 위치는 폰 안에서만 쓰고 저장하지 않음 |

## 위험과 대응

가장 큰 위험은 가족 목소리·얼굴을 악용하는 보이스피싱과 도용, 그리고 어르신이 같은 이름의 다른 장소로 가거나 길에서 위험해지는 일입니다.

| 위험 | 내용 | 대응 |
| --- | --- | --- |
| 보이스피싱 오용 | 가족 목소리 복제 기술이 사기에 쓰일 수 있음 | MVP는 미리 녹음한 고정 문장만 사용하고 실시간 생성은 하지 않음. 이후 실시간 복제는 본인 동의와 앱 안에서만 재생하는 구조로 설계 |
| 실사형 아바타 오용·오해 | 실제 얼굴과 목소리를 합치면 도용에 쓰일 수 있고, 어르신이 진짜 가족과 통화 중이라고 믿을 수 있음 | 본인 동의 필수, 다른 사람 사진은 올릴 수 없음을 안내, 앱 안에서만 재생하고 내려받기와 공유 기능은 두지 않음. 화면에 "AI 도우미"를 항상 표시하고 첫 인사에서 AI임을 알림 |
| 같은 이름의 다른 장소 | 같은 이름의 병원이나 약국이 여러 곳이라 엉뚱한 곳으로 안내될 수 있음 | 현재 위치에서 가장 가까운 곳부터 지역과 함께 "맞아요?"라고 꼭 확인하고, 확인 전에는 안내하지 않음. 가족이 등록한 자주 가는 곳을 우선함 |
| 길 안내 오류 | 안내가 실제 길과 달라 어르신이 헤맬 수 있음 | 시연은 미리 검증한 경로로 한정. 실제 서비스는 지도 API로 경로를 만들고 안전 검증을 거침. 막히면 "다시 알려줘"로 다시 들을 수 있음 |
| 카메라 방향 오류·걸으며 폰 사용 | 화살표가 틀리거나, 폰을 보며 걷다 사고가 날 수 있음 | "멈춰서 비춰 주세요"라고 먼저 말로 안내하고, 화살표는 보조로 두며 음성 안내를 함께 제공. 시연은 미리 검증한 장면으로 한정 |
| 택시 호출·요금 실수 | 의도하지 않은 곳으로 호출되거나 요금을 모르고 탈 수 있음. 곁에가 직접 부르므로 잘못 알아들으면 바로 잘못된 호출이 됨 | 타는 곳을 확인하고, 호출 전에 출발지·도착지·예상 요금을 보여줘 "맞아"라고 답한 경우에만 부름. 대답이 없거나 알아듣지 못하면 부르지 않음. 요금은 예상 금액이라 실제와 다를 수 있음을 알림. 취소 방법 [제안]을 둠 |
| 위치 정보 | 어르신의 위치는 민감한 개인정보 | MVP는 가상 위치만 쓰고, 이후에도 위치는 폰 안에서만 쓰며 저장하거나 외부로 보내지 않음. 가족에게 위치를 공유하려면 어르신의 동의를 먼저 받음 |
| 의존 | 어르신이 혼자 시도하지 않게 될 수 있음 | 안내를 따라 하다 보면 직접 할 수 있게 하는 "혼자 해보기" 모드를 이후 검토 |
| 음성 인식 오류 | 사투리, 발음, 주변 소음 때문에 인식이 틀릴 수 있고, 도우미 목소리를 마이크가 다시 들을 수 있음. 앱을 열자마자 듣는 기능을 브라우저가 막을 수도 있음 | 알아듣는 말을 짧은 단어로 한정, 도우미가 말하는 동안 듣기 중지, 선택 버튼과 큰 말하기 버튼, "다시 알려줘" 버튼을 함께 제공 |
| 말뜻을 잘못 이해 | AI가 목적지를 엉뚱하게 이해할 수 있음 | 장소는 항상 "맞아요?"로 되묻고 어르신이 확인한 뒤에만 진행. 실패하면 정해진 단어로 대체 |
| 등록한 말의 오인식 | 등록한 표현이 다른 뜻과 겹치거나 매번 다르게 받아 적혀 잘못 처리될 수 있음 | 한 표현은 한 가지 뜻에만 등록하고, 장소는 항상 "맞아요?"로 확인. 못 알아들으면 선택 버튼 사용 |
| 어르신 말·목소리 정보 | 말버릇과 목소리는 개인정보이고, 브라우저 음성 인식은 소리를 외부 서버로 보낼 수 있음 | 어르신 본인에게 알리고 동의를 받은 뒤 진행. 곁에는 녹음 파일을 저장하지 않고 글자만 이 폰에 저장하며 삭제할 수 있게 함. 이미 있는 통화 녹음이나 영상을 쓸 때는 어르신과 통화 상대 모두의 동의를 받고 법적 문제를 확인한 뒤 사용함 |
| 목업과 실제 서비스의 차이 | 시연이 실제 길에서도 바로 되는 것처럼 보일 수 있음 | 발표에서 목업과 가상 위치임을 밝히고, 실제 서비스는 지도 API 연동과 안전 검증이 필요하다고 설명 |
| API 키 노출 | 키를 코드에 넣어 GitHub에 올리면 남이 쓰고 요금이 청구될 수 있음 | 키를 코드에 넣지 않고 앱의 입력칸에 직접 넣어 본인 폰에만 저장. 이후 서버에서 키를 숨기는 구조로 전환 |
| 가족 사진 개인정보 | 아바타를 만들려고 올린 얼굴 사진이 외부 AI 서비스로 전송됨 | 사진 주인의 동의를 먼저 받고, 변환이 끝나면 원본 사진은 저장하지 않고 아바타 이미지만 폰에 보관 |

## 이후 단계 로드맵

MVP는 말하는 아바타가 택시 부르기를 돕고 가상 위치를 기준으로 길을 안내하는 방식입니다. 발표에서는 이 점을 밝히고, 실제 서비스로 가는 길을 로드맵으로 보여줍니다.

| 단계 | 내용 |
| --- | --- |
| MVP | 말하는 아바타 + 택시 부르기(타는 곳 확인, 출발지·도착지·요금 확인, 모의 호출, 기다리기 안내) + 짧은 문장 길 안내, 미리 만든 안내 음성 문장(시연은 녹음한 음성), 가족 설정 화면 |
| 다음 | 실제 GPS·나침반 기반 카메라 방향 안내, 지도 API 연동, 전철·버스·시외버스 예약 등으로 확장 |
| 이후 | 자유롭게 대화하는 AI 도우미, 가족 목소리 안내, 아바타 입 움직임(시연에서는 제외하고 발표용 영상으로만 보여줌), 가족 목소리 실시간 생성, 녹음(기존 통화 녹음·영상 포함)으로 어르신의 사투리·발음 학습, 진짜 앱 위에서 짚어주는 도우미(안드로이드 네이티브 앱) |

## 열린 질문

- [ ] 앱 이름을 무엇으로 할까요? (후보: 곁에, 콕콕, 든든)
- [ ] 아바타 이미지 변환과 말뜻 이해에 쓸 AI 서비스는 무엇으로 할까요? (Gemini 또는 OpenAI, Claude는 이미지 생성 불가)
- [ ] 시연 목적지 2~3곳(같은 이름이 두 곳인 장소 포함)과 그 경로 문장은 누가 정하고 만들까요?
- [ ] 실제 서비스에서 카카오 택시를 직접 부르려면 어떤 제휴와 API가 필요할까요?
- [ ] 곁에가 부른 택시의 결제는 어떤 방식으로 할까요? 결제 수단은 누가, 언제 준비할까요?
- [ ] "아니야", 호출 취소, 걸어가기·연결 실패의 "아니" 처리 [제안]을 그대로 쓸까요?
- [ ] "어르신이 말해보며 등록"까지 이번 시연에 넣을까요? 시연에 쓸 어르신 표현 예시는 누가 정할까요?
- [ ] 안내 문장 목록을 확정했나요?
- [ ] 카메라로 방향 보기 시연 장면(어디서 어느 쪽을 비출지)은 누가 준비할까요?
- [ ] 성공 지표의 목표 수치를 얼마로 잡을까요?
- [ ] 사용성 테스트에 참여할 어르신을 어떻게 구할까요?

## 나중에 추가할 기능

MVP는 택시 부르기와 길찾기입니다. 아래는 같은 방식으로 도울 다른 서비스들이며, 시연 일정 안에는 넣지 않습니다.

| 서비스 | 도우미가 하는 일 |
| --- | --- |
| 실제 걷는 길 안내 | 폰의 GPS를 따라 "앞으로 쭉 가세요.", "좌회전하세요."를 걸음마다 실시간으로 안내 |
| 실제 택시 호출 연동 | 곁에가 실제로 택시를 부르고 예상 요금과 도착 알림을 알려줌 (제휴·API 확인 필요) |
| 전철 설명 | 노선, 환승, 승강장 방향, 출구 번호를 말로 설명 |
| 버스 | 어느 번호를 타는지, 어디서 타고 내리는지 안내 |
| 시외버스 예약 | 출발지, 도착지, 시간, 좌석을 고르는 과정을 안내하고 결제 금액을 먼저 확인 |
| 배달앱 주문 (배민 같은 앱) | 가게, 메뉴, 장바구니, 주소, 결제를 단계별로 안내하고 결제 전에 금액 확인 |
| 영화관·병원 예약, 송금 | 같은 방식으로 단계별 안내 |
| 키오스크 안내 | 폰 카메라로 키오스크 화면을 비추면 눌러야 할 버튼을 알려줌 (아래 부록) |

## 부록: 카메라로 키오스크 안내

폰 밖의 키오스크(카페, 식당, 병원 접수처)를 안내하는 확장입니다. "카메라로 방향 보기"와 같은 카메라 기능을 쓰므로 길찾기 다음 순서로 검토합니다.

1. 어르신이 곁에를 열고 "카페 주문"이라고 말합니다.
2. 폰 카메라로 키오스크 화면을 비추고 "알려줘"를 누르면 사진 한 장을 AI에 보냅니다.
3. AI가 눌러야 할 버튼과 위치를 찾고, 준비된 짧은 안내 문장 중 지금 단계를 고릅니다.
4. 영상 위에 큰 동그라미가 뜨고 가족 목소리 안내가 나옵니다.
5. 화면이 바뀔 때마다 2~4를 반복하고, 결제 화면에서는 금액 확인 질문을 먼저 합니다.

필요한 것은 이미지 인식 AI API(Gemini 또는 OpenAI, 키 필요), 카메라, 시연용 키오스크 화면입니다.

| 한계 | 대응 |
| --- | --- |
| 한 손에 폰, 한 손으로 키오스크를 눌러야 함 | 목걸이형 폰 홀더나 거치대, 말로 위치를 설명하는 음성 안내 |
| AI 응답에 2~5초가 걸림 | "생각하는 중" 표시를 넣고 연속 촬영 없이 한 장씩 보냄 |
| 폰을 움직이면 동그라미가 어긋나고 AI가 찍은 위치도 조금 틀릴 수 있음 | 폰을 가만히 들게 안내, 동그라미를 크게 그림, "다시 알려줘" 버튼 |
| 낯선 키오스크에서 틀린 버튼을 가리킬 수 있음 | 시연은 미리 테스트한 화면으로 한정, 결제 단계는 금액 확인 후 진행 |

이후에는 화면이 바뀔 때만 사진을 보내는 연속 인식, 빠른 모델로 지연 줄이기, 진짜 앱 위에 떠다니는 도우미(안드로이드 네이티브 앱)로 확장합니다.
