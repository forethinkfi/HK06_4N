# 곁에 PRD 초안

2026-11-25

곁에는 어르신이 배달앱 같은 온라인 서비스를 쓸 때, 화면 위에 가족 아바타가 떠서 가족의 목소리로 눌러야 할 버튼을 짚어주는 서비스입니다. MVP는 배달앱을 본뜬 목업(실제 작동하지 않는 가짜 화면) 위에서 시연합니다.

## 배경과 문제

어르신이 혼자 배달앱 같은 온라인 서비스를 쓰려면, 옆에서 알려주는 사람이 거의 항상 필요합니다.

- 배달앱, 예약앱, 은행앱처럼 전화나 방문 대신 앱으로 주문하고 결제하는 서비스가 늘면서, 어르신이 직접 앱을 써야 하는 상황이 많아졌습니다.
- 어르신은 화면의 용어(장바구니, 배달 팁, 쿠폰 등)와 버튼 위치를 몰라서 막히고, 잘못 누르면 결제될까 봐 두려워 포기하기도 합니다.
- 가족은 전화로 "그거 말고 저거 눌러"를 반복해야 하고, 직접 알려주러 갈 수 없는 경우가 많습니다.
- 기존 도움말은 글자와 용어 중심이라 어르신께 낯섭니다. 어르신이 따르는 건 "아는 사람의 목소리"입니다.

핵심 통찰은 어르신께 필요한 것이 기능 설명이 아니라 **믿는 사람이 옆에 있다는 안심감**이라는 점입니다.

## 목표와 성공 지표

MVP(핵심 기능 하나만 실제로 동작하게 만든 최소 제품)의 목표는 "어르신이 가족의 목소리 안내만으로 배달 주문을 끝낸다"는 가설을 검증하는 것입니다.

| 지표 | 측정 방법 | 목표 |
| --- | --- | --- |
| 주문 완료율 | 테스트 참가자 중 도움 없이 주문을 끝낸 비율 | 정해야 함 |
| 완료까지 걸린 시간 | 시작 버튼부터 주문 완료까지 초 단위 측정 | 정해야 함 |
| 막히는 횟수 | "다시 알려줘" 요청 횟수 | 정해야 함 |
| 안심감 | 사용 후 "혼자 해냈다는 느낌이 들었는지" 5점 척도 질문 | 정해야 함 |

팀플 단계에서는 어르신 3~5분을 대상으로 짧은 사용성 테스트(실제 사용자에게 써보게 하고 관찰하는 테스트)를 하고 위 표의 목표수치를 팀이 정합니다.

## 사용자

사용자는 두 사람입니다. 어르신이 쓰고, 가족이 목소리와 아바타를 준비합니다. (페르소나는 실제 인터뷰 전까지 가정으로 쓴 대표 사용자 상입니다.)

| 구분 | 어르신 (사용자) | 가족 (준비자) |
| --- | --- | --- |
| 대표 인물 | 스마트폰은 쓰지만 배달앱과 키오스크에는 자신이 없는 할머니 | 멀리 사는 자녀나 손주, 수시로 전화를 받는 사람 |
| 하려는 일 | 배달앱으로 치킨이나 점심 주문하기 | 어르신이 무엇을 누를지 일일이 설명하지 않아도 되게 하기 |
| 불편 | 용어가 낯선 데다 뒤 사람이 신경 쓰임 | 전화로 말로만 설명하기 어렵고 자주 반복됨 |
| 원하는 것 | 혼자 해내고 싶고, 믿는 목소리가 옆에 있기를 바라기 | 어르신이 혼자 중단 없이 쓰고 이를 확인하기 |

이 표는 가정이므로 어르신 인터뷰 후 고쳐야 합니다.

## 핵심 시나리오

할머니가 배달앱 목업에서 치킨을 주문하는 흐름입니다. (사용자 흐름은 사용자가 목표를 이루기까지 거치는 단계를 순서대로 적은 것입니다.)

1. 할머니가 배달앱 화면을 엽니다. 화면 한쪽에 가족 아바타가 작게 떠 있고, 필요 없으면 치울 수 있습니다.
2. 할머니가 아바타를 누르면 "할머니, 뭐 도와드릴까요?"라고 가족 목소리로 묻습니다.
3. 할머니가 "치킨 주문"이라고 말합니다. (음성 인식으로 원하는 일을 파악합니다.)
4. 화면에서 눌러야 할 곳(가게 고르기, 메뉴 담기, 장바구니, 주소 확인, 결제)에 큰 동그라미나 버튼 영역 표시가 뜨고, 준비된 12개 문장 중 지금 단계에 맞는 가족 목소리 안내가 나옵니다. 안내는 눌러야 할 곳을 말로도 설명합니다. ("오른쪽 아래 노란 버튼을 눌러보세요")
5. 안내가 끝나면 도우미가 듣는 상태가 되고, 할머니가 말로 답합니다. "눌렀어", "다시", "잘 모르겠어"처럼 짧은 말을 알아듣고 다음 단계로 넘어가거나 다시 안내합니다. 직접 눌러도 다음 단계로 넘어갑니다.
6. 결제 화면에서는 가족 목소리가 "금액이 맞는지 확인하셨어요?"라고 먼저 묻고, 할머니가 "응, 맞아"라고 말로 답하면 결제 수단 선택과 결제까지 안내합니다. "아니"라고 하면 장바구니로 돌아갑니다.
7. 주문이 끝나면 가족이 미리 녹음한 "정말 잘하셨어요!"라는 칭찬이 나옵니다.

막히는 경우에는 "다시 알려줘" 버튼과 선택 버튼(치킨 주문, 병원 예약 등)을 함께 두어 음성 인식 오류에 대비합니다. 목업은 지금 화면이 어느 단계인지 앱이 이미 알고 있어서, MVP에는 AI 화면 인식이 필요하지 않습니다.

**가족 시나리오:** 가족이 곁에를 준비하는 흐름입니다.

1. 가족이 곁에 앱의 가족 설정 화면을 엽니다.
2. 본인 사진을 올립니다. (사진 주인의 동의가 전제입니다.)
3. 생성형 이미지 AI가 사진을 일러스트풍 아바타로 바꿔주고, 마음에 들 때까지 다시 만들 수 있습니다.
4. 아바타의 입 위치를 손가락으로 한 번 맞춥니다.
5. 안내 문장을 하나씩 읽으며 녹음합니다. 녹음하지 않은 문장은 복제 목소리 파일이 대신 재생됩니다.
6. 미리 듣기로 아바타가 말하는 모습과 목소리를 확인합니다.
7. 설정이 끝나면 어르신께 폰을 건네거나 곁에를 설치해 드립니다. (MVP는 설정이 한 폰에만 저장되므로 같은 폰으로 시연합니다.)

## 기능 범위

MVP는 "배달앱 목업에서 치킨 주문 한 가지"만 끝까지 되게 만듭니다. 도우미는 목업 화면 안에서 떠다니며, 진짜 앱 위에 띄우는 기능은 다음 단계로 미룹니다. 카메라로 키오스크를 안내하는 외부 버전은 맨 마지막 "나중에 추가할 기능"에 따로 적었습니다.

### 어르신이 쓰는 기능

| 기능 | 범위 | 설명 |
| --- | --- | --- |
| 화면 위에 떠 있는 도우미 | MVP | 배달앱 목업 화면 위에 아바타가 떠 있고, 누르면 도우미가 시작되며 필요 없으면 치울 수 있음 |
| 음성 요청 인식 | MVP | 브라우저 기본 음성 인식(Web Speech API)으로 "치킨 주문"을 알아듣기 |
| 음성으로 주고받기 | MVP | 도우미가 말로 안내하고 할머니도 말로 답함. 알아듣는 말은 "눌렀어", "다시", "응/아니"처럼 미리 정한 짧은 말로 한정. 도우미가 말하는 동안에는 듣지 않고 끝난 뒤에 들음. 눌러서 답하는 버튼도 함께 둠 |
| 단계 안내 | MVP | 목업이 현재 단계를 알고 있어서, 단계에 맞는 12개 문장 중 하나를 고름 (AI가 새 문장을 짓지 않음) |
| 화면 위 동그라미 표시 | MVP | 눌러야 할 버튼에 큰 동그라미를 그리거나 버튼 영역 전체를 강조해서 보여줌 |
| 가족 목소리 인사·칭찬 | MVP | 12개 문장(인사, 안내, 칭찬, 격려)을 가족 목소리 파일로 재생 |
| 단계별 안내 목소리 | MVP | 일레븐랩스로 본인 동의를 받은 팀원 목소리를 복제해 12개 안내 문장을 미리 만들어 두고, 단계에 맞는 파일을 재생 |
| 아바타 표시와 입 움직임 | MVP | 가족 아바타를 화면에 표시하고, 목소리가 재생되는 동안 소리 크기에 맞춰 입 모양이 바뀌어 말하는 것처럼 보이게 함 |
| 결제 금액 확인 질문 | MVP | 결제 화면에서 가족 목소리가 "금액이 맞는지 확인하셨어요?"라고 먼저 묻고, 어르신이 확인한 뒤에만 결제 수단 선택과 결제를 안내 |
| 실패 시 선택 버튼 | MVP | 음성 인식이 틀리거나 막힐 때 눌러서 고를 수 있는 버튼 ("다시 알려줘" 포함) |
| 자유롭게 대화하는 AI 도우미 | 이후 | 실제 서비스의 최종 형태. 미리 정한 말이 아니라 어르신이 하는 말을 이해하고, 상황에 맞게 대답하고 되묻는 대화형 AI. 발표에서 반드시 명시함. 시연은 정해진 짧은 말과 12문장으로 대체 |
| 실시간 복제 목소리 생성(AI가 만든 새 문장까지 가족 목소리로) | 이후 | 실제 서비스의 최종 형태이며 발표에서 반드시 명시함. 시연은 12문장 파일로 대체하고, 보이스피싱 위험을 설계한 뒤 도입 |
| 혼자 해보기 모드 | 이후 | 안내를 따라 하다 보면 어르신이 직접 할 수 있게 하는 모드 |
| 진짜 앱 위에 띄우는 오버레이 | 이후 | 실제 배달앱 위에 떠다니는 도우미. 안드로이드 네이티브 앱이 필요해 MVP에서는 목업 안에서만 구현 |
| 병원 예약·송금·키오스크 안내 | 이후 | 배달 시나리오가 검증된 뒤 확장 |
| 길찾기 안내 | 이후 (확장) | 어르신이 목적지를 말하면 길찾기 과정을 가족 목소리와 아바타가 단계별로 안내. 화면 위에 떠다니는 도우미와 함께 확장 |

### 가족이 쓰는 기능

| 기능 | 범위 | 설명 |
| --- | --- | --- |
| 가족 전용 설정 화면(녹음·아바타 등록) | MVP | 어르신께 드리기 전에 가족이 준비하는 화면 |
| 사진 올리기와 동의 확인 | MVP | 사진 주인의 동의를 먼저 확인한 뒤 사진을 올림. 변환 후 원본 사진은 저장하지 않음 |
| 사진을 아바타로 변환 | MVP | 올린 사진을 생성형 이미지 AI가 일러스트풍 아바타로 바꾸고, 마음에 들 때까지 다시 만들 수 있음 |
| 아바타 디자인 방향 | MVP | 그림체는 일러스트풍(세부 그림체는 팀에서 정함). 닮는 정도는 올린 사진을 기반으로 가족임을 알아볼 수 있을 만큼. 동의 방식은 사진 주인의 동의를 먼저 받고, 변환 후 원본 사진은 저장하지 않음 |
| 입 위치 맞추기 | MVP | 입 움직임이 자연스럽도록 아바타의 입 위치를 처음에 한 번 맞춤 |
| 안내 문장 직접 녹음 | MVP | 가족이 문장을 직접 녹음하면 그 녹음이 복제 목소리보다 먼저 재생됨. 복제 목소리 파일은 기본값 |
| 미리 듣기 | MVP | 설정이 끝나면 아바타가 말하는 모습과 목소리를 확인 |
| 아바타 꾸미기(편집) | 이후 (우선순위 아님) | 사진 기반으로 만든 아바타를 머리 모양, 색, 소품 등으로 직접 고쳐 꾸미는 기능. 사진 기반 아바타가 먼저이며, 이 기능은 우선순위에 넣지 않고 이후로 미룸 |
| 어르신 사용 확인 알림 | 이후 | 어르신이 곁에를 사용했는지 가족이 확인할 수 있게 하는 알림이나 사용 기록 |

**사용자 기능이 아니라 팀이 준비하는 것:** 일레븐랩스로 복제 목소리 12문장 파일 만들기, 문장 목록 확정과 팀원 목소리 동의 받기, AI 키 입력칸(본인 폰에만 저장)을 만듭니다.

## MVP 우선순위

하루 안에 만들어야 하므로 어르신 흐름(배달앱 목업)만으로 시연이 성립하게 하고, 가족 설정은 그다음에 얹습니다. (P0은 꼭 되어야 하는 것, P1은 되면 좋은 것, P2는 시간이 남으면 하는 것, P3은 우선순위에 넣지 않고 이후로 미루는 것입니다.)

| 우선순위 | 기능 | 이유 |
| --- | --- | --- |
| P0 | 배달앱 목업 화면(가게, 메뉴, 장바구니, 주소, 결제), 화면 위에 떠 있는 도우미 | 시연의 무대 |
| P0 | 음성 요청 인식, 음성으로 주고받기, 12개 문장 중 단계 고르기 | 어르신 흐름의 시작과 핵심 |
| P0 | 크게 그린 동그라미 또는 버튼 영역 표시 | 눌러야 할 곳을 알아보기 쉽게 함 |
| P0 | 복제 목소리 파일 재생, 미리 만든 아바타, 입 움직임 | "가족이 옆에 있다"는 느낌을 시연에서 보여줌 |
| P0 | 결제 금액 확인 질문, 실패 시 선택 버튼 | 잘못된 안내와 인식 오류에 대비 |
| P1 | 가족 녹음 화면 | 가족 쪽 경험을 보여줌 |
| P1 | 사진을 아바타로 변환, 입 위치 맞추기 | 가족이 직접 아바타를 만드는 경험 |
| P2 | 자유롭게 대화하는 AI 도우미 | 시연 범위 밖. 응답 지연, 요금, 엉뚱한 대답 위험 때문에 이후 단계로 둠 |
| P2 | 실시간 복제 목소리 생성(AI가 만든 새 문장까지) | 시연 범위 밖. 키 보안, 대기 시간, 요금 문제 때문에 이후 단계로 둠 |
| P3 | 아바타 꾸미기(편집) | 우선순위 아님. 시연 범위와 개발 일정에서 제외하고 이후 단계로 미룸 |

**발표에서 반드시 명시할 것 (1):** 시연은 배달앱 목업이라 앱이 화면 단계를 이미 알고 있으며, 실제 서비스에서는 AI가 화면을 읽어 안내하고 진짜 앱 위에 떠다니는 도우미로 확장한다는 점을 함께 밝힙니다.

**발표에서 반드시 명시할 것 (2):** 시연의 대화는 "눌렀어", "다시", "응/아니" 같은 미리 정한 짧은 말을 알아듣는 방식이지만, 실제 서비스의 도우미는 어르신의 말을 이해하고 상황에 맞게 대답하는 대화형 AI라는 점을 밝힙니다.

**발표에서 반드시 명시할 것 (3):** 시연에 쓰는 가족 목소리는 미리 만들어 둔 12문장이지만, 실제 서비스는 목소리를 학습해 어떤 대답이든 실시간으로 생성하는 구조로 만든다는 점을 발표자료에 분명히 적습니다. 동시에 시연 화면이 실시간 생성처럼 보이지 않도록, 시연은 미리 만든 문장임을 함께 밝힙니다.

## 필요한 기술과 API

MVP에서 키가 필요한 것은 아바타 이미지 변환 하나이고, 나머지는 브라우저 기본 기능이나 미리 만든 파일입니다. (API는 앱이 다른 서비스의 기능을 빌려 쓰는 통로, 키는 그 통로를 여는 비밀 열쇠입니다.)

| 기능 | 사용 기술 | 키 필요 | 비고 |
| --- | --- | --- | --- |
| 배달앱 목업 화면과 떠 있는 도우미 | HTML, CSS, JavaScript | 불필요 | 단계 정보는 앱 안에서 관리 |
| 사진을 아바타로 변환 | 이미지 생성 AI API (Gemini 또는 OpenAI) | 필요 | Claude API는 이미지를 만들지 못해 제외. 가족 동의 필요 |
| 아바타 입 움직임 | Web Audio (브라우저가 소리 크기를 분석하는 기능) | 불필요 | 입 모양을 소리 크기에 맞춤 |
| 음성 요청 인식 | Web Speech API | 불필요 | 안드로이드 크롬에서 가장 안정적 |
| 가족 문장 녹음 | MediaRecorder (마이크 소리를 파일로 저장하는 기능) | 불필요 | 녹음이 복제 목소리보다 먼저 재생됨 |
| 안내 목소리 12문장 | 일레븐랩스로 미리 만든 음성 파일 | 앱에는 불필요 | 제작할 때만 사용 |
| 키·녹음·아바타 저장 | localStorage, IndexedDB (브라우저 안의 작은 저장 공간) | 불필요 | 본인 폰에만 저장, 폰을 바꾸면 다시 설정 |
| 웹 주소 만들기 | GitHub Pages (GitHub에 올리면 웹 주소로 바꿔주는 무료 기능) | 불필요 | 폰에서 열고 마이크 권한을 쓰려면 https 필요 |

## 위험과 대응

가장 큰 위험은 가족 목소리를 악용하는 보이스피싱과, 어르신이 도우미 없이는 아무것도 못 하게 되는 의존입니다.

| 위험 | 내용 | 대응 |
| --- | --- | --- |
| 보이스피싱 오용 | 가족 목소리 복제 기술이 사기에 쓰일 수 있음 | MVP는 본인 동의를 받은 팀원 목소리로 미리 만든 고정 12문장만 사용하고 실시간 생성은 하지 않음. 이후 실시간 복제는 본인 동의와 앱 안에서만 재생하는 구조로 설계 |
| 의존 | 어르신이 혼자 시도하지 않게 될 수 있음 | 안내를 따라 하다 보면 직접 할 수 있게 하는 "혼자 해보기" 모드를 이후 검토 |
| 음성 인식 오류 | 사투리, 발음, 주변 소음 때문에 인식이 틀릴 수 있고, 도우미 목소리를 마이크가 다시 들을 수 있음 | 알아듣는 말을 짧은 단어로 한정, 도우미가 말하는 동안 듣기 중지, 선택 버튼(치킨 주문, 병원 예약 등)과 "다시 알려줘" 버튼을 함께 제공. 결제 확인은 말로 답해도 버튼으로 한 번 더 확인 |
| 목업과 실제 앱의 차이 | 시연이 실제 배달앱에서도 바로 되는 것처럼 보일 수 있음 | 발표에서 목업임을 밝히고, 실제 서비스는 AI 화면 인식과 오버레이(네이티브 앱)가 필요하다고 설명 |
| API 키 노출 | 키를 코드에 넣어 GitHub에 올리면 남이 쓰고 요금이 청구될 수 있음 | 키를 코드에 넣지 않고 앱의 입력칸에 직접 넣어 본인 폰에만 저장. 이후 서버에서 키를 숨기는 구조로 전환 |
| 가족 사진 개인정보 | 아바타를 만들려고 올린 얼굴 사진이 외부 AI 서비스로 전송됨 | 사진 주인의 동의를 먼저 받고, 변환이 끝나면 원본 사진은 저장하지 않고 아바타 이미지만 폰에 보관 |
| 결제 오안내 | 틀린 버튼을 가리켜 잘못 결제될 수 있음 | 결제 화면에서는 가족 목소리가 "금액이 맞는지 확인하셨어요?"라고 먼저 묻고, 어르신이 확인한 뒤에만 결제 수단 선택과 결제를 안내 |

## 이후 단계 로드맵

MVP는 배달앱 목업 안에서 도우미가 단계별로 안내하는 방식입니다. 목업은 화면 단계를 앱이 알고 있으므로 AI 화면 인식과 카메라는 쓰지 않습니다. (카메라 방식은 맨 마지막에 정리했습니다.) 발표에서는 이 점을 밝히고, 실제 서비스로 가는 길을 로드맵으로 보여줍니다.

| 단계 | 내용 |
| --- | --- |
| MVP | 배달앱 목업 + 떠 있는 도우미, 미리 만든 12문장 가족 목소리, 가족 설정 화면 |
| 다음 | 외부 버전(카메라로 키오스크 안내, 맨 마지막 섹션 참고) |
| 이후 | 자유롭게 대화하는 AI 도우미, 가족 목소리 실시간 생성, 진짜 앱 위에 떠다니는 도우미(안드로이드 네이티브 앱), 길찾기 등 확장 |

## 열린 질문

- [ ] 앱 이름을 무엇으로 할까요? (후보: 곁에, 콕콕, 든든)
- [ ] 아바타 이미지 변환에 쓸 AI 서비스는 무엇으로 할까요? (Gemini 또는 OpenAI, Claude는 이미지 생성 불가)
- [ ] 배달앱 목업은 어느 화면 흐름(가게, 메뉴, 장바구니, 주소, 결제)으로 만들고 누가 만들까요?
- [ ] 성공 지표의 목표 수치를 얼마로 잡을까요?
- [ ] 12개 안내 문장을 확정하고, 목소리를 복제할 팀원의 동의를 받았나요?
- [ ] 사용성 테스트에 참여할 어르신을 어떻게 구할까요?

## 나중에 추가할 기능: 외부 버전 (키오스크 안내, 길찾기 안내)

MVP는 폰 안의 배달앱 목업이고, 외부 버전은 폰 밖의 키오스크(카페, 식당, 병원 접수처)를 안내하는 확장입니다. 시연 일정 안에는 넣지 않고, 목업 시연이 끝난 뒤 시간이 남으면 시도합니다.

**어떻게 동작하나요?**
1. 어르신이 곁에를 열고 "카페 주문"이라고 말합니다.
2. 폰 카메라로 키오스크 화면을 비추고(getUserMedia, 브라우저가 카메라를 켜는 기능, https 주소에서만 동작) "알려줘"를 누르면 사진 한 장을 AI에 보냅니다.
3. AI가 눌러야 할 버튼과 위치를 찾고, 준비된 12개 문장 중 지금 단계를 고릅니다.
4. 카메라 영상 위에 큰 동그라미나 버튼 영역 표시가 뜨고, 가족 목소리 안내가 나옵니다.
5. 화면이 바뀔 때마다 2~4를 반복하고, 결제 화면에서는 금액 확인 질문을 먼저 합니다.

**필요한 것:** 이미지 인식 AI API(Gemini 또는 OpenAI, 키 필요), 카메라, 시연용 키오스크 화면.

**알려진 한계와 대응**

| 한계 | 내용 | 대응 |
| --- | --- | --- |
| 손이 모자람 | 한 손에 폰, 한 손으로 키오스크를 눌러야 함 | 목걸이형 폰 홀더나 거치대, 말로 위치를 설명하는 음성 안내 |
| 응답 지연 | AI 응답에 2~5초가 걸림 | "생각하는 중" 표시를 넣고, 요금과 지연 때문에 연속 촬영 없이 한 장씩 보냄 |
| 동그라미가 어긋남 | 폰을 움직이면 고정된 동그라미가 어긋나고, AI가 찍은 위치도 조금 틀릴 수 있음 | 폰을 가만히 들게 안내, 동그라미를 크게 그리거나 버튼 영역 전체를 칠함, "다시 알려줘" 버튼 |
| 처음 보는 화면 | 낯선 키오스크에서 틀린 버튼을 가리킬 수 있음 | 시연은 미리 테스트한 화면으로 한정, 결제 단계는 금액 확인 후 진행 |

**이후 발전:** 화면이 바뀔 때만 사진을 보내는 연속 인식, 빠른 모델로 지연 줄이기, 폰이 움직여도 동그라미가 따라오게 하기, 그리고 진짜 앱 위에 떠다니는 도우미(안드로이드 네이티브 앱)로 확장합니다.

**길찾기 안내(지도):** 키오스크뿐 아니라 지도 기능도 넣을 예정입니다. 어르신이 "나 병원 갈 거야"처럼 가고 싶은 곳을 말하면, 도우미가 "OOO 여기 맞아요?"라고 먼저 되물어 목적지를 확인합니다. 맞다고 하면 폰의 GPS(위치를 알려주는 기능)를 따라 가족 목소리로 "여기서 오른쪽으로 가세요", "여기서 신호를 건너세요"처럼 걸어가는 길을 음성으로 안내합니다. 시연 일정에는 넣지 않고, 이후 단계에서 추가합니다.
