# 곁에 PRD 초안

2026-11-25

곁에는 어르신이 앱을 켜고 말하면, 영상통화처럼 보이는 가족 아바타가 가족의 목소리로(시연은 손주 목소리 녹음) 짧은 문장으로 한 단계씩 도와주는 AI 도우미입니다. **택시 부르기가 메인**이고, 길찾기도 함께 들어갑니다. 어르신은 **집 안에서** 택시를 부른 뒤 밖으로 나갑니다. 목적지는 가족이 등록한 대학병원·동네 내과에서 고르거나 다른 병원을 말합니다. 배차 후에는 차량 정보와 **지도(필수)**로 택시 위치를 보여줍니다. 가까우면 걸어가는 길을 안내하고, 길을 모를 때 카메라를 비추면 방향을 큰 화살표로 알려줍니다. 전철, 버스, 시외버스 예약 등은 이후 확장 계획입니다. 이번 MVP는 **실제 연동이 없는 예시안**입니다.

## 배경과 문제

어르신이 혼자 이동하려면, 길을 알려주는 사람이 거의 항상 필요합니다.

- 지도앱, 택시앱, 버스·기차 예약앱처럼 이동에 앱이 필요한 일이 늘었습니다.
- 어르신은 길은 알아도 택시 앱의 메뉴, 위치 설정, 호출 방법이 낯설어 막히고, 같은 이름의 다른 장소로 잘못 가기도 합니다. 길을 잃을까 봐 외출 자체를 망설이기도 합니다.
- 가족은 전화로 "거기서 왼쪽으로 가"를 반복해야 하고, 직접 데려다줄 수 없는 경우가 많습니다.
- 기존 앱은 글자와 화면 중심이라 어르신께 낯섭니다. 어르신이 따르는 건 "아는 사람의 목소리"입니다.
- 요즘 택시는 앱으로 호출하거나 미리 예약하는 방식이 중심이라, 길에서 손을 들어도 빈 택시가 잘 보이지 않고 잡기 어렵습니다. 앱을 못 쓰면 택시를 타기 어려워졌습니다.

핵심 통찰은 어르신께 필요한 것이 기능 설명이 아니라 **믿는 사람이 옆에서 하나하나 말해 준다는 안심감**이라는 점입니다.

**아바타를 쓰는 이유:** 어르신은 새로운 앱에 거부감이 커서, 처음부터 낯선 화면을 쓰게 하면 시작조차 어렵습니다. 아는 가족의 얼굴과 목소리가 말해 주면 새 앱이라는 느낌이 줄어들어, 영상통화하듯 편하게 시작할 수 있습니다.

## 목표와 성공 지표

MVP(핵심 기능 하나만 실제로 동작하게 만든 최소 제품)의 목표는 "어르신이 말과 간단한 답만으로 택시를 부르고, 타고, 도착까지 따라갈 수 있다"는 가설을 검증하는 것입니다. 이번 해커톤에서는 예시안 시연으로 보여주고, 검증은 이후 사용성 테스트에서 합니다.

**시연 한 줄:** 평일 오전 10시, 불광동 자택에서 김정성 할아버지가 "병원 가게 택시 잡아줘"라고 말하면, 등록된 대학병원을 고르고 확인한 뒤, 집 안에서 타는 곳(○○아파트 101동 앞)과 결제 방법, 나갈 준비, 예상 요금을 확인해 택시를 부릅니다(모의 호출). 차 사진·차종·번호와 택시 위치 지도를 보며 챙겨서 나가 택시를 확인해 타고, 도착 전 내릴 준비 안내와 도착 후 칭찬까지 듣습니다.

**택시에서 곁에가 돕는 부분:** 말 한마디와 ⭕ 네 / ❌ 아니요 답으로 택시를 부를 수 있게 하고, 어디서 타는지, 어떤 차인지, 어디까지 왔는지, 언제 내릴 준비를 하는지를 아바타가 하나씩 알려줍니다.

| 지표 | 측정 방법 | 목표 |
| --- | --- | --- |
| 택시 호출 성공률 | 테스트 참가자 중 도움 없이 올바른 목적지와 타는 곳을 확인하고 택시 호출까지 마친 비율 | 정해야 함 |
| 호출까지 걸린 시간 | 곁에를 연 때부터 택시 호출 완료까지 초 단위 측정 | 정해야 함 |
| 막히는 횟수 | "다시 알려줘" 요청 횟수와 장소를 잘못 알아들은 횟수 | 정해야 함 |
| 안심감 | 사용 후 "혼자 해냈다는 느낌이 들었는지" 5점 척도 질문 | 정해야 함 |

사용성 테스트(실제 사용자에게 써보게 하고 관찰하는 테스트)는 이번 해커톤에서는 하지 않고 이후에 합니다. 위 표의 목표수치는 그 테스트 때 정합니다.

## 사용자

사용자는 두 사람입니다. 어르신이 쓰고, 가족이 목소리, 아바타, 집 주소, 병원을 준비합니다. (페르소나는 실제 인터뷰 전까지 가정으로 쓴 대표 사용자 상입니다. 김정성 씨는 합성 데이터(nvidia/Nemotron-Personas-Korea, CC BY 4.0) 기반이며 실존 인물이 아닙니다. 자세한 유저저니는 docs/USER\_JOURNEY.md를 참고합니다.)

| 구분 | 어르신 (사용자) | 가족 (준비자) |
| --- | --- | --- |
| 대표 인물 | 김정성 씨(79세 남성, 서울 은평구 불광동, 배우자와 거주, 오랜 승용차·승합차 운전 경력). 길은 잘 알지만 택시 앱의 메뉴, 위치 설정, 호출 방법이 낯섦. 스마트폰 퍼즐 게임은 익숙하게 하고, 평소 손주에게 스마트폰 사용법을 배움 | 멀리 사는 자녀나 손주, 수시로 전화를 받는 사람 |

| 불편 | 택시 앱의 메뉴, 위치 설정, 호출 방법이 낯설고, 같은 이름의 장소가 헷갈림 | 전화로 말로만 설명하기 어렵고 자주 반복됨 |

이 표는 가정이므로 어르신 인터뷰 후 고쳐야 합니다.

## 핵심 시나리오

**상황:** 평일 오전 10시, 은평구 불광동 자택. 김정성 할아버지는 정기 검진을 받으러 대학병원에 가야 하고, 오늘은 운전하지 않고 택시로 가기로 했습니다. 집 안에서 며칠 전 손주가 설치해 준 곁에를 엽니다. 가족 설정과 동의는 이미 끝났다고 가정합니다. 목표는 손주에게 전화하지 않고 혼자 택시로 병원에 가는 것입니다. 이 상황과 병원 이름(행복대학병원, 튼튼내과), 아파트 이름, 요금, 시간은 모두 가상 예시이며, 김정성 씨는 합성 데이터(nvidia/Nemotron-Personas-Korea, CC BY 4.0) 기반 페르소나입니다. 자세한 유저저니는 GitHub docs/USER\_JOURNEY.md에 있습니다.

택시 부르기가 메인이고, 길찾기는 가까운 거리의 도보 안내와 타는 곳까지 가는 길에 쓰입니다. 안내 문장은 짧게 쓰고 한 번에 하나만 묻습니다. (사용자 흐름은 사용자가 목표를 이루기까지 거치는 단계를 순서대로 적은 것입니다.)

**답하는 방식:** 네·아니요로 답할 수 있는 질문은 아래에 (⭕❌)로 표시합니다. 화면에는 [⭕ 네] [❌ 아니요] 큰 버튼을 글자와 함께 보여주고, "응", "맞아", "그래"는 네로, "아니", "아니야"는 아니요로 알아듣습니다. 병원 이름이나 장소를 묻는 질문, 여러 항목 중 고르는 질문은 그대로 둡니다. 대답이 없거나 알아듣지 못하면 다음으로 넘어가지 않습니다.

1. **앱 실행:** 영상통화처럼 보이는 가족 아바타, "AI 도우미" 표시, 인사말, 듣기 표시, 큰 말하기 버튼이 보이고 바로 듣습니다. 첫 이용 때 "저는 손주의 모습과 목소리로 만든 AI 도우미예요."라고 알린 뒤 "할아버지, 오늘 어디 가세요?"라고 묻습니다.
2. **병원 선택:** "대학병원과 동네 내과 중 어디로 가세요?"라고 묻고, 병원 종류와 이름이 적힌 큰 버튼과 [다른 병원] 버튼을 보여줍니다. 고르면 (⭕❌) "행복대학병원 맞아요?"라고 확인합니다.
   - ❌ 아니요 또는 [다른 병원]: (⭕❌) "혹시 다른 병원 가시는 걸까요?" ⭕면 "어느 병원에 가세요?"라고 묻고 (⭕❌) "○○동 ○○병원 맞아요?"로 확인합니다. 같은 이름이 여러 곳이면 가까운 곳부터 확인합니다. ❌면 등록한 병원을 다시 보여줍니다.
3. **이동 방법:** "택시 잡아줘"라고 했으면 4번으로 갑니다. "어떻게 가?"라고 했는데 멀면 (⭕❌) "걸어가기엔 조금 먼데 택시 타고 가실래요?"라고 묻습니다. ❌면 (⭕❌) "걸어가는 길을 알려드릴까요?"라고 묻고, 이것도 ❌면 안내를 마칩니다. 가까우면 걸어가는 길을 안내합니다.
4. **타는 곳 확인:** 집 안에서 지도(우리 집·타는 곳)와 타는 곳 사진을 보여주고 (⭕❌) "타는 곳은 ○○아파트 101동 앞으로 하면 될까요?"라고 묻습니다. ❌면 "그럼 어디에서 부를까요?"라고 묻고 새 장소를 다시 확인합니다. 바꾼 장소가 길 건너편이면 "길 건너" 큰 표시를 보여줍니다. 집 안에서는 위치가 부정확할 수 있어 가족이 등록한 집 주소와 동을 기준으로 합니다. 어르신은 촬영하지 않습니다. ○○아파트 101동은 가상 예시입니다.
5. **결제 방법:** (⭕❌) "등록한 카드로 결제할까요?" ❌면 "내리실 때 직접 결제해 주세요."라고 알립니다. 등록한 카드가 없으면 묻지 않고 직접 결제로 안내합니다.
6. **나갈 준비 확인:** 택시를 부르기 전에 (⭕❌) "나갈 준비 되셨어요?"라고 묻습니다. ❌면 부르지 않고 "천천히 준비하세요. 준비되면 '준비됐어'라고 말씀해 주세요."라고 알린 뒤 [준비됐어요] 버튼을 두고 기다립니다. 재촉하지 않습니다. ⭕ 또는 "준비됐어"라고 하면 최종 확인으로 갑니다.
7. **최종 확인:** 출발지·도착지·예상 요금·결제 방법을 큰 글씨로 보여주고 말로도 읽은 뒤 (⭕❌) "이대로 부를까요?"라고 묻습니다. ⭕일 때만 부릅니다. ❌면 "어디가 다른가요?"라고 묻고 [타는 곳] [가는 곳] [결제] [안 부를래] 중에서 고릅니다. 고친 뒤에는 최종 확인을 다시 합니다. [안 부를래]면 부르지 않고 마칩니다.
8. **호출과 배차:** "택시를 부르고 있어요."라고 알리고 취소 버튼을 둡니다. 배차되면 차 사진·차종·차 번호를 팝업으로 보여주고 (⭕❌) "차 사진과 번호, 확인하셨어요?"라고 묻습니다. ⭕ 또는 닫기를 고르면 차 사진과 번호가 화면 아래 카드로 내려가며, 누르면 다시 크게 볼 수 있습니다. ❌면 팝업을 유지하고 차종·번호를 읽은 뒤 다시 묻습니다.
9. **나가기와 대기:** 지도가 커지고 택시 위치를 보여줍니다. 아바타는 왼쪽 위, 말풍선은 아바타 오른쪽에 두며 최근 1~2개만 큰 글씨로 보여줍니다. 도착 예정 시간은 화면과 음성으로 함께 알립니다. "3분 뒤에 도착해요. 천천히 챙겨서 나가세요." 타는 곳을 길 건너편으로 바꾼 경우에만 길 앞에서 "횡단보도로 건너세요. 초록불에 주위를 살피세요."라고 안내합니다. 가까워지면 "택시가 곧 도착해요."라고 알립니다.
10. **택시 확인과 탑승:** (⭕❌) "택시가 보이세요?" ❌면 "타는 곳에서 조금 더 기다려 주세요."라고 말하고 지도를 보여준 뒤 다시 묻습니다. ⭕면 (⭕❌) "차 번호가 맞나요?"라고 묻습니다. ⭕면 "이제 타셔도 돼요.", ❌면 "이 차는 타지 마세요."라고 알리고 택시 확인으로 돌아갑니다.
11. **내릴 준비:** "곧 병원에 도착해요. 소지품을 챙기세요. 차가 완전히 멈추면 내리세요." 직접 결제면 "요금은 내리실 때 직접 결제해 주세요."를 덧붙입니다.
12. **도착:** "병원에 도착했어요. 혼자서 잘 오셨어요! 다음에도 곁에서 도와드릴게요."라고 칭찬·격려하고, [안내 마치기]를 누르면 첫 화면으로 돌아갑니다.

**취소와 실패**

| 상황 | 곁에의 처리 |
| --- | --- |
| 호출 중이나 대기 중에 "취소해" | (⭕❌) "택시를 취소할까요?" ⭕면 취소하고 "택시를 취소했어요."라고 알림. ❌면 그대로 진행. 실제 서비스의 취소 수수료는 확인 필요 |
| 택시 연결 실패 | (⭕❌) "카카오택시 연결이 안 되네요. 한 번 더 해볼까요?" ⭕면 다시 시도, ❌면 부르지 않고 마침 |
| 택시가 잘 안 잡힘 (시연 제외) | "다른 길로 갈까요, 계속 부를까요?"라고 물음 |

**걸어갈 때:** 가까운 거리나 택시 타는 곳까지는 짧은 문장으로 한 단계씩 길을 알려줍니다. 예: "약국에서 왼쪽으로 가세요." 한 단계가 끝나 할아버지가 "알겠어"라고 하면 다음 단계를 말합니다. 위치상 길을 잘 가고 있으면 중간에도 "잘 가고 계세요."라고 짧게 칭찬합니다. 길을 모르겠으면 "여기서 어디로 가?"라고 말하거나 버튼을 누르고 카메라로 앞을 비춥니다. 영상 위에 가야 할 방향이 큰 화살표로 뜨고 "이쪽으로 가세요."라고 말합니다. 걸으면서 들지 않도록 "멈춰서 비춰 주세요."라고 먼저 안내합니다. 시연은 가상 위치가 정해진 경로를 따라 움직입니다. 걸어갈 때의 "지도 보기" 버튼(예시 지도에 현재 위치, 목적지, 경로 표시)은 시간이 되면 넣습니다. 택시 대기·이동 지도는 필수입니다.

**어르신만의 말:** 어르신이 사투리를 쓰거나 장소를 다르게 부를 수 있어, 가족이 등록한 표현(예: "그려"는 "응", "역전 병원"은 ○○병원)을 등록한 뜻으로 알아듣습니다. 장소는 부르는 이름으로 알아들어도 "○○병원이에요?"라고 반드시 다시 확인합니다. 음성 인식이 매번 다르게 받아 적으면 못 알아들을 수 있어 선택 버튼은 그대로 둡니다.

음성 인식에 실패하면 "다시 알려줘" 버튼과 지금 질문의 선택 버튼이 있는 별도 화면이 나옵니다. 시연 목적지는 행복대학병원(택시)을 기본으로 하고, 튼튼내과와 다른 병원 선택은 갈래를 보여줄 때 씁니다.

**가족 시나리오:** 가족이 곁에를 준비하는 흐름입니다. 시연에서는 팀이 가족 설정을 미리 해 두고, 목소리 녹음과 입 위치 맞추기는 시연에서 제외합니다(이후 단계). 어르신이 해야 하는 동의는 가족이 대신 누르지 않고, 설명을 들은 어르신이 직접 확인합니다. 동의하지 않은 기능은 켜지 않습니다.

1. 가족이 곁에 앱의 가족 설정 화면을 엽니다.
2. 사진·목소리 주인의 동의를 확인한 뒤 본인 사진을 올립니다.
3. 생성형 이미지 AI가 사진을 실제 모습에 가까운 아바타로 바꿔주고, 마음에 들 때까지 다시 만들 수 있습니다.
4. 아바타의 입 위치를 손가락으로 한 번 맞춥니다. (이후 단계, 시연 제외)
5. 안내 문장을 하나씩 읽으며 녹음합니다(이후 단계, 시연 제외). 녹음하지 않은 문장은 미리 만든 기본 음성 파일(시연은 녹음한 음성)이 대신 재생됩니다.
6. 어르신 본인의 동의를 받고 우리 집 주소(아파트 동까지)를 등록합니다. 위치 정보 사용도 어르신이 동의합니다.
7. 병원을 종류(대학병원, 동네 내과), 이름, 주소로 등록합니다.
8. 결제 카드를 등록합니다(선택). 어르신과 카드 명의자가 동의합니다. 예시안에서는 실제 카드 번호를 입력받지 않습니다.
9. 어르신이 평소에 쓰는 말을 등록합니다. 뜻("응", "아니", "택시", "걸어서", "다시", "잠깐")을 고르고 어르신의 표현을 입력합니다. 병원에는 어르신이 부르는 이름을 함께 적습니다.
10. 사용해보기로 아바타가 말하는 모습과 목소리를 확인합니다.
11. 설정이 끝나면 어르신께 폰을 건네거나 곁에를 설치해 드립니다. (MVP는 설정이 한 폰에만 저장되므로 같은 폰으로 시연합니다.)

## 기능 범위

범위 표시는 세 가지입니다. **MVP(필수)**는 시연에 꼭 필요한 것, **MVP(시간 되면)**는 하루 일정에서 시간이 남을 때 넣는 것, **이후**는 이번 시연 범위 밖입니다.

### 어르신이 쓰는 기능

| 기능 | 범위 | 설명 |

| 지도 화면 자동 전환 | MVP(시간 되면) | 걷는 중, 그리고 택시를 기다리며 대화가 없을 때는 지도(택시 위치 지도 포함)가 기본이고, 택시를 기다리며 대화할 때는 아바타가 나옴. 기본 지도는 현재 위치·목적지·길만 단순하게 보여주고, "지도 보여줘"라고 하면 지도를 띄우고 "자세히 보여줘"라고 하면 자세한 지도로 바꿈. "지도 계속 보여줘"라고 하면 지금 보는 상황 동안 지도를 유지하며 아바타는 작게, 말은 아래 큰 자막으로 보여주고, 도착하거나 택시에 타면 유지가 풀림. 시연은 네이버 지도 이미지나 목업 지도 |

| 카카오 택시 호출 | MVP(필수) | 집 안에서 타는 곳(○○아파트 101동 앞, 지도·사진. 길 건너로 바꾸면 표시), 결제 방법, 나갈 준비, 출발지·도착지·예상 요금을 확인하고 ⭕일 때만 부름. 타는 곳 변경, 수정, 중단, 취소 가능. 곁에는 결제 방법을 고르게 할 뿐 결제를 직접 처리하지 않음. 시연은 호출·결제·요금·도착이 모두 예시 |
| 차량 정보 팝업과 아래 카드 | MVP(필수) | 배차되면 차 사진·차종·번호 팝업. 닫으면 사진과 번호가 아래 카드로 내려가고, 누르면 다시 크게 보임 |
| 탑승 확인 | MVP(필수) | "택시가 보이세요?"와 "차 번호가 맞나요?"를 차례로 확인. 번호가 다르면 타지 않도록 안내 |

| 입 위치 맞추기 | 이후 | 입 움직임이 자연스럽도록 아바타의 입 위치를 처음에 한 번 맞춤 |
| 안내 문장 직접 녹음 | 이후 | 시연에는 넣지 않음. 가족이 문장을 직접 녹음하면 그 녹음이 기본 음성 파일보다 먼저 재생됨. 기본값은 미리 만든 음성 파일(시연은 녹음한 음성) |
| 병원·집 주소 등록 | MVP(시간 되면) | 우리 집 주소와 병원의 종류(대학병원, 동네 내과)·이름·주소를 등록 |
| 어르신 말 등록(가족 입력) | MVP(시간 되면) | 뜻("응", "아니", "택시", "걸어서", "다시", "잠깐")을 고르고 어르신의 표현을 입력. 병원은 "부르는 이름" 칸에 적음. 한 표현은 한 가지 뜻에만 등록하고, 언제든 삭제 가능 |
| 어르신이 말해보며 등록 | MVP(시간 되면) | 가족 입력 다음에 만듦. 어르신 본인이 표현을 몇 번 말하면 음성 인식이 받아 적은 글자를 함께 저장. 어르신 동의가 필요하며 녹음 파일은 저장하지 않음 |
| 녹음으로 사투리·발음 학습 | 이후 | 어르신의 녹음(새로 녹음하거나 통화 녹음 같은 이미 있는 녹음본, 영상 속 소리)으로 음성 인식 모델(소리를 글자로 바꾸는 AI)을 맞춰 훈련하는 기능. 동의, 보관, 삭제 방식을 설계한 뒤 검토. 영상은 소리만 쓰고 영상 자체는 저장하지 않는 방향 |
| 기존 녹음본·영상에서 어르신 말 가져오기 | 이후 | 통화 녹음처럼 이미 있는 녹음본이나 영상을 올리면 어르신 목소리 부분을 글자로 받아 적어 표현 후보를 보여주고, 가족이 골라 어르신 말로 등록함. 영상은 소리만 쓰고 올린 파일은 후보를 뽑은 뒤 저장하지 않음. 통화 녹음은 갤럭시 기본 통화 녹음으로 만든 파일을 쓰고, 어르신과 통화 상대의 동의 여부를 먼저 확인함. 실제로 만들 때는 일레븐랩스 같은 음성 복제 서비스를 씀. 이 파일은 녹음으로 사투리·발음 학습에도 쓸 수 있도록 검토 |
| 사용해보기 | MVP(시간 되면) | 설정이 끝나면 아바타가 말하는 모습과 목소리를 확인 |
| 말하는 모습 영상 올리기 | 이후 | 가족이 말하는 5~10초 영상을 올리면 아바타가 대기 중일 때 반복 재생. 사진 한 장으로 말하는 영상을 자동으로 만드는 립싱크 AI도 이후에 검토 |
| 아바타 꾸미기(편집) | 이후 | 사진 기반 아바타를 머리 모양, 색, 소품 등으로 고쳐 꾸미는 기능. 우선순위에 넣지 않음 |
| 어르신 사용 확인 알림 | 이후 | 어르신이 곁에를 사용했는지 가족이 확인할 수 있게 하는 알림이나 사용 기록 |

**사용자 기능이 아니라 팀이 준비하는 것:** 안내 문장을 녹음해 음성 파일을 만들고, AI 키 입력칸(본인 폰에만 저장)을 만듭니다. 기존 음성 대본(VOICE_SCRIPT)은 아직 이 흐름에 맞춰지지 않아, 녹음 전에 아래 택시 문장을 기준으로 대본을 고쳐야 합니다.

## MVP 우선순위

하루 안에 만들어야 하므로 "시연 한 줄"에 필요한 것만 P0로 둡니다. (P0은 꼭 되어야 하는 것, P1은 시간이 되면 넣는 것, P2는 시연 범위 밖이지만 시간이 남으면 해보는 것, P3은 우선순위에 넣지 않고 이후로 미루는 것입니다.)

| 우선순위 | 기능 | 이유 |
| --- | --- | --- |
| P0 | 아바타 화면(AI 도우미 표시 포함), 녹음한 안내 음성 파일 재생 | "가족이 옆에 있다"는 느낌을 입 움직임 없이도 시연에서 보여줌. 입이 움직이는 모습은 발표용 영상으로 보여줌 |
| P0 | 바로 듣기, 음성 요청 인식, ⭕❌ 답하기, 실패 시 선택 버튼 | 대화의 시작과 인식 오류 대비. 음성 인식이 불안정하면 버튼만 눌러 시연함 |
| P0 | 병원 선택·확인(다른 병원 질문 포함), 타는 곳 확인(지도·사진) | 시연 한 줄의 핵심 |
| P0 | 결제 방법·나갈 준비·요금 최종 확인, 모의 호출 | 메인 시나리오. 시연의 중심 |
| P0 | 차량 팝업·아래 카드, 택시 위치 지도, 도착 예정 시간, 탑승 확인, 내릴 준비·도착 칭찬 | 부른 뒤 도착까지 안심하고 따라가는 흐름 |
| P1 | 카메라로 방향 보기, 걸어갈 때의 길 안내, 지도 화면 자동 전환, 지금 상태 카드 | 서브 기능. 안 되면 음성 설명만으로 시연 |
| P1 | 가족 화면의 동의·집 주소·병원·카드 등록 | 가족 쪽 경험을 보여줌. 안 되면 미리 설정한 값으로 시연 |
| P1 | 사진을 실제 모습에 가까운 아바타로 변환 | 가족이 직접 아바타를 만드는 경험. 안 되면 미리 만든 아바타 사용 |
| P1 | AI 말뜻 이해 | 시연에서 AI의 역할을 보여줌. 실패하면 정해진 단어로 대체 |
| P1 | 어르신 말 등록(가족 입력)과 등록한 말 알아듣기. 시간이 더 남으면 어르신이 말해보며 등록 | 사투리나 다르게 부르는 이름에 대비. 안 되면 선택 버튼으로 시연 |
| P2 | 실제 GPS·나침반 연동 | 걸으며 시연하기 어려워 시연 범위 밖. 지도 이미지와 주소 변환은 네이버 지도로 시연에서 쓸 수 있음 |
| P2 | 자유롭게 대화하는 AI 도우미 | 응답 지연, 요금, 엉뚱한 대답 위험 때문에 이후 단계로 둠 |
| P2 | 실시간 복제 목소리 생성 | 키 보안, 대기 시간, 요금 문제 때문에 이후 단계로 둠 |
| P2 | 녹음(기존 통화 녹음·영상 포함)으로 사투리·발음 학습 | 데이터와 시간이 필요해 시연 범위 밖 |
| P3 | 아바타 꾸미기(편집), 말하는 영상 올리기 | 우선순위 아님. 이후 단계로 미룸 |

**발표에서 반드시 명시할 것 (1):** 이번 결과물은 실제 연동이 없는 예시안입니다(지도 화면은 네이버 지도 이미지나 예시 지도를 쓰고, 걷는 길은 미리 정한 경로입니다). 위치, 지도, 타는 곳 사진, 택시 호출, 결제, 요금, 차량 정보, 택시 이동, 도착은 모두 예시이며 정해 둔 화면과 시간으로 전환합니다. 카메라 화살표도 미리 정한 장면입니다. 실제 서비스의 지도·택시·결제 연동 가능 여부는 확인하지 않았습니다. 전철, 버스, 시외버스 예약 등도 같은 방식으로 돕는 것이 목표라는 점을 함께 제시합니다.

**발표에서 반드시 명시할 것 (2):** 시연의 대화는 네/아니요, 병원 이름, "택시", "걸어서", "다시", "잠깐" 같은 미리 정한 짧은 말에 반응하는 방식(AI 말뜻 이해가 되면 다양한 말도 이해)이지만, 실제 서비스의 도우미는 어르신의 말을 이해하고 상황에 맞게 대답하는 대화형 AI라는 점을 밝힙니다.

**발표에서 반드시 명시할 것 (3):** 시연에 쓰는 목소리는 녹음해서 미리 만들어 둔 짧은 문장이지만, 실제 서비스는 목소리를 학습해 어떤 장소와 경로든 실시간으로 생성하는 구조로 만든다는 점을 발표자료에 분명히 적습니다. 동시에 시연은 미리 만든 문장임을 함께 밝힙니다.

**발표용 영상으로만 보여줄 것:** 가족 목소리로 안내하는 모습과 입이 움직이는 아바타는 시연에 넣지 않고 발표용 영상으로만 보여줍니다. 시연은 아바타 화면과 녹음한 음성 파일로 진행합니다. 영상 제작은 일정에 넣고 담당은 팀이 정합니다.

**발표 표현 주의:** 이번 기능은 AI가 사투리를 학습하는 것이 아니라 "가족이 어르신만의 말을 알려주면 곁에가 그 말로 알아듣는다"로 설명합니다. 녹음 학습은 이후 단계라고 밝힙니다.

**설계 원칙:** 도우미는 처음에 AI임을 알립니다. 어르신이 실제 가족과 통화 중이라고 오해하지 않도록 화면에 "AI 도우미" 표시를 항상 둡니다.

## 필요한 기술과 API

MVP에서 키가 필요한 것은 AI 서비스(AI Studio의 제미나이: 아바타 이미지 변환, 말뜻 이해), 지도(네이버 지도), 목소리(일레븐랩스) 세 가지이고, 나머지는 브라우저 기본 기능이나 미리 만든 파일입니다. (API는 앱이 다른 서비스의 기능을 빌려 쓰는 통로, 키는 그 통로를 여는 비밀 열쇠입니다.)

| 기능 | 사용 기술 | 키 필요 | 비고 |
| --- | --- | --- | --- |
| 말하는 아바타 화면과 지도 | HTML, CSS, JavaScript(예시 지도 이미지 위에 타는 곳·목적지·택시 위치를 그림) | 불필요 | 안내 단계는 앱 안에서 관리, 위치와 택시 이동은 예시 |
| 카카오 택시 호출 | 앱 안의 모의 호출(정해 둔 화면과 시간) | 불필요 | 실제 호출·결제 연동 방식과 가능 여부는 확인하지 않음 |
| 지도와 길 정보 | 네이버 지도(Maps): Static Map(지도 이미지), Geocoding(장소 이름을 좌표로), Directions(자동차 길찾기) | 필요 | Directions는 자동차 경로만 줘서 걷는 길은 받을 수 없음. 걷는 길은 미리 정한 좌표와 문장으로 안내 |
| 안내 목소리 만들기 | 일레븐랩스(글을 목소리로 바꾸는 서비스) | 필요 | 시연용 문장은 미리 만들어 파일로 재생. 실시간 생성 여부는 팀이 정하는 중 |
| 카메라로 방향 보기 | getUserMedia(브라우저가 카메라를 켜는 기능, https 주소에서만 동작), 영상 위에 화살표 겹치기 | 불필요 | 시연은 미리 정한 장면과 고정된 화살표. 이후 DeviceOrientation(폰 방향 센서), GPS, 지도 API로 계산 |
| 사진을 아바타로 변환 | 이미지 생성 AI API (Gemini 또는 OpenAI) | 필요 | Claude API는 이미지를 만들지 못해 제외. 가족 동의 필요 |
| 말뜻 이해(의도 분류) | 텍스트 AI API (아바타 변환과 같은 서비스) | 필요 | 짧은 문장만 보내 요금 부담이 작음. 실패하면 정해진 단어로 대체 |
| 아바타 입 움직임 | Web Audio (브라우저가 소리 크기를 분석하는 기능) | 불필요 | 입 모양을 소리 크기에 맞춤. 시연에서는 제외하고 발표용 영상에서만 보여줌 |
| 음성 요청 인식 | Web Speech API | 불필요 | 안드로이드 크롬에서 가장 안정적. 앱을 열면 바로 듣기 시작하되, 브라우저가 막을 때를 대비해 큰 말하기 버튼을 둠 |
| 어르신 말 사전 | JavaScript(받아 적은 글자를 등록한 표현과 비교), 브라우저 저장 공간에 글자만 저장 | 불필요 | 음성 인식 모델을 훈련하지는 않음. 설정은 이 폰에만 저장 |
| 기존 녹음본·영상에서 말 가져오기(이후) | 일레븐랩스 같은 음성 서비스(음성 복제, 소리를 글자로 바꾸기). 통화 녹음은 갤럭시 기본 통화 녹음으로 만든 파일, 영상은 소리만 추출 | 필요 | MVP에서는 쓰지 않음. 올린 파일이 외부 서비스로 전송되므로 어르신과 통화 상대의 동의를 먼저 확인 |
| 가족 문장 녹음(이후, 시연 제외) | MediaRecorder (마이크 소리를 파일로 저장하는 기능) | 불필요 | 녹음이 기본 음성 파일보다 먼저 재생됨 |
| 안내 목소리 파일 | 미리 녹음한 음성 파일 | 앱에는 불필요 | 제작할 때만 사용. 시연은 녹음한 음성, 실제 서비스는 가족 목소리 복제 |
| 키·녹음·아바타·집 주소·병원 저장 | localStorage, IndexedDB (브라우저 안의 작은 저장 공간) | 불필요 | 예시안은 가짜 주소만 사용. 본인 폰에만 저장. 카드 번호는 저장하지 않음 |
| 웹 주소 만들기 | GitHub Pages (GitHub에 올리면 웹 주소로 바꿔주는 무료 기능) | 불필요 | 폰에서 열고 마이크 권한을 쓰려면 https 필요 |
| 실제 위치·지도 연동(이후) | Geolocation API(브라우저가 현재 위치를 알려주는 기능), 지도·길찾기 API(예: 카카오 또는 네이버 지도) | 필요 | MVP에서는 쓰지 않음. 위치는 폰 안에서만 쓰고 저장하지 않음 |

## 위험과 대응

가장 큰 위험은 가족 목소리·얼굴을 악용하는 보이스피싱과 도용, 그리고 어르신이 같은 이름의 다른 장소로 가거나 길에서 위험해지는 일입니다.

| 위험 | 내용 | 대응 |
| --- | --- | --- |
| 보이스피싱 오용 | 가족 목소리 복제 기술이 사기에 쓰일 수 있음 | MVP는 미리 녹음한 고정 문장만 사용하고 실시간 생성은 하지 않음. 이후 실시간 복제는 본인 동의와 앱 안에서만 재생하는 구조로 설계 |
| 실사형 아바타 오용·오해 | 실제 얼굴과 목소리를 합치면 도용에 쓰일 수 있고, 어르신이 진짜 가족과 통화 중이라고 믿을 수 있음 | 본인 동의 필수, 다른 사람 사진은 올릴 수 없음을 안내, 앱 안에서만 재생하고 내려받기와 공유 기능은 두지 않음. 화면에 "AI 도우미"를 항상 표시하고 첫 인사에서 AI임을 알림 |
| 같은 이름의 다른 장소 | 같은 이름의 병원이나 약국이 여러 곳이라 엉뚱한 곳으로 안내될 수 있음 | 현재 위치에서 가장 가까운 곳부터 지역과 함께 "맞아요?"라고 꼭 확인하고, 확인 전에는 안내하지 않음. 가족이 등록한 병원을 먼저 보여주고, 등록하지 않은 병원은 이름과 지역을 확인함 |
| 길 안내 오류 | 안내가 실제 길과 달라 어르신이 헤맬 수 있음 | 시연은 미리 검증한 경로로 한정. 실제 서비스는 지도 API로 경로를 만들고 안전 검증을 거침. 막히면 "다시 알려줘"로 다시 들을 수 있음 |
| 카메라 방향 오류·걸으며 폰 사용 | 화살표가 틀리거나, 폰을 보며 걷다 사고가 날 수 있음 | "멈춰서 비춰 주세요"라고 먼저 말로 안내하고, 화살표는 보조로 두며 음성 안내를 함께 제공. 시연은 미리 검증한 장면으로 한정 |
| 택시 호출·요금 실수 | 의도하지 않은 곳으로 호출되거나 요금을 모르고 탈 수 있음 | 타는 곳, 결제 방법, 나갈 준비, 예상 요금을 확인하고 최종 질문에 ⭕일 때만 부름. 대답이 없거나 알아듣지 못하면 부르지 않음. 수정·중단·취소 가능. 요금은 실제와 다를 수 있음을 알림 |
| 서두름과 길 건너기 | 택시 시간에 맞추려고 급히 나가다 다칠 수 있음. 타는 곳을 길 건너로 바꾸면 건너는 위험도 있음 | "나갈 준비 되셨어요?"에 ⭕일 때만 호출로 넘어가고 "천천히 챙겨서 나가세요"라고 안내함. 길 건너일 때는 횡단보도를 안내함. 대기 시간이 충분한지는 사용성 테스트에서 확인 필요 |
| 다른 차 탑승 | 비슷한 택시를 부른 차로 착각할 수 있음 | 차 사진·번호를 보여주고, 번호가 맞다고 답한 뒤에 타도록 안내 |
| 위치 정보와 집 주소 | 어르신의 위치와 집 주소는 개인정보 | 예시안은 가상 위치와 가짜 주소만 사용. 실제 서비스에서는 어르신의 동의를 받고, 호출에 필요한 범위에서만 전달하며 보관·삭제 방식을 설계해야 함. 가족에게 위치를 공유하려면 별도 동의를 받음 |
| 의존 | 어르신이 혼자 시도하지 않게 될 수 있음 | 안내를 따라 하다 보면 직접 할 수 있게 하는 "혼자 해보기" 모드를 이후 검토 |
| 음성 인식 오류 | 사투리, 발음, 주변 소음 때문에 인식이 틀릴 수 있고, 도우미 목소리를 마이크가 다시 들을 수 있음. 앱을 열자마자 듣는 기능을 브라우저가 막을 수도 있음 | 알아듣는 말을 짧은 단어로 한정, 도우미가 말하는 동안 듣기 중지, 선택 버튼과 큰 말하기 버튼, "다시 알려줘" 버튼을 함께 제공 |
| 말뜻을 잘못 이해 | AI가 목적지를 엉뚱하게 이해할 수 있음 | 장소는 항상 "맞아요?"로 되묻고 어르신이 확인한 뒤에만 진행. 실패하면 정해진 단어로 대체 |
| 등록한 말의 오인식 | 등록한 표현이 다른 뜻과 겹치거나 매번 다르게 받아 적혀 잘못 처리될 수 있음 | 한 표현은 한 가지 뜻에만 등록하고, 장소는 항상 "맞아요?"로 확인. 못 알아들으면 선택 버튼 사용 |
| 지도 API 한계 | 네이버 길찾기는 자동차 경로만 주고, 브라우저에서 바로 부르면 막힐 수 있어 중계 프로그램이 필요할 수 있음 | 시연은 미리 정한 좌표와 문장을 쓰고, 발표 환경에서 지도가 나오는지 미리 확인 |
| 어르신 말·목소리 정보 | 말버릇과 목소리는 개인정보이고, 브라우저 음성 인식은 소리를 외부 서버로 보낼 수 있고, 일레븐랩스 같은 음성 복제 서비스를 쓰면 올린 파일이 그 서비스로 전송됨 | 어르신 본인에게 알리고 동의를 받은 뒤 진행. 곁에는 녹음 파일을 저장하지 않고 글자만 이 폰에 저장하며 삭제할 수 있게 함. 이미 있는 통화 녹음(갤럭시 기본 통화 녹음 기능으로 만든 파일)이나 영상을 쓸 때는 어르신과 통화 상대의 동의 여부를 먼저 확인하고, 법적 문제를 확인한 뒤 사용함 |
| 예시안과 실제 서비스의 차이 | 시연이 실제 택시 호출·결제까지 되는 것처럼 보일 수 있음 | 발표에서 실제 연동이 없는 예시안임을 밝힘. 실제 서비스는 연동 가능 여부 확인과 안전 검증이 필요하다고 설명 |
| API 키 노출 | 키를 코드에 넣어 GitHub에 올리면 남이 쓰고 요금이 청구될 수 있음 | 키를 코드에 넣지 않고 앱의 입력칸에 직접 넣어 본인 폰에만 저장. 이후 서버에서 키를 숨기는 구조로 전환 |
| 가족 사진 개인정보 | 아바타를 만들려고 올린 얼굴 사진이 외부 AI 서비스로 전송됨 | 사진 주인의 동의를 먼저 받고, 변환이 끝나면 원본 사진은 저장하지 않고 아바타 이미지만 폰에 보관 |

## 이후 단계 로드맵

MVP는 말하는 아바타가 택시 호출부터 도착까지 돕는 흐름을 실제 연동 없는 예시안으로 보여줍니다. 발표에서는 이 점을 밝히고, 실제 서비스로 가는 길을 로드맵으로 보여줍니다.

| 단계 | 내용 |
| --- | --- |
| MVP | 말하는 아바타 + 병원 선택 + 택시 부르기(타는 곳·결제·나갈 준비·요금 확인, 모의 호출) + 차량 정보·택시 위치 지도 + 탑승 확인 + 내릴 준비·도착 칭찬. 길찾기, 가족 설정 화면은 시간 되면 |
| 다음 | 어르신 사용성 테스트(성공 지표 목표 수치 결정), 실제 GPS·나침반 기반 카메라 방향 안내, 지도 API 연동, 전철·버스·시외버스 예약 등으로 확장 |
| 이후 | 자유롭게 대화하는 AI 도우미, 가족 목소리 안내, 아바타 입 움직임(시연에서는 제외하고 발표용 영상으로만 보여줌), 가족 목소리 실시간 생성, 녹음(기존 통화 녹음·영상 포함)으로 어르신의 사투리·발음 학습, 진짜 앱 위에서 짚어주는 도우미(안드로이드 네이티브 앱) |

## 팀 역할

4인 팀(4N)의 역할입니다. 주담당과 지금까지 한 일을 함께 적습니다.

| 책임 영역 | 담당 | 지금까지 한 일 |
| --- | --- | --- |
| 기획·진행 | 권희수 | PM/PO (범위·일정·발표) |
| UX·UI | 이도은 | PRD, UX |
| 화면 제작 | 박민영 | 페르소나, 유저저니, UI |
| AI·통합 | 진영빈 | 개발, API |

백업 담당은 따로 정하고, 테스트와 최종 확인은 팀 전체가 참여합니다.

## 정리한 질문

- [x] AI 서비스: 이 문서의 기술 표 기준(Gemini 또는 OpenAI, Claude는 이미지 생성 불가)으로 진행
- [x] 시연 목적지와 경로 문장: 음성 대본의 목적지와 문장 기준으로 진행, 필요한 문장은 추가 목록으로 보탬
- [x] 카카오 택시 가정: "곁에는 카카오 파생 서비스라 카카오 택시 호출을 쓴다는 가정"을 발표에서 그대로 밝힘
- [x] 택시 결제: 등록한 카드 또는 내릴 때 직접 결제를 고르게 함. 곁에가 결제를 직접 처리하지 않으며 예시안은 실제 결제 없음
- [x] "아니요" 처리와 호출 취소: 정식 흐름에 포함. 시연 기본 흐름에 모두 보여줄 필요는 없음
- [x] 호출 시점: "나갈 준비 되셨어요?"에 ⭕라고 답한 뒤 호출. 대기 시간 "3분"은 예시이며 사용성 테스트에서 확인
- [x] 타는 곳: ○○아파트 101동 앞(가상 예시). "길 건너" 표시는 타는 곳을 길 건너로 바꾼 경우에 보여줌
- [x] 어르신이 말해보며 등록: MVP(시간 되면)로 두고 시연 필수에는 넣지 않음
- [x] 카메라로 방향 보기 시연 장면: MVP(시간 되면)로 두고, 안 되면 음성 설명만으로 시연
- [x] 성공 지표 목표 수치: 이후 사용성 테스트 때 정함
- [x] 사용성 테스트 참여자: 사용성 테스트와 함께 이후에 구함

## 나중에 추가할 기능

MVP는 택시 부르기와 길찾기입니다. 아래는 같은 방식으로 도울 다른 서비스들이며, 시연 일정 안에는 넣지 않습니다.

| 서비스 | 도우미가 하는 일 |
| --- | --- |
| 실제 걷는 길 안내 | 폰의 GPS를 따라 "앞으로 쭉 가세요.", "좌회전하세요."를 걸음마다 실시간으로 안내 |
| 실제 택시 호출 연동 | 곁에가 실제로 택시를 부르고 예상 요금과 도착 알림을 알려줌 (카카오 파생 서비스 가정) |
| 전철 설명 | 노선, 환승, 승강장 방향, 출구 번호를 말로 설명 |
| 버스 | 어느 번호를 타는지, 어디서 타고 내리는지 안내 |
| 시외버스 예약 | 출발지, 도착지, 시간, 좌석을 고르는 과정을 안내하고 결제 금액을 먼저 확인 |
| 배달앱 주문 (배민 같은 앱) | 가게, 메뉴, 장바구니, 주소, 결제를 단계별로 안내하고 결제 전에 금액 확인 |
| 영화관·병원 예약, 송금 | 같은 방식으로 단계별 안내 |
| 키오스크 안내 | 폰 카메라로 키오스크 화면을 비추면 눌러야 할 버튼을 알려줌 (아래 부록) |

## 부록: 카메라로 키오스크 안내

폰 밖의 키오스크(카페, 식당, 병원 접수처)를 안내하는 확장입니다. "카메라로 방향 보기"와 같은 카메라 기능을 쓰므로 길찾기 다음 순서로 검토합니다.

1. 어르신이 곁에를 열고 "카페 주문"이라고 말합니다.
2. 폰 카메라로 키오스크 화면을 비추고 "알려줘"를 누르면 사진 한 장을 AI에 보냅니다.
3. AI가 눌러야 할 버튼과 위치를 찾고, 준비된 짧은 안내 문장 중 지금 단계를 고릅니다.
4. 영상 위에 큰 동그라미가 뜨고 가족 목소리 안내가 나옵니다.
5. 화면이 바뀔 때마다 2~4를 반복하고, 결제 화면에서는 금액 확인 질문을 먼저 합니다.

필요한 것은 이미지 인식 AI API(Gemini 또는 OpenAI, 키 필요), 카메라, 시연용 키오스크 화면입니다.

| 한계 | 대응 |
| --- | --- |
| 한 손에 폰, 한 손으로 키오스크를 눌러야 함 | 목걸이형 폰 홀더나 거치대, 말로 위치를 설명하는 음성 안내 |
| AI 응답에 2~5초가 걸림 | "생각하는 중" 표시를 넣고 연속 촬영 없이 한 장씩 보냄 |
| 폰을 움직이면 동그라미가 어긋나고 AI가 찍은 위치도 조금 틀릴 수 있음 | 폰을 가만히 들게 안내, 동그라미를 크게 그림, "다시 알려줘" 버튼 |
| 낯선 키오스크에서 틀린 버튼을 가리킬 수 있음 | 시연은 미리 테스트한 화면으로 한정, 결제 단계는 금액 확인 후 진행 |

이후에는 화면이 바뀔 때만 사진을 보내는 연속 인식, 빠른 모델로 지연 줄이기, 진짜 앱 위에 떠다니는 도우미(안드로이드 네이티브 앱)로 확장합니다.
