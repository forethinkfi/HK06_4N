# 곁에 PRD 초안

2026-11-25

곁에는 어르신이 낯선 앱을 쓸 때, 화면 위에 가족 아바타가 떠서 가족의 목소리로 한 단계씩 짚어 주는 서비스입니다. MVP의 대표 시나리오는 **택시 부르기**입니다. 전철, 버스, 시외버스 예약 같은 다른 이동·예약 서비스도 같은 방식으로 모두 도울 수 있게 확장할 계획입니다. MVP는 택시앱 목업(실제 작동하지 않는 가짜 화면)에서 시연합니다.

## 배경과 문제

어르신이 혼자 이동하려면, 앱 쓰는 법을 알려주는 사람이 거의 항상 필요합니다.

- 택시앱, 버스·기차 예약앱, 지도앱처럼 이동에 앱이 필요한 일이 늘었습니다.
- 어르신은 어느 버튼을 눌러야 하는지, 요금과 결제가 맞는지 몰라서 막히고, 잘못 눌러 요금이 나갈까 봐 앱 사용 자체를 망설이기도 합니다.
- 가족은 전화로 "그 초록색 버튼 눌러"를 반복해야 하고, 직접 불러 줄 수 없는 경우가 많습니다.
- 기존 앱 도움말은 글자 중심이라 어르신께 낯섭니다. 어르신이 따르는 건 "아는 사람의 목소리"입니다.

핵심 통찰은 어르신께 필요한 것이 기능 설명이 아니라 **믿는 사람이 옆에서 눌러야 할 곳을 말해 준다는 안심감**이라는 점입니다.

## 목표와 성공 지표

MVP(핵심 기능 하나만 실제로 동작하게 만든 최소 제품)의 목표는 "어르신이 가족의 목소리 안내만으로 택시를 끝까지 부른다"는 가설을 검증하는 것입니다.

| 지표 | 측정 방법 | 목표 |
| --- | --- | --- |
| 호출 성공률 | 테스트 참가자 중 도움 없이 택시 호출까지 마친 비율 | 정해야 함 |
| 호출까지 걸린 시간 | 곁에를 연 때부터 호출 완료까지 초 단위 측정 | 정해야 함 |
| 막히는 횟수 | "다시 알려줘" 요청 횟수와 잘못 누른 횟수 | 정해야 함 |
| 안심감 | 사용 후 "혼자 해냈다는 느낌이 들었는지" 5점 척도 질문 | 정해야 함 |

팀플 단계에서는 어르신 3~5분을 대상으로 짧은 사용성 테스트(실제 사용자에게 써보게 하고 관찰하는 테스트)를 하고 위 표의 목표수치를 팀이 정합니다.

## 사용자

사용자는 두 사람입니다. 어르신이 쓰고, 가족이 목소리와 아바타를 준비합니다. (페르소나는 실제 인터뷰 전까지 가정으로 쓴 대표 사용자 상입니다.)

| 구분 | 어르신 (사용자) | 가족 (준비자) |
| --- | --- | --- |
| 대표 인물 | 스마트폰은 쓰지만 택시, 예약 앱에는 자신이 없는 할머니 | 멀리 사는 자녀나 손주, 수시로 전화를 받는 사람 |
| 하려는 일 | 병원이나 터미널까지 택시를 불러 혼자 가기 | 어르신이 앱 앞에서 막히지 않게 일일이 설명하지 않아도 되게 하기 |
| 불편 | 어느 버튼을 눌러야 할지, 요금이 맞는지 헷갈림 | 전화로 말로만 설명하기 어렵고 자주 반복됨 |
| 원하는 것 | 혼자 하고 싶고, 믿는 목소리가 옆에 있기를 바라기 | 어르신이 혼자 안전하게 다녀오고 이를 확인하기 |

이 표는 가정이므로 어르신 인터뷰 후 고쳐야 합니다.

## 핵심 시나리오

할머니가 택시앱 목업에서 병원까지 가는 택시를 부르는 흐름입니다. (사용자 흐름은 사용자가 목표를 이루기까지 거치는 단계를 순서대로 적은 것입니다.)

1. 할머니가 곁에를 열면 화면 한쪽에 가족 아바타가 작게 떠 있고, 필요 없으면 치울 수 있습니다.
2. 할머니가 아바타를 누르면 "할머니, 어디 가세요?"라고 가족 목소리로 묻습니다.
3. 할머니가 "병원 가야 돼, 택시 불러줘"라고 말합니다. (음성 인식으로 말을 글자로 바꾸고, AI가 "아픈데 택시 타고 병원 갈래" 같은 말도 목적지와 택시 호출로 이해합니다.)
4. 도우미가 "여기서 출발하는 거 맞아요?", "병원 맞아요?"라고 되묻고, 출발지와 목적지 이름은 화면에 큰 글자로 보여줍니다. 할머니가 "응"이라고 말하면 다음으로 넘어가고, "아니"라고 하면 다시 고릅니다.
5. 택시앱 목업 화면에서 눌러야 할 버튼에 큰 동그라미가 뜨고 "이 초록 버튼을 눌러 보세요"라고 안내합니다.
6. 요금이 나오면 "요금은 약 8천 원이에요, 괜찮으세요?"라고 먼저 확인하고, 할머니가 "응"이라고 해야 호출 버튼으로 넘어갑니다.
7. 호출이 끝나면 "택시가 오고 있어요. 번호판을 꼭 확인하세요"라고 알려줍니다.
8. 탑승을 마치면 가족이 미리 녹음한 "정말 잘 부르셨어요!"라는 칭찬이 나옵니다.

막히는 경우에는 "다시 알려줘" 버튼과 선택 버튼(병원, 시장, 터미널 등)을 함께 두어 음성 인식 오류에 대비합니다. 시연은 목적지를 미리 정한 2~3곳으로 하고, 택시앱은 실제 서비스가 아닌 가짜 화면이므로 MVP에는 외부 앱 연동과 실제 결제가 필요하지 않습니다.

**가족 시나리오:** 가족이 곁에를 준비하는 흐름입니다.

1. 가족이 곁에 앱의 가족 설정 화면을 엽니다.
2. 본인 사진을 올립니다. (사진 주인의 동의가 전제입니다.)
3. 생성형 이미지 AI가 사진을 일러스트풍 아바타로 바꿔주고, 마음에 들 때까지 다시 만들 수 있습니다.
4. 아바타의 입 위치를 손가락으로 한 번 맞춥니다.
5. 안내 문장을 하나씩 읽으며 녹음합니다. 녹음하지 않은 문장은 복제 목소리 파일이 대신 재생됩니다.
6. 미리 듣기로 아바타가 말하는 모습과 목소리를 확인합니다.
7. 설정이 끝나면 어르신께 폰을 건네거나 곁에를 설치해 드립니다. (MVP는 설정이 한 폰에만 저장되므로 같은 폰으로 시연합니다.)

## 기능 범위

MVP는 "택시앱 목업에서 택시 부르기 한 가지"만 끝까지 되게 만듭니다. 전철, 버스, 시외버스 예약 같은 다른 서비스도 같은 방식으로 모두 도울 수 있게 할 계획이며, 시연 범위에는 넣지 않고 맨 마지막 "나중에 추가할 기능"에 모아 적었습니다.

### 어르신이 쓰는 기능

| 기능 | 범위 | 설명 |
| --- | --- | --- |
| 화면 위에 떠 있는 도우미 | MVP | 택시앱 목업 화면 위에 아바타가 떠 있고, 누르면 도우미가 시작되며 필요 없으면 치울 수 있음 |
| 음성 요청 인식 | MVP | 브라우저 기본 음성 인식(Web Speech API)으로 말을 글자로 바꾸고, 텍스트 AI가 "택시 불러줘", "병원 가야 돼" 같은 다양한 말도 이해함. AI가 안 될 때는 정해진 단어로 알아들음 |
| 출발지·목적지 되묻기 | MVP | "여기서 출발하는 거 맞아요?", "병원 맞아요?"라고 물어 어르신이 확인한 뒤에만 다음으로 넘어감. 이름은 화면에 큰 글자로 보여줌 |
| 눌러야 할 버튼 짚어주기 | MVP | 택시앱 목업 화면에서 지금 눌러야 할 버튼에 큰 동그라미를 표시하고 가족 목소리로 안내. 미리 정한 12개 문장 중에서 고름 (AI가 새 문장을 짓지 않음) |
| 요금 확인 | MVP | 호출 전에 요금을 알려주고 "괜찮으세요?"라고 물어, 어르신이 "응"이라고 해야 호출로 넘어감 |
| 음성으로 주고받기 | MVP | 도우미가 말로 안내하고 할머니도 말로 답함. 알아듣는 말은 "응/아니", "다시", "잠깐"처럼 미리 정한 짧은 말로 한정. 도우미가 말하는 동안에는 듣지 않고 끝난 뒤에 들음. 눌러서 답하는 버튼도 함께 둠 |
| 가족 목소리 인사·칭찬 | MVP | 12개 문장(인사, 확인, 안내, 칭찬, 격려)을 가족 목소리 파일로 재생 |
| 단계별 안내 목소리 | MVP | 일레븐랩스로 본인 동의를 받은 팀원 목소리를 복제해 12개 안내 문장을 미리 만들어 두고, 상황에 맞는 파일을 재생 |
| 아바타 표시와 입 움직임 | MVP | 가족 아바타를 화면에 표시하고, 목소리가 재생되는 동안 소리 크기에 맞춰 입 모양이 바뀌어 말하는 것처럼 보이게 함 |
| 실패 시 선택 버튼 | MVP | 음성 인식이 틀리거나 막힐 때 눌러서 고를 수 있는 버튼 ("다시 알려줘" 포함) |
| 실제 택시앱 연동 | 이후 | 실제 택시앱 화면을 읽고 눌러야 할 곳을 짚어 줌. 화면 인식과 안드로이드 앱이 필요해 MVP에서는 목업 안에서만 구현 |
| 자유롭게 대화하는 AI 도우미 | 이후 | 실제 서비스의 최종 형태. 미리 정한 말이 아니라 어르신이 하는 말을 이해하고, 상황에 맞게 대답하고 되묻는 대화형 AI. 발표에서 반드시 명시함. 시연은 정해진 짧은 말과 12문장으로 대체 |
| 실시간 복제 목소리 생성(AI가 만든 새 문장까지 가족 목소리로) | 이후 | 실제 서비스의 최종 형태이며 발표에서 반드시 명시함. 시연은 12문장 파일로 대체하고, 보이스피싱 위험을 설계한 뒤 도입 |
| 혼자 해보기 모드 | 이후 | 안내를 따라 하다 보면 어르신이 직접 할 수 있게 하는 모드 |
| 진짜 앱 위에 띄우는 오버레이 | 이후 | 실제 택시앱 위에 떠다니는 도우미. 안드로이드 네이티브 앱이 필요해 MVP에서는 목업 안에서만 구현 |
| 확장 서비스 | 이후 | 전철 설명, 버스, 시외버스 예약, 걷는 길 안내, 배달앱, 영화관 예약, 병원 예약, 송금, 키오스크 안내를 모두 돕는 것을 목표로 함. 맨 마지막 "나중에 추가할 기능"에 모아 적음 |

### 가족이 쓰는 기능

| 기능 | 범위 | 설명 |
| --- | --- | --- |
| 가족 전용 설정 화면(녹음·아바타 등록) | MVP | 어르신께 드리기 전에 가족이 준비하는 화면 |
| 사진 올리기와 동의 확인 | MVP | 사진 주인의 동의를 먼저 확인한 뒤 사진을 올림. 변환이 끝나면 원본 사진은 저장하지 않고 아바타 이미지만 폰에 보관 |
| 사진을 아바타로 변환 | MVP | 올린 사진을 생성형 이미지 AI가 일러스트풍 아바타로 바꾸고, 마음에 들 때까지 다시 만들 수 있음 |
| 아바타 디자인 방향 | MVP | 그림체는 일러스트풍(세부 그림체는 팀에서 정함). 닮는 정도는 올린 사진을 기반으로 가족임을 알아볼 수 있을 만큼. |
| 입 위치 맞추기 | MVP | 입 움직임이 자연스럽도록 아바타의 입 위치를 처음에 한 번 맞춤 |
| 안내 문장 직접 녹음 | MVP | 가족이 문장을 직접 녹음하면 그 녹음이 복제 목소리보다 먼저 재생됨. 복제 목소리 파일은 기본값 |
| 미리 듣기 | MVP | 설정이 끝나면 아바타가 말하는 모습과 목소리를 확인 |
| 아바타 꾸미기(편집) | 이후 (우선순위 아님) | 사진 기반으로 만든 아바타를 머리 모양, 색, 소품 등으로 직접 고쳐 꾸미는 기능. 사진 기반 아바타가 먼저이며, 이 기능은 우선순위에 넣지 않고 이후로 미룸 |
| 어르신 사용 확인 알림 | 이후 | 어르신이 곁에를 사용했는지 가족이 확인할 수 있게 하는 알림이나 사용 기록 |

**사용자 기능이 아니라 팀이 준비하는 것:** 일레븐랩스로 복제 목소리 12문장 파일 만들기, 문장 목록 확정과 팀원 목소리 동의 받기, AI 키 입력칸(본인 폰에만 저장)을 만듭니다. 12문장은 택시 부르기 상황(인사, 목적지 묻기, 출발지 확인, 목적지 확인, 눌러야 할 버튼 안내, 요금 확인, 호출 완료, 번호판 확인, 다시 안내, 잠깐 멈춤, 칭찬, 격려)에 맞춰 팀에서 확정합니다.

## MVP 우선순위

하루 안에 만들어야 하므로 어르신 흐름(택시앱 목업에서 택시 부르기)만으로 시연이 성립하게 하고, 가족 설정은 그다음에 얹습니다. (P0은 꼭 되어야 하는 것, P1은 되면 좋은 것, P2는 시간이 남으면 하는 것, P3은 우선순위에 넣지 않고 이후로 미루는 것입니다.)

| 우선순위 | 기능 | 이유 |
| --- | --- | --- |
| P0 | 택시앱 목업 화면(출발지·목적지 입력, 요금, 호출), 화면 위에 떠 있는 도우미 | 시연의 무대 |
| P0 | 음성 요청 인식, 출발지·목적지 되묻기, 음성으로 주고받기, 12개 문장 중 지금 안내 고르기 | 어르신 흐름의 시작과 핵심 |
| P0 | 눌러야 할 버튼 짚어주기, 요금 확인 | 어르신이 막히는 지점과 잘못 누를 위험을 막음 |
| P0 | 복제 목소리 파일 재생, 미리 만든 아바타, 입 움직임 | "가족이 옆에 있다"는 느낌을 시연에서 보여줌 |
| P0 | 실패 시 선택 버튼 | 인식 오류에 대비 |
| P1 | 가족 녹음 화면 | 가족 쪽 경험을 보여줌 |
| P1 | 사진을 아바타로 변환, 입 위치 맞추기 | 가족이 직접 아바타를 만드는 경험 |
| P1 | AI 말뜻 이해("병원 가야 돼, 택시 불러줘"도 이해) | 시연에서 AI의 역할을 보여줌. 실패하면 정해진 단어로 대체 |
| P2 | 실제 택시앱 연동 | 화면 인식과 안드로이드 앱이 필요해 시연 범위 밖 |
| P2 | 자유롭게 대화하는 AI 도우미 | 시연 범위 밖. 응답 지연, 요금, 엉뚱한 대답 위험 때문에 이후 단계로 둠 |
| P2 | 실시간 복제 목소리 생성(AI가 만든 새 문장까지) | 시연 범위 밖. 키 보안, 대기 시간, 요금 문제 때문에 이후 단계로 둠 |
| P3 | 아바타 꾸미기(편집) | 우선순위 아님. 시연 범위와 개발 일정에서 제외하고 이후 단계로 미룸 |

**발표에서 반드시 명시할 것 (1):** 시연은 가짜 택시앱 목업이고 실제 호출이나 결제는 일어나지 않으며, 실제 서비스에서는 진짜 택시앱 위에서 안내한다는 점을 함께 밝힙니다. 전철, 버스, 시외버스 예약 등도 같은 방식으로 모두 돕는 것이 목표라는 점도 함께 제시합니다.

**발표에서 반드시 명시할 것 (2):** 시연의 대화는 AI가 다양한 말을 이해하고 "응/아니", "다시", "잠깐" 같은 미리 정한 짧은 말에 반응하는 방식이지만, 실제 서비스의 도우미는 어르신의 말을 이해하고 상황에 맞게 대답하는 대화형 AI라는 점을 밝힙니다.

**발표에서 반드시 명시할 것 (3):** 시연에 쓰는 가족 목소리는 미리 만들어 둔 12문장이지만, 실제 서비스는 목소리를 학습해 어떤 대답이든 실시간으로 생성하는 구조로 만든다는 점을 발표자료에 분명히 적습니다. 동시에 시연 화면이 실시간 생성처럼 보이지 않도록, 시연은 미리 만든 문장임을 함께 밝힙니다.

## 필요한 기술과 API

MVP에서 키가 필요한 것은 AI 서비스 하나(아바타 이미지 변환, 말뜻 이해)이고, 나머지는 브라우저 기본 기능이나 미리 만든 파일입니다. (API는 앱이 다른 서비스의 기능을 빌려 쓰는 통로, 키는 그 통로를 여는 비밀 열쇠입니다.)

| 기능 | 사용 기술 | 키 필요 | 비고 |
| --- | --- | --- | --- |
| 택시앱 목업 화면과 떠 있는 도우미 | HTML, CSS, JavaScript(가짜 택시앱 화면 위에 동그라미 표시와 단계 진행을 그림) | 불필요 | 실제 서비스 이름이나 로고 없이 가상의 앱으로 만듦. 안내 단계는 앱 안에서 관리 |
| 사진을 아바타로 변환 | 이미지 생성 AI API (Gemini 또는 OpenAI) | 필요 | Claude API는 이미지를 만들지 못해 제외. 가족 동의 필요 |
| 말뜻 이해(의도 분류) | 텍스트 AI API (아바타 변환과 같은 서비스) | 필요 | 짧은 문장만 보내 요금 부담이 작음. 실패하면 정해진 단어로 대체 |
| 아바타 입 움직임 | Web Audio (브라우저가 소리 크기를 분석하는 기능) | 불필요 | 입 모양을 소리 크기에 맞춤 |
| 음성 요청 인식 | Web Speech API | 불필요 | 안드로이드 크롬에서 가장 안정적 |
| 가족 문장 녹음 | MediaRecorder (마이크 소리를 파일로 저장하는 기능) | 불필요 | 녹음이 복제 목소리보다 먼저 재생됨 |
| 안내 목소리 12문장 | 일레븐랩스로 미리 만든 음성 파일 | 앱에는 불필요 | 제작할 때만 사용 |
| 키·녹음·아바타 저장 | localStorage, IndexedDB (브라우저 안의 작은 저장 공간) | 불필요 | 본인 폰에만 저장, 폰을 바꾸면 다시 설정 |
| 웹 주소 만들기 | GitHub Pages (GitHub에 올리면 웹 주소로 바꿔주는 무료 기능) | 불필요 | 폰에서 열고 마이크 권한을 쓰려면 https 필요 |
| 실제 택시앱·길찾기 연동(이후) | 화면 인식 AI, 안드로이드 네이티브 앱, 지도·길찾기 API | 필요 | MVP에서는 쓰지 않음. 위치는 폰 안에서만 쓰고 저장하지 않음 |

## 위험과 대응

가장 큰 위험은 가족 목소리를 악용하는 보이스피싱과, 어르신이 안내를 따르다 잘못 결제하는 일입니다.

| 위험 | 내용 | 대응 |
| --- | --- | --- |
| 보이스피싱 오용 | 가족 목소리 복제 기술이 사기에 쓰일 수 있음 | MVP는 본인 동의를 받은 팀원 목소리로 미리 만든 고정 12문장만 사용하고 실시간 생성은 하지 않음. 이후 실시간 복제는 본인 동의와 앱 안에서만 재생하는 구조로 설계 |
| 잘못된 결제·호출 | 안내를 잘못 따라 의도하지 않은 요금이 나가거나 엉뚱한 곳으로 호출될 수 있음 | 호출 전에 출발지, 목적지, 요금을 항상 되묻고 어르신이 "응"이라고 한 뒤에만 다음으로 넘어감. 결제는 어르신이 직접 누르게 함 |
| 위치 정보 | 어르신의 출발지는 민감한 개인정보 | MVP는 가상 위치만 쓰고, 이후에도 위치는 폰 안에서만 쓰며 저장하거나 외부로 보내지 않음. 가족에게 위치를 공유하려면 어르신의 동의를 먼저 받음 |
| 의존 | 어르신이 혼자 시도하지 않게 될 수 있음 | 안내를 따라 하다 보면 직접 할 수 있게 하는 "혼자 해보기" 모드를 이후 검토 |
| 음성 인식 오류 | 사투리, 발음, 주변 소음 때문에 인식이 틀릴 수 있고, 도우미 목소리를 마이크가 다시 들을 수 있음 | 알아듣는 말을 짧은 단어로 한정, 도우미가 말하는 동안 듣기 중지, 선택 버튼(병원, 시장, 터미널 등)과 "다시 알려줘" 버튼을 함께 제공 |
| 말뜻을 잘못 이해 | AI가 목적지를 엉뚱하게 이해할 수 있음 | 출발지와 목적지는 항상 "맞아요?"로 되묻고 어르신이 확인한 뒤에만 진행. 실패하면 정해진 단어로 대체 |
| 목업과 실제 앱의 차이 | 시연이 진짜 택시앱에서도 바로 되는 것처럼 보일 수 있음 | 발표에서 가짜 화면임을 밝히고, 실제 서비스는 화면 인식과 네이티브 앱, 서비스 사업자와의 협의가 필요하다고 설명 |
| API 키 노출 | 키를 코드에 넣어 GitHub에 올리면 남이 쓰고 요금이 청구될 수 있음 | 키를 코드에 넣지 않고 앱의 입력칸에 직접 넣어 본인 폰에만 저장. 이후 서버에서 키를 숨기는 구조로 전환 |
| 가족 사진 개인정보 | 아바타를 만들려고 올린 얼굴 사진이 외부 AI 서비스로 전송됨 | 사진 주인의 동의를 먼저 받고, 변환이 끝나면 원본 사진은 저장하지 않고 아바타 이미지만 폰에 보관 |

## 이후 단계 로드맵

MVP는 가짜 택시앱 목업 안에서 도우미가 눌러야 할 곳을 짚어 주는 방식입니다. 발표에서는 이 점을 밝히고, 실제 서비스로 가는 길을 로드맵으로 보여줍니다.

| 단계 | 내용 |
| --- | --- |
| MVP | 택시앱 목업 + 떠 있는 도우미, 미리 만든 12문장 가족 목소리, 가족 설정 화면 |
| 다음 | 전철 설명, 버스·시외버스 예약, 걷는 길 안내 등 다른 이동·예약 서비스로 확장 |
| 이후 | 자유롭게 대화하는 AI 도우미, 가족 목소리 실시간 생성, 진짜 앱 위에 떠다니는 도우미(안드로이드 네이티브 앱) |

## 나중에 추가할 기능: 확장 서비스와 외부 버전

MVP는 택시 부르기이고, 아래는 같은 방식으로 모두 도울 다른 서비스들입니다. 시연 일정 안에는 넣지 않습니다.

| 서비스 | 도우미가 하는 일 |
| --- | --- |
| 전철 설명 | 어느 노선을 타는지, 어디서 갈아타는지, 어느 방향 승강장으로 가는지, 몇 번 출구로 나가는지를 말로 설명 |
| 버스 | 어느 번호를 타는지, 어디서 타고 내리는지 안내 |
| 시외버스 예약 | 출발지, 도착지, 시간, 좌석을 고르고 결제하는 과정을 안내하고, 결제 금액이 맞는지 먼저 물음 |
| 걷는 길 안내 | 네이버 길찾기처럼 폰의 GPS를 따라 "앞으로 쭉 가세요", "좌회전하세요"를 실시간으로 안내 |
| 배달앱 주문 (배민 같은 앱) | 가게, 메뉴, 장바구니, 주소, 결제를 단계별로 안내하고 결제 전에 금액 확인 질문을 함 |
| 영화관 예약 | 영화, 시간, 좌석을 고르고 결제하는 과정을 안내 |
| 병원 예약·송금 | 같은 방식으로 단계별 안내 |

**외부 버전: 카메라로 키오스크 안내.** 폰 밖의 키오스크(카페, 식당, 병원 접수처)를 안내하는 확장입니다.

1. 어르신이 곁에를 열고 "카페 주문"이라고 말합니다.
2. 폰 카메라로 키오스크 화면을 비추고(getUserMedia, 브라우저가 카메라를 켜는 기능, https 주소에서만 동작) "알려줘"를 누르면 사진 한 장을 AI에 보냅니다.
3. AI가 눌러야 할 버튼과 위치를 찾고, 준비된 12개 문장 중 지금 단계를 고릅니다.
4. 카메라 영상 위에 큰 동그라미나 버튼 영역 표시가 뜨고, 가족 목소리 안내가 나옵니다.
5. 화면이 바뀔 때마다 2~4를 반복하고, 결제 화면에서는 금액 확인 질문을 먼저 합니다.

**필요한 것:** 이미지 인식 AI API(Gemini 또는 OpenAI, 키 필요), 카메라, 시연용 키오스크 화면.

**알려진 한계와 대응**

| 한계 | 내용 | 대응 |
| --- | --- | --- |
| 손이 모자람 | 한 손에 폰, 한 손으로 키오스크를 눌러야 함 | 목걸이형 폰 홀더나 거치대, 말로 위치를 설명하는 음성 안내 |
| 응답 지연 | AI 응답에 2~5초가 걸림 | "생각하는 중" 표시를 넣고, 요금과 지연 때문에 연속 촬영 없이 한 장씩 보냄 |
| 동그라미가 어긋남 | 폰을 움직이면 고정된 동그라미가 어긋나고, AI가 찍은 위치도 조금 틀릴 수 있음 | 폰을 가만히 들게 안내, 동그라미를 크게 그리거나 버튼 영역 전체를 칠함, "다시 알려줘" 버튼 |
| 처음 보는 화면 | 낯선 키오스크에서 틀린 버튼을 가리킬 수 있음 | 시연은 미리 테스트한 화면으로 한정, 결제 단계는 금액 확인 후 진행 |

**이후 발전:** 화면이 바뀔 때만 사진을 보내는 연속 인식, 빠른 모델로 지연 줄이기, 폰이 움직여도 동그라미가 따라오게 하기, 그리고 진짜 앱 위에 떠다니는 도우미(안드로이드 네이티브 앱)로 확장합니다.
