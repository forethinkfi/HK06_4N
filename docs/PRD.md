# 곁에 PRD 초안

2026-11-25

곁에는 어르신이 키오스크 앞에서 폰 카메라로 화면을 비추면, 가족의 목소리와 아바타가 눌러야 할 버튼을 짚어주는 서비스입니다.

## 배경과 문제

어르신이 혼자 온라인 서비스나 키오스크(무인 주문기)를 쓰려면, 옆에서 알려주는 사람이 거의 항상 필요합니다.

- 카페, 식당, 병원 접수처의 키오스크가 늘면서 어르신이 직원 없이 주문하거나 접수해야 하는 상황이 많아졌습니다.
- 어르신은 화면의 용어와 버튼 위치를 몰라서 막히고, 뒤에 선 사람들의 눈치 때문에 포기하기도 합니다.
- 가족은 전화로 "그거 말고 저거 눌러"를 반복해야 하고, 직접 알려주러 갈 수 없는 경우가 많습니다.
- 기존 도움말은 글자와 용어 중심이라 어르신께 낯섭니다. 어르신이 따르는 건 "아는 사람의 목소리"입니다.

핵심 통찰은 어르신께 필요한 것이 기능 설명이 아니라 **믿는 사람이 옆에 있다는 안심감**이라는 점입니다.

**영상통화와의 차이:** 영상통화로 화면을 보여주며 물어볼 수도 있지만, 어르신은 바쁜 자식과 손주에게 선뜻 연락하지 못합니다. 곁에는 가족이 바쁠 때도 눈치 보지 않고 가족 목소리의 도움을 받게 해서, 연락하기 미안한 마음 때문에 포기하는 순간을 줄입니다.

## 목표와 성공 지표

MVP(핵심 기능 하나만 실제로 동작하게 만든 최소 제품)의 목표는 "어르신이 가족의 목소리 안내만으로 키오스크 주문을 끝낸다"는 가설을 검증하는 것입니다.

| 지표 | 측정 방법 | 목표 |
| --- | --- | --- |
| 주문 완료율 | 테스트 참가자 중 도움 없이 주문을 끝낸 비율 | 정해야 함 |
| 완료까지 걸린 시간 | 시작 버튼부터 주문 완료까지 초 단위 측정 | 정해야 함 |
| 막히는 횟수 | "다시 알려줘" 요청 횟수 | 정해야 함 |
| 안심감 | 사용 후 "혼자 해냈다는 느낌이 들었는지" 5점 척도 질문 | 정해야 함 |

팀플 단계에서는 어르신 3~5분을 대상으로 짧은 사용성 테스트(실제 사용자에게 써보게 하고 관찰하는 테스트)를 하고 위 표의 목표수치를 팀이 정합니다.

## 사용자

사용자는 두 사람입니다. 어르신이 쓰고, 가족이 목소리와 아바타를 준비합니다. (페르소나는 실제 인터뷰 전까지 가정으로 쓴 대표 사용자 상입니다.)

| 구분 | 어르신 (사용자) | 가족 (준비자) |
| --- | --- | --- |
| 대표 인물 | 스마트폰은 쓰지만 키오스크와 앱 예약에는 자신이 없는 할머니 | 멀리 사는 자녀나 손주, 수시로 전화를 받는 사람 |
| 하려는 일 | 카페에서 커피 한 잔 주문하기 | 어르신이 무엇을 누를지 일일이 설명하지 않아도 되게 하기 |
| 불편 | 용어가 낯선 데다 뒤 사람이 신경 쓰임 | 전화로 말로만 설명하기 어렵고 자주 반복됨 |
| 원하는 것 | 혼자 해내고 싶고, 믿는 목소리가 옆에 있기를 바라기 | 어르신이 혼자 중단 없이 쓰고 이를 확인하기 |

이 표는 가정이므로 어르신 인터뷰 후 고쳐야 합니다.

## 핵심 시나리오

할머니가 카페 키오스크에서 커피를 주문하는 흐름입니다. (사용자 흐름은 사용자가 목표를 이루기까지 거치는 단계를 순서대로 적은 것입니다.)

1. 할머니가 곁에 앱을 열고 큰 도우미 버튼을 누릅니다.
2. 가족 아바타가 나타나 "할머니, 뭐 도와드릴까요?"라고 가족 목소리로 물어봅니다.
3. 할머니가 "카페 주문"이라고 말합니다. (음성 인식으로 원하는 일을 파악합니다.)
4. 폰 카메라로 키오스크 화면을 비추고 "알려줘" 버튼을 눌러 한 장을 찍습니다.
5. AI가 사진을 읽고 눌러야 할 버튼과 그 위치를 찾고, 준비된 12개 안내 문장 중 지금 단계에 맞는 것을 고릅니다.
6. 카메라 화면 위에 동그라미가 뜨고, "빨간 동그라미 친 곳을 눌러보세요"라는 안내가 나옵니다.
7. 할머니가 키오스크를 누른 뒤 화면이 바뀔 때마다 4~6단계를 반복합니다. 결제 화면에서는 가족 목소리가 "금액이 맞는지 확인하셨어요?"라고 먼저 묻고, 어르신이 맞다고 답하면 결제 수단 선택과 결제까지 안내합니다.
8. 주문이 끝나면 가족이 미리 녹음한 "정말 잘하셨어요!"라는 칭찬이 나옵니다.

막히는 경우에는 "다시 알려줘" 버튼과 선택 버튼(커피 주문, 병원 접수 등)을 함께 두어 음성 인식 오류에 대비합니다.

**가족 시나리오:** 가족이 곁에를 준비하는 흐름입니다.

1. 가족이 곁에 앱의 가족 설정 화면을 엽니다.
2. 본인 사진을 올립니다. (사진 주인의 동의가 전제입니다.)
3. 생성형 이미지 AI가 사진을 일러스트풍 아바타로 바꿔주고, 마음에 들 때까지 다시 만들 수 있습니다.
4. 아바타의 입 위치를 손가락으로 한 번 맞춥니다.
5. 안내 문장을 하나씩 읽으며 녹음합니다. 녹음하지 않은 문장은 복제 목소리 파일이 대신 재생됩니다.
6. 미리 듣기로 아바타가 말하는 모습과 목소리를 확인합니다.
7. 설정이 끝나면 어르신께 폰을 건네거나 곁에를 설치해 드립니다. (MVP는 설정이 한 폰에만 저장되므로 같은 폰으로 시연합니다.)

## 기능 범위

MVP는 "키오스크 카페 주문 한 가지"만 끝까지 되게 만듭니다. 나머지는 다음 단계로 미룹니다. 서비스의 원래 형태는 앱을 열지 않아도 화면 위에 떠다니는 도우미이고, 이 기능은 일정상 뒤로 미뤘다가 시간이 남으면 시도합니다.

### 어르신이 쓰는 기능

| 기능 | 범위 | 설명 |
| --- | --- | --- |
| 큰 도우미 시작 버튼 | MVP | 어르신이 앱을 열면 가장 크게 보이는 버튼 |
| 음성 요청 인식 | MVP | 브라우저 기본 음성 인식(Web Speech API)으로 "카페 주문"을 알아듣기 |
| 카메라 화면 촬영 | MVP | "알려줘" 버튼으로 한 장씩 찍어 AI에 보내기 (요금을 아끼기 위해 연속 촬영은 하지 않음) |
| AI 화면 인식 | MVP | 사진에서 눌러야 할 버튼과 위치를 찾고, 준비된 12개 문장 중 지금 단계를 고르기 (AI가 새 문장을 짓지 않음) |
| 화면 위 동그라미 표시 | MVP | 카메라 영상 위에 표시를 겹쳐 보여주기. 동그라미를 크게 그리거나 버튼 영역 전체를 칠해서 보여줌 |
| 가족 목소리 인사·칭찬 | MVP | 12개 문장(인사, 안내, 칭찬, 격려)을 가족 목소리 파일로 재생 |
| 단계별 안내 목소리 | MVP | 일레븐랩스로 본인 동의를 받은 팀원 목소리를 복제해 12개 안내 문장을 미리 만들어 두고, 단계에 맞는 파일을 재생 |
| 아바타 표시와 입 움직임 | MVP | 가족 아바타를 화면에 표시하고, 목소리가 재생되는 동안 소리 크기에 맞춰 입 모양이 바뀌어 말하는 것처럼 보이게 함 |
| 결제 금액 확인 질문 | MVP | 결제 화면에서 가족 목소리가 "금액이 맞는지 확인하셨어요?"라고 먼저 묻고, 어르신이 확인한 뒤에만 결제 수단 선택과 결제를 안내 |
| 실패 시 선택 버튼 | MVP | 음성 인식이 틀리거나 막힐 때 눌러서 고를 수 있는 버튼 ("다시 알려줘" 포함) |
| 실시간 복제 목소리 생성(AI가 만든 새 문장까지 가족 목소리로) | 이후 | 실제 서비스의 최종 형태이며 발표에서 반드시 명시함. 시연은 12문장 파일로 대체하고, 보이스피싱 위험을 설계한 뒤 도입 |
| 혼자 해보기 모드 | 이후 | 안내를 따라 하다 보면 어르신이 직접 할 수 있게 하는 모드 |
| 폰 안 앱 위에 띄우는 오버레이 | 이후 | 서비스의 원래 형태(화면 위에 떠다니는 도우미). 안드로이드 네이티브 앱이 필요해 일정상 후순위, 시간이 남으면 시도 |
| 병원 예약·배달앱·송금 안내 | 이후 | 카페 시나리오가 검증된 뒤 확장 |
| 길찾기 안내 | 이후 (확장) | 어르신이 목적지를 말하면 길찾기 과정을 가족 목소리와 아바타가 단계별로 안내. 화면 위에 떠다니는 도우미와 함께 확장 |

### 가족이 쓰는 기능

| 기능 | 범위 | 설명 |
| --- | --- | --- |
| 가족 전용 설정 화면(녹음·아바타 등록) | MVP | 어르신께 드리기 전에 가족이 준비하는 화면 |
| 사진 올리기와 동의 확인 | MVP | 사진 주인의 동의를 먼저 확인한 뒤 사진을 올림. 변환 후 원본 사진은 저장하지 않음 |
| 사진을 아바타로 변환 | MVP | 올린 사진을 생성형 이미지 AI가 일러스트풍 아바타로 바꾸고, 마음에 들 때까지 다시 만들 수 있음 |
| 아바타 디자인 방향 | MVP | 그림체는 일러스트풍(세부 그림체는 팀에서 정함). 닮는 정도는 올린 사진을 기반으로 가족임을 알아볼 수 있을 만큼. 동의 방식은 사진 주인의 동의를 먼저 받고, 변환 후 원본 사진은 저장하지 않음 |
| 입 위치 맞추기 | MVP | 입 움직임이 자연스럽도록 아바타의 입 위치를 처음에 한 번 맞춤 |
| 안내 문장 직접 녹음 | MVP | 가족이 문장을 직접 녹음하면 그 녹음이 복제 목소리보다 먼저 재생됨. 복제 목소리 파일은 기본값 |
| 미리 듣기 | MVP | 설정이 끝나면 아바타가 말하는 모습과 목소리를 확인 |
| 아바타 꾸미기(편집) | 이후 (우선순위 아님) | 사진 기반으로 만든 아바타를 머리 모양, 색, 소품 등으로 직접 고쳐 꾸미는 기능. 사진 기반 아바타가 먼저이며, 이 기능은 우선순위에 넣지 않고 이후로 미룸 |
| 어르신 사용 확인 알림 | 이후 | 어르신이 곁에를 사용했는지 가족이 확인할 수 있게 하는 알림이나 사용 기록 |

**사용자 기능이 아니라 팀이 준비하는 것:** 일레븐랩스로 복제 목소리 12문장 파일 만들기, 문장 목록 확정과 팀원 목소리 동의 받기, AI 키 입력칸(본인 폰에만 저장)을 만듭니다.

## MVP 우선순위

하루 안에 만들어야 하므로 어르신 흐름만으로 시연이 성립하게 하고, 가족 설정은 그다음에 얹습니다. (P0은 꼭 되어야 하는 것, P1은 되면 좋은 것, P2는 시간이 남으면 하는 것, P3은 우선순위에 넣지 않고 이후로 미루는 것입니다.)

| 우선순위 | 기능 | 이유 |
| --- | --- | --- |
| P0 | 큰 도우미 시작 버튼, 음성 요청 인식, 카메라 촬영 | 어르신 흐름의 시작 |
| P0 | AI 화면 인식과 12개 문장 중 단계 고르기 | 서비스의 핵심 |
| P0 | 크게 그린 동그라미 또는 버튼 영역 표시 | AI 위치가 조금 어긋나도 알아볼 수 있게 함 |
| P0 | 복제 목소리 파일 재생, 미리 만든 아바타, 입 움직임 | "가족이 옆에 있다"는 느낌을 시연에서 보여줌 |
| P0 | 결제 금액 확인 질문, 실패 시 선택 버튼 | 잘못된 안내와 인식 오류에 대비 |
| P1 | 가족 녹음 화면 | 가족 쪽 경험을 보여줌 |
| P1 | 사진을 아바타로 변환, 입 위치 맞추기 | 가족이 직접 아바타를 만드는 경험 |
| P2 | 실시간 복제 목소리 생성(AI가 만든 새 문장까지) | 시연 범위 밖. 키 보안, 대기 시간, 요금 문제 때문에 이후 단계로 둠 |
| P3 | 아바타 꾸미기(편집) | 우선순위 아님. 시연 범위와 개발 일정에서 제외하고 이후 단계로 미룸 |

**발표에서 반드시 명시할 것:** 시연에 쓰는 가족 목소리는 미리 만들어 둔 12문장이지만, 실제 서비스는 목소리를 학습해 어떤 대답이든 실시간으로 생성하는 구조로 만든다는 점을 발표자료에 분명히 적습니다. 동시에 시연 화면이 실시간 생성처럼 보이지 않도록, 시연은 미리 만든 문장임을 함께 밝힙니다.

## 필요한 기술과 API

키가 필요한 것은 AI 서비스 하나이고, 나머지는 브라우저 기본 기능이나 미리 만든 파일입니다. 화면 인식과 이미지 변환을 같은 서비스로 하면 키 하나로 해결됩니다. (API는 앱이 다른 서비스의 기능을 빌려 쓰는 통로, 키는 그 통로를 여는 비밀 열쇠입니다.)

| 기능 | 사용 기술 | 키 필요 | 비고 |
| --- | --- | --- | --- |
| 화면 인식과 단계 고르기 | 이미지 인식 AI API (Gemini 또는 OpenAI) | 필요 | 사진을 한 장씩 보내 요금을 아낌 |
| 사진을 아바타로 변환 | 이미지 생성 AI API (화면 인식과 같은 서비스) | 필요 | Claude API는 이미지를 만들지 못해 제외. 가족 동의 필요 |
| 아바타 입 움직임 | Web Audio (브라우저가 소리 크기를 분석하는 기능) | 불필요 | 입 모양을 소리 크기에 맞춤 |
| 음성 요청 인식 | Web Speech API | 불필요 | 안드로이드 크롬에서 가장 안정적 |
| 카메라 | getUserMedia (브라우저가 카메라를 켜는 기능) | 불필요 | https 주소에서만 동작 |
| 가족 문장 녹음 | MediaRecorder (마이크 소리를 파일로 저장하는 기능) | 불필요 | 녹음이 복제 목소리보다 먼저 재생됨 |
| 안내 목소리 12문장 | 일레븐랩스로 미리 만든 음성 파일 | 앱에는 불필요 | 제작할 때만 사용 |
| 키·녹음·아바타 저장 | localStorage, IndexedDB (브라우저 안의 작은 저장 공간) | 불필요 | 본인 폰에만 저장, 폰을 바꾸면 다시 설정 |
| 웹 주소 만들기 | GitHub Pages (GitHub에 올리면 웹 주소로 바꿔주는 무료 기능) | 불필요 | 카메라 사용에 필요한 https 확보 |

## 위험과 대응

가장 큰 위험은 가족 목소리를 악용하는 보이스피싱과, 어르신이 도우미 없이는 아무것도 못 하게 되는 의존입니다.

| 위험 | 내용 | 대응 |
| --- | --- | --- |
| 보이스피싱 오용 | 가족 목소리 복제 기술이 사기에 쓰일 수 있음 | MVP는 본인 동의를 받은 팀원 목소리로 미리 만든 고정 12문장만 사용하고 실시간 생성은 하지 않음. 이후 실시간 복제는 본인 동의와 앱 안에서만 재생하는 구조로 설계 |
| 의존 | 어르신이 혼자 시도하지 않게 될 수 있음 | 안내를 따라 하다 보면 직접 할 수 있게 하는 "혼자 해보기" 모드를 이후 검토 |
| 음성 인식 오류 | 사투리나 발음 때문에 인식이 틀릴 수 있음 | 선택 버튼(커피 주문, 병원 접수 등)을 함께 제공 |
| AI 화면 인식 오류 | 처음 보는 키오스크 화면에서 틀린 버튼을 가리킬 수 있음 | 시연은 미리 테스트한 키오스크로 한정하고 "다시 알려줘" 버튼 제공 |
| API 키 노출 | 키를 코드에 넣어 GitHub에 올리면 남이 쓰고 요금이 청구될 수 있음 | 키를 코드에 넣지 않고 앱의 입력칸에 직접 넣어 본인 폰에만 저장. 이후 서버에서 키를 숨기는 구조로 전환 |
| 사용 중 손이 모자람 | 한 손에 폰, 한 손으로 키오스크를 눌러야 함 | 음성 안내 중심으로 설계하고 폰을 세워 두는 방법을 안내 |
| 가족 사진 개인정보 | 아바타를 만들려고 올린 얼굴 사진이 외부 AI 서비스로 전송됨 | 사진 주인의 동의를 먼저 받고, 변환이 끝나면 원본 사진은 저장하지 않고 아바타 이미지만 폰에 보관 |
| 결제 오안내 | AI가 틀린 버튼을 가리켜 잘못 결제될 수 있음 | 결제 화면에서는 가족 목소리가 "금액이 맞는지 확인하셨어요?"라고 먼저 묻고, 어르신이 확인한 뒤에만 결제 수단 선택과 결제를 안내 |
| 동그라미 위치 어긋남 | AI가 찍은 위치가 조금씩 어긋날 수 있음 | 동그라미를 크게 그리거나 버튼 영역 전체를 칠해서 보여주기 |
